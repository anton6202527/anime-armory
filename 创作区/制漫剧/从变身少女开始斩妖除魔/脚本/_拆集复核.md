## 为什么不直接采用机器首10集

1. 原文件每个章节标题连续重复两次。旧分析曾把819个唯一章节误报为1638章；现已修复，但初始化时的 raw 仍是一章一集脚手架。
2. 机器首10集只覆盖原著第1–10章，部分断点停在事件中间，例如第1集停在裴长青再次醒转前，尚未兑现“杀人取道行→斩虎→录谱”的开篇承诺。
3. 初始化前未写题材，split_plan.genre_basis 仍是“未设题材→古装动作(默认)”，没有让系统流、志怪悬疑与身份钩参与边界判断。
4. 原著第18章约4300正文字符，不能再与第17章或第19–20章捆成一集；本方案将它单列为身份审判/入司集。
5. 签收时前10个 raw 均为 raw-only、尚未写词；现已由 `apply_split_mapping.py` 事务式重建并同步计划、机器索引与进度，未覆盖任何人工稿或媒体产物。

## 正式重建 raw 的条件与步骤

以下条件已由用户/导演明确签收并完成实施：

1. 在新临时根按已写题材“系统流+修仙+志怪悬疑”生成对照计划。
2. 对照本表确认每集 source unit 范围、开场问题、兑现和集尾钩。
3. 已备份当前机器 raw 的 SHA 映射；只重建仍为 raw-only 的第1–10集，未覆盖任何已有人工稿。
4. 已同步更新 split_plan、机器索引、raw 与 _进度.md；旧第19集起的未落地机器后缀从新第11集连续承接。
5. 逐集 table read；超210秒优先回剪重复说明和非因果段，不加速念白，不跨越本表的保护功能。

## 边界签收标准

- 每集开场0–3秒有危险、异常或明确问题。
- 每集至少兑现一项上一承诺，并打开一个可复述的下一问题。
- 不把角色关键选择、力量升级前置、战斗结果或身份反转切到两集之间。
- 原文章节/source unit映射完整；任何合并、删节、前置都有 adaptation_delta。
- 第18章单列；第19–20章不再硬塞进首10集。
- table read时长、对白负荷、角色数、场景数和高风险VFX在预算范围内。
