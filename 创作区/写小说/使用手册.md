# 写小说使用手册

入口 skill：`novel`。产物放在 `创作区/写小说/<项目名>/`。适合原创小说、导入源书、续写/扩写/改写、审稿、评分、资料包、真实读者反馈、导出。

## 你可以这样说

| 场景 | 直接说 |
|---|---|
| 从零起书 | “写一本架空悬疑仙侠，先帮我立项访谈。” |
| 导入源书 | “把这个 txt 导入小说工坊，先建档。” |
| 继续项目 | “继续 `创作区/写小说/<项目名>`，看下一步。” |
| 审稿查硬伤 | “审第 1-5 章，重点查人设、伏笔和逻辑。” |
| 市场评分 | “给这本书打分，判断要小改、大改还是弃稿重立。” |
| 专业资料 | “这段涉及刑侦流程，先补专业资料包，别写外行。” |
| 发布前 | “导出前跑 gate，检查权利、AI 披露、审稿评分是否齐。” |

## 推荐流程

1. 立项：确定 `小说用途`、目标平台、篇幅和权利来源。
2. 蓝图：题材、主角、读者承诺、世界观、章纲。
3. Demo：先写 1-3 章，过 demo gate 再放量。
4. 正文：逐章写作，写后合并 `state_delta`，避免状态和伏笔丢账。
5. 质检：`novel-review` 查硬伤，`novel-score` 判断市场价值。
6. 修订：`novel-edit` 合并审稿、评分、读者反馈，分层改。
7. 导出：补 AI 使用披露、合规资料和 release manifest。

```text
把 创作区/写小说/仙界闭关小能手 立项成外传项目，先做立项访谈。
```

## 避坑

- “写小说”不默认等于“漫剧源书”；新项目先选用途。
- 不要只跑 score 就开改，先用 review/wiki/balance 找清问题来源。
- 专业题材先建 `novel-research` 资料包，再写正文。
- 写后必须做状态账本；长篇靠记忆会丢伏笔、关系和战力。
