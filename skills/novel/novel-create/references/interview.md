# 立项访谈 — 把"几个字"补全成创作蓝图

> novel-create 第 0 步的引导手册。目标：从用户的**只言片语 + 碎片**，问出一份能动笔的 `创作蓝图.md`。
> 灵魂在三条：**① AI/市场建议前先逐字冻结作者原始种子；② 普通工艺缺项采用推荐值，只有核心作者事实无法推断时才一次问一组；③ 用户给过的别再问，先吃再补缺。**

---

## 一、先冻结原文，再吃碎片、问缺口

用户往往不是白纸，他给了"几个字 / 部分风格 / 部分文件"。在复述、改写 logline、展示案例或给故事候选之前，先保存用户未经润色的原文：已有作品根就立刻用 `novel-craft/scripts/exploration.py seed`；尚未建根则先只补建目录所需且无法推断的中性元数据，在 `init_project.py` 同一命令用 `--human-seed-file`、`--human-seed-author`、`--human-first-confirmed` 冻结。然后再**记录理解、只补核心缺口**——别让用户重答已给过的。完整协议见 `novel-craft/references/exploration-workflow.md`。

| 用户给的 | 你先做 | 收进哪 |
|---|---|---|
| 几个字 / 一句话点子 | 先逐字冻结 human-first seed，再形成**初稿 logline**；只有可能误解核心意图时才请作者修正 | `探索/种子/` + 蓝图 logline |
| 部分风格（"像XX那种""冷峻一点""多对话"） | 提炼成**风格卡草稿**（关键词/句子节奏/对白比/禁忌） | 蓝图 风格卡 |
| 风格样本文件 / 喜欢的段落 | `--ingest` 收进 `素材/`，**读它**抽文风特征 → 风格卡 | 素材/ + 风格卡 |
| 零散设定笔记 / 世界观片段 | `--ingest` 收进 `素材/`，整理进设定圣经草稿，标出**还缺什么** | 素材/ + 设定圣经 |
| 半成品章节 / 开头 | `--ingest` 收进 `素材/`，**读它**反推已隐含的 logline/主角/文风，当文风锚 | 素材/ + 蓝图 + Demo 锚 |

> 复述模板："我理解你想写的是【…一句话…】，风格偏【…】，已经有【…碎片…】。对吗？下面只问还没定的几处。"

## 二、六组提取字段（核心事实缺失时才问）

human-first seed 已冻结后，先从输入/素材提取；普通缺项采用推荐值。只有主角、核心阅读承诺、主线冲突等核心作者事实无法推断时，才一次问一组并给 2-3 个候选。

1. **题材 + 小说用途 + 目标平台 + 创作工艺档**（最先定；工艺档独立于平台）
   - 题材：都市异能 / 玄幻修真 / 古言宅斗 / 科幻 / 悬疑 / 历史…
   - 小说用途：传统小说 / 漫剧源书 / 微短剧源书 / 短读短篇 / 自定义
   - 平台：起点(男频长线) / 番茄(爽快下沉) / 晋江(女频细腻) / **抖音漫剧·红果(短章高频强钩)** / 历史向 / 跨平台
   - 创作工艺档：commercial_serial / genre_novel / literary / experimental；按作者想采用的叙事合同明确选，不把番茄/晋江等平台名硬映射成档位。
   - → 用途决定交付形态（传统连载 vs 漫剧源书 vs 短篇试写），平台提供需实时核验的市场/交付假设，工艺档决定场景结构合同。漫剧源书后续改成视频脚本时还要二次压缩；不要把小说章当成成片逐字台词。

2. **主角 + 故事引擎**
   - 主角是谁、出身、性格底色（一句）
   - 哪种**能力、资源、关系、职责或困境**持续迫使他选择？若是超常能力/高杠杆机制，再写清代价、边界与后果。
   - 候选必须随题材变化：现实/文学小说可从关系与困境出发；系统流/异能文才给能力机制候选。

3. **核心阅读承诺**（读者为何继续）
   - 悬念、情感关系、人物变化、主题探索、幽默、恐惧、智斗、成长或爽感等。
   - 问“读者翻开这本书，最持续期待看到什么”，定 1-2 个主承诺；商业爽文再细化爽点类型与兑现节奏。

4. **主线冲突 / 反派**（对抗什么）
   - 主角要对抗的最大阻力：人 / 势力 / 困局 / 命运
   - 一句话主线张力（"他要……，但……拦着”）。

5. **规模 + 视角**
   - 规模档：short(3章试水) / medium(20) / long(40) / 微短剧(50) / 漫剧(90短章)——平台已暗示，确认即可
   - 人称：第一 / 第三限制（默认第三限制）
   - 目标读者（一句）。

6. **风格 + 输出**
   - 风格卡（若一/未提炼）：文风关键词、句子节奏、对白vs内心戏比、禁忌词/套路
   - 没有明确风格 → 记"**Demo 后回填**"，用前 1-3 章定调
   - 输出：txt / docx / outline（默认全要）。

## 三、节奏与边界

- **只问核心缺口**：需要询问时一次一组，回填蓝图后继续；普通可逆项不形成交互 gate。
- **推荐值可覆盖**：采用推荐值后写回并在摘要说明，用户随时可改。
- **缺口可延后**：风格、目标读者这类可"Demo 后回填"，不卡立项。但 **logline / 主角与故事引擎 / 用途或平台 / 规模**这四样必须当场定——它们决定骨架。
- **够了就开工**：四样硬项 + 一个核心阅读承诺 + 一句主线冲突 = 可以跑 `init_project.py` 建骨架了，剩下的边写边补。别把访谈拖成无止境问卷。

## 四、产出对照（访谈 → 蓝图字段）

| 访谈得到 | 写进 创作蓝图.md |
|---|---|
| 初稿 logline | ## 一句话故事 |
| 题材 + 用途 + 平台 + 基调 | ## 题材 / 用途 / 平台 / 基调 |
| 主角 + 故事引擎（能力/关系/困境；必要时含边界）+ 动机 | ## 主角 |
| 核心阅读承诺 | ## 核心阅读承诺 |
| 主线冲突 / 反派 | ## 主线冲突 |
| 目标读者 | ## 目标读者 |
| 规模档 + 人称 | ## 规模 / 视角 |
| 风格卡 / 样本 | ## 风格卡（+ 素材/） |

提取/必要访谈结束 → 跑 `init_project.py`（第 1 步）→ 把上表填进 `创作蓝图.md`（第 2 步）→ 按当前审阅策略过 gate（默认 independent specialist）。
