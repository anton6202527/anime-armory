# 真相揭示 / 身份曝光 / 掉马场景专项

用于章纲命中身份曝光、掉马、真相揭示、旧案回收、内鬼暴露、身世认亲等场景。揭示场不是说明书，而是一次权力重排：某个秘密从少数人知道变成更多人知道，角色的选择空间立刻变化。

## 总原则

0. **先选信息策略（希区柯克炸弹论）**：同一个秘密有三种放法——**surprise**（读者与角色同时知道：15 秒惊讶）、**suspense**（读者先知道：桌下的炸弹，读者替角色捏汗，值 15 分钟悬念）、**mystery**（读者后知道：解谜快感）。默认别全用 surprise；最贵的秘密优先考虑让读者先知（`reader_knows_since` 提前），然后**在反讽窗口里让不知情者围着炸弹说话**——窗口开了却零触碰=悬念资产闲置。知情账机检：`irony_window_untouched`（窗口空转）/`reveal_burst`（同章倾泻 ≥3 条=互相踩踏）/`surprise_heavy`（全书 ≥80% surprise 型）。
1. 先写信息差：谁早就知道、谁误判、谁第一次知道、谁假装不知道。
2. 证据必须可感知：信物、血书、密信、伤痕、旧称谓、法器反应、证人口供、系统提示或行为破绽。
3. 揭示按阶梯递进：线索 -> 指向 -> 反驳 -> 反证 -> 不可逆反应。
4. 反应比解释重要：否认、失语、改口、站队、逃跑、反咬、保护、崩溃都比旁白更有戏。
5. 揭示后要立刻改变局势：关系、身份、敌我、资源、目标或危险至少变一项。

## 身份曝光 / 掉马

- 掉马前给一次“还能蒙混过去”的缝隙，再用证据关死。
- 被揭穿者不要只震惊，要有即时策略：装傻、反咬、承认一半、转移焦点或抢夺证物。
- 围观者/关键关系人必须有反应次序，尤其是最不该知道的人。
- 身份曝光后写清新称谓、新权力、新危险，不能下章又当没发生。

## 真相揭示 / 证据揭穿

- 证据链分批抛，不一次性倒完设定。
- 每抛一个证据，都让对方给一个反驳或动作，形成攻防。
- 真相最好同时回答一个旧问题，并抛出一个新问题。
- 如果是章末钩，只揭一半真相，关键名词/选择/代价留到下一章开场。

## 旧案 / 秘密回收

- 标出它回收的是哪个伏笔或前文疑点，避免像临时补丁。
- 旧案不要只改变过去，也要改变现在：继承权、仇恨、婚约、师承、债务、阵营。
- 允许保留“真相中的真相”，但要让本章至少兑现一个明确答案。

## 写完自检

- [ ] 本场揭示前后，主角的目标或危险是否变化？
- [ ] 证据是否具体，而不是旁白宣布？
- [ ] 至少三个关键角色的反应是否不同？
- [ ] 是否回答了一个旧问题，同时留下一个新动作或新钩子？
- [ ] 新身份、知情人范围、旧案状态和未解问题是否写入 `state_delta`？
- [ ] 知情面变化是否已记入知情账？（谁新得知/开始怀疑/当众公开 → `python3 skills/novel/novel-wiki/scripts/knowledge_sentry.py learn/suspect/reveal`；写前该场在场各方"谁知道什么"以 `设定/knowledge_ledger.json` 为准，别靠现场重推）
