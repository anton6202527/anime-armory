# 结局 / 完本工艺：终局弧 · 清账 · 落点

`opening.md` 管前 3 章抓人，`hooks.md`/`arc-pacing.md` 管中途不断，本篇管**最后 10% 怎么收**——
网文口碑的最终定格在结局：追了几百章的读者对"烂尾"的记恨远超中段平淡，而完本口碑直接决定
老读者会不会追作者下一本。机检侧已有三道闸（`arc_gate.py` 终局必答/反向刹车、`foreshadow_ledger.py`
终章未击发反查、`novel-balance` 烂尾预警），本篇是**写作侧**：终局弧从哪启动、按什么顺序收、落在哪。

> 一句话法则：**结局是兑现，不是收摊**。读者契约里每一条承诺在终局都要有下落——兑现、翻转着兑现、
> 或显式告知不兑现的理由；"作者写累了"的仓促感是完本第一死因。

## 一、终局弧从哪启动（别到最后一章才想收）

- **启动点 ≈ 全书 85-90% 处**（长篇约倒数 8-15 章，短篇倒数 2-3 章）：从这里起**不再开新线、不再
  引入新主要角色/新设定**；已有线开始逐条并拢。判据：本章若还在埋只有终局后才能收的新伏笔 → 太晚了，删或移前。
- **写终局前先跑清账三件套**：
  1. `python3 skills/novel/novel-wiki/scripts/foreshadow_ledger.py <作品根> scan --through <当前章>`——pending 伏笔逐条决定：终局收 / 提前收 / 显式 drop（drop 要清干净前文线索）。
  2. `python3 skills/novel/novel-review/scripts/thread_resolution.py <作品根>`——未收支线清单。
  3. 对照 `设定/读者契约.md` 的「终局必须回答」（`must_answer`）逐条打勾——这是 `arc_gate.py` 的硬闸输入，也是读者的验收单。
- **倒推法**：终局大纲先写"最后一幕定格在哪个画面/哪句话"，再倒推需要哪些前置就位（七点结构的
  从结局倒推，见 `story-structures.md`）。

## 二、收线顺序：先外围、后核心、题旨最后回声

高潮不是把所有线挤进同一章，而是**分层清账**，一层比一层贴近核心：

1. **外围支线先收**（终局弧前半）：配角归宿、次要恩怨、势力格局——为主线高潮清场，让最终对决时
   读者的注意力无处旁骛。配角结局要与其弧光呼应（`群像与角色弧光.md`），不要一句旁白打包发盒饭。
2. **主线外部冲突**（高潮章）：boss 战 / 终极对决 / 最后翻盘。胜负必须由**前文建立的机制、代价与
   人物选择**挣来（`reader-contract.md` 的"挣来的结局"）——终局才掏出的新能力 = deus ex machina，
  读者积攒几百章的期待直接泄气。力量体系上限对齐 `力量体系设计.md`，不越 registry 崩战力。
3. **主线内部弧光**（高潮章内或紧随）：外部冲突的解法应**同时是**主角内心问题的答案——他赢是因为
   他终于变成了那个能赢的人。外部赢了、内心弧没交代 = 空胜利。
4. **题旨回声**（最后）：核心题旨不由旁白点破（`prose_craft_audit` 的 moralizing_ending 正是抓这个），
   而由一个**镜像场景**承载——终局复现开篇场景/意象/对白，但人物的选择变了，变化本身就是题旨。

## 三、最终揭示与反转

- 终局大反转仍守"意料之外、情理之中"：回看时伏笔链成立（`premise-divergence.md` 的意外×合理）。
  反转候选同样先发散 2-3 个再挑（VS 采样口径见 `premise-divergence.md` §7），不要顺撇写第一直觉。
- 揭示节奏照 `reveal-scenes.md`：证据分批抛，别在终局一次性倒设定；**最后一层真相留给主角亲手掀开**，
  不借反派之口独白交代。
- 知情账清零：终局后所有 critical 秘密要么公开、要么显式写明"带进坟墓"——
  `knowledge_sentry.py scan` 不应再有 reveal_overdue。

## 四、尾声（denouement）：短、落地、留余温

- **长度**：高潮后 1-2 章内收束（长篇可加番外，正文别拖）。高潮是波峰，尾声是缓坡——超过 3 章的
  日常流水会把完本情绪耗光；反过来高潮章直接"全书完"也太陡，读者需要一小段告别时间。
- **内容**：新常态一瞥（世界/关系变成了什么样）+ 核心角色各归其位 + 题旨余味。不塞新冲突；
  若要留续作钩子，放在**番外或最后一段**，且不得动摇本书已兑现的承诺（留钩 ≠ 烂尾开放）。
- **结局走向是契约**：HE/BE/开放在 `读者契约.md` 写死（女频对 BE 尤其敏感，见 `女频情感.md`）；
  中途想改走向 = 改契约，须显式修订并预警，不是终局突袭。

## 五、烂尾三形态（自查）

| 形态 | 症状 | 修法 |
|---|---|---|
| **仓促收**（最常见） | 终局节奏骤然加速、矛盾一章内全解、配角集体消失 | 终局弧提前启动（§一）；把清账摊进倒数 8-15 章 |
| **无限拖** | 高潮后又开新图/新敌人，完本遥遥无期、追读崩 | 反向刹车已挡"提前解主线"；主线已解就收，新图留给续作 |
| **主题跑偏** | 结局与开篇承诺的题旨/走向相悖（爽文结尾突然虐、复仇文结尾强行和解） | 对照 `must_answer` 与禁偏清单；偏离是毁约不是深刻 |
