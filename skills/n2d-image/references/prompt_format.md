# 出图 prompt 两层架构 — 标准格式

把要出的图展开成**开箱即用**的 prompt 块——出图阶段可喂给 `生图AI` 所选官方/已登录图后端（默认 Codex，可选 Dreamina/即梦官方 CLI / Seedream / 可灵主体库 / Nano Banana / Sora Cameo 等）。**分两层**：复用资产（定妆 = 角色/场景/反复入镜道具）放共享，单次资产（分镜）放本集。

---

## 1. 共享层 — `出图/共享/图片/`（全篇一份：prompt/ 文件夹 + 图片/ 文件夹）

角色人读总入口固定在作品根 `设定库/角色圣经.md`；所有入镜人物的可迁移资产包放在 `设定库/character_assets/`，共享层索引必须链接它。`identity_registry.json` 是机器执行真值，角色圣经是 prompt/QC/返工说明的人读真值；`character_assets` 只归拢 reference / prompts / lora / voice / adapters / qc，不替代 registry。

```
出图/共享/
├── identity_registry.json   机器真值：角色/形态的角色 DNA 五层 + 参考组 + reference_atlas 参考图数据库 + 后端身份适配 + 固定 seed pool + 角度策略 + 禁漂项
├── asset_registry.json      机器真值：场景/道具/独立服装/VFX 的参考组 + 场景 DNA + 结构/光位约束 + 禁漂项
├── prompt/                  共享 prompt 文件
│   ├── 00_索引.md           全篇定妆清单 + 状态 + 首现/复用范围 + PNG 路径
│   ├── 角色定妆.md          所有角色（含形态变体）实战 prompt
│   ├── 场景定妆.md          所有场景实战 prompt
│   ├── 道具定妆.md          关键道具实战 prompt
│   ├── 法宝定妆.md          ⚙️仙侠玄幻可选：法宝/法器（含形态/成长阶段多态）
│   └── 特效定妆.md          ⚙️仙侠玄幻可选：剑气/灵力光效/法术/护体光/阵法（锁颜色/形状/拖尾/强度）
└── 图片/                    共享 PNG 产物（与 prompt/ 平级）
    ├── 定妆_<角色>.png          标准三视图·正面主参考
    ├── 定妆_<角色>_侧.png        标准三视图·侧面参考
    ├── 定妆_<角色>_背.png        标准三视图·背面参考
    ├── 定妆_<角色>_半身.png      服装/体态参考（二选一）
    ├── 定妆_<角色>_全身.png      服装/体态参考（二选一）
    ├── 定妆_<角色>_脸部特写.png  基础脸锚；可用同源表情参考替代
    ├── 定妆_<角色>_三视图.png    人审归档·由正/侧/背生产拆图拼成的标准三视图
    ├── 定妆_<角色>_设定表.png    人审归档·含服装/表情增强项时可用这个更宽泛命名
    ├── 定妆_<角色>_表情.png      增强项·表情条（喜/怒/哀/惊）
    ├── 定妆_<角色>_<形态>.png    形态变体
    ├── 定妆_<场景>.png           场景定妆主图
    ├── 定妆_<场景>_<向>.png      场景多视图
    ├── 定妆_<道具>.png
    ├── 定妆_<法宝>.png / 定妆_<法宝>_<阶段>.png
    └── 定妆_<特效>.png
```

所有人物角色另有项目内资产包（含短线/功能角色；体量只影响 LoRA/主体库升档，不影响基础定妆包）：

```
设定库/character_assets/
├── _index.json              项目内角色资产包索引
└── CHAR_01__slug/
    ├── manifest.json        可迁移资产包：reference / prompts / lora / voice / adapters / qc
    ├── reference/
    ├── prompts/
    ├── lora/
    ├── voice/
    ├── adapters/
    └── qc/
```

> **prompt / 产物分离铁律**：本 skill 任一目录（`共享/` 或 `第N集/`；旧项目 `common/` 仅读取兼容）下，所有 prompt md 进 `prompt/` 子目录；生成产物 PNG 进 `图片/` 子目录。详见 `n2d/references/architecture.md` 二节。

### 1.1 `00_索引.md` 必含字段

- 表（角色 / 场景 / 道具；**⚙️仙侠玄幻题材再加 法宝 / 特效 两张表**），每条含 **ID**、名称、形态、首现集、复用范围、状态（✅/⏳/⬜）、PNG 路径
- `设定库/角色圣经.md` 链接：声明角色圣经是人读总入口；后续定妆、分镜、video prompt、QC 和返工说明先引用角色圣经，再绑定 `CHAR_xx/形态`
- `identity_registry.json` 同步登记提示：角色/形态行必须能对应到 `characters[].id` + `forms[].form`；每个 form 必须有 `character_dna.face / hair / outfit / accessories` 五层摘要；后端角色 ID / Face Lock / LoRA 状态以 registry 为机器真值，`00_索引.md` 只做人读摘要
- 跨集成长升级提示：长线角色若有 `evolution_profile`，`00_索引.md` 必须摘要当前成长阶段、身份不变量、允许升级项和下一阶段触发条件。升级不是换脸：新 form 必须从上一阶段身份锚派生，只允许服装/法宝/气场/VFX/姿态气质升级。
- **角色资产包（Character Assets）摘要**：所有人物角色/形态只要会入镜，`00_索引.md` 必须列 `characters[].asset_bundle.manifest` 路径、可继承资产（reference/prompts/lora/voice/adapters/qc）和缺口。资产包用于迁移和继承，不重新定义角色 DNA；不得因“短线/功能角色”省略资产包。
- 固定 seed pool 提示：若 form 有 `generation_control.seed_strategy=fixed_pool`，`00_索引.md` 只摘要池和后端支持状态；执行以 registry 为真值。支持 seed 的后端传入 `usage` 对应 seed；不支持/未暴露 seed 的后端记录 `seed_effective=false` no-op 降级，不得宣称可复现。
- **角色参考图数据库（Reference Atlas）摘要**：逐角色/形态摘要 `reference_atlas.build_tier`、基础视角 ready/planned 数、表情参考 ready/planned 数、动作参考 ready/planned 数、缺口处理。`reference_atlas` 是 `reference_group` 的增强索引，不是第二套真值；只有 `status=ready` 的路径能作为本集参考图传入后端，`planned` 只做待补计划。
- `asset_registry.json` 同步登记提示：场景/道具/独立服装/VFX 行必须能对应到 `assets[].id`；场景用 `LOC_xx`，道具用 `PROP_xx`，独立服装/套装用 `OUTFIT_xx`，法宝/光效/VFX 用 `VFX_xx`；参考组、场景 DNA、结构/光位约束、禁漂项以 registry 为机器真值，`00_索引.md` 只做人读摘要
- **场景 DNA 摘要**：反复出现的 `LOC_xx` 必须摘要 `scene_dna` 七项：归属锚、地标/识别物、空间布局/轴线、建筑材质/主色、光色/天气/气候、常驻物件/植被/水体、禁漂项。角色有归属感靠固定环境锚，不能只写一个地点名。
- **角色 DNA 一致性定档表（P0 · 出图前必产，付费出图前输出给用户并落此表）**：逐角色/形态一行——`角色/形态 ｜ 体量 ｜ 当前档 ｜ 目标档 ｜ 表情库 ｜ LoRA ｜ 升档触发条件`。档①=参考图派生+锚点句（默认全员）/ 档②=后端原生主体 ID·主体库（参考图压不住·无 GPU）/ 档③=LoRA（几十集核心角+前两档压不住）；附加=完整情绪库 / 动作参考（情绪戏、动作戏多的角色 opt-in）。**ROI 驱动、默认最小化只用于主体库、LoRA、完整情绪库、动作参考，不用于基础包**：所有人物都必须先有标准正/45°/侧/背、半身或全身服装参考、脸部特写或至少一个同源表情参考、asset_bundle 和 reference_atlas；升档只在触发条件命中时发生。逐角色分档方法见 `lora_consistency.md「出图前角色 DNA 定档框架」`
- **跨 AI 锚定句速查**（常用生视频模型的中英锚定句）
- **全集统一负面词**
- **图 AI 统一参数**（Codex/官方 OpenAI/Dreamina/Seedream 等模型 / 比例 / 精细度 / 数量 / 参考强度档位）
- **工作流约定**（新角色/场景/道具/法宝/特效如何加入共享库）

### 1.2 `角色|场景|道具定妆.md` — 定妆 prompt 块标准格式

```markdown
## ① <ID> <名称>·<形态>（✅/⏳/⬜）

**首现**：第N集 / **复用**：第N-M集
**目标存档**：`出图/共享/图片/定妆_xxx.png`
**角色圣经引用**：`设定库/角色圣经.md` → `CHAR_xx/形态`（角色必填；场景/道具/法宝/特效写“无”）
**角色资产包**（所有人物角色必填；短线/功能角色也不得写“无”）：`设定库/character_assets/<CHAR_ID>__<slug>/manifest.json`；只作为 reference / prompts / lora / voice / adapters / qc 的迁移索引，角色 DNA 仍读 `identity_registry.json`
**身份注册**：`出图/共享/identity_registry.json` → `characters[].forms[]`（角色/形态必填；场景/道具/法宝/特效写“无”）
**资产引用注册**：`出图/共享/asset_registry.json` → `assets[]`（场景/道具/独立服装/VFX 必填；角色写“无”）
**参考图来源**：（已完成共享图 / 无需参考图）
**场景 DNA**（场景必填；角色/道具/法宝/特效写“无”）：从 `asset_registry.json.scene_dna` 读取；地标/识别物、空间布局/轴线、建筑材质/主色、光色/天气/气候、常驻物件/植被/水体。示例：青云宗=悬空仙山+云海+白玉台阶+金色飞檐洞府+固定青石+灵泉+竹林。
**角色 DNA**（角色必填）：脸 / 发型 / 服装 / 配饰 / 质感 五层；无配饰写“无”，与 `设定库/角色圣经.md` 和 `identity_registry.json.character_dna` 一致
**表演层**（角色必填）：气质 / 性格 / 动作习惯；来自 `设定库/角色圣经.md`，不写进 `identity_registry.character_dna` 四键
**人物审美基线**（角色必填；场景/道具/法宝/特效写“无”）：除非角色圣经或用户特别说明“丑、怪、老、病、恐怖、喜剧丑角、粗粝写实、非主流”等，本角色默认按当下主流可播审美和镜头友好来写：脸部比例协调、五官清晰有辨识度、发型妆造干净精致、服装剪裁/材质有质感、光影让五官立体好看；同时保留年龄、身份阶层、伤病/战损、反派气质和角色 DNA，不写成同质化网红脸或过度磨皮塑料脸。
**跨集成长阶段**（长线角色必填；非长线写“无”）：从 `identity_registry.json.evolution_profile` 读取；本形态属于哪个 stage、从哪个上一阶段派生、身份不变量锁什么、允许升级项是什么。新阶段定妆必须用上一阶段正脸/脸部特写 image2image 派生，不得纯文重抽新脸。
**固定 seed 策略**（角色必填；场景/道具/法宝/特效写“无”）：从 `identity_registry.json.generation_control` 读取；本块用途=turnaround/expression/closeup/shot；若后端支持 seed 传 `requested_seed`，否则记录 `seed_effective=false` no-op 降级，不把 Codex/未暴露 seed 的后端称为可复现
**角色参考图数据库**（角色必填；场景/道具/法宝/特效写“无”）：从 `identity_registry.json.reference_atlas` 读取；基础视角（正脸/45°/侧脸/半身或全身/背影）+ 基础脸锚（face_anchor_refs）+ 表情参考 + 动作参考；本块生成后把 ready/planned 状态同步回 atlas。所有人物都必须登记标准基础视角（front / three_quarter / side / back / half_body 或 full_body）和至少一个同源脸部特写/表情参考，且基础项必须是 ready；完整喜怒哀惊库、动作参考、LoRA 或高档主体库再按剧情需要升档。
**角色定妆组**（所有人物必出基础包 + 人审拼版；不按主配角或题材省背面）：
- **标准三视图生产拆图**：
  - 正面主参考：`出图/共享/图片/定妆_<角色>.png`（正脸中性光，下游分镜的主参考图）
  - 45°参考：`图片/定妆_<角色>_45度.png`（基础硬要求；所有人物/形态必出 ready，锁转头、过肩、三分之二侧脸高频角）
  - 侧面参考：`图片/定妆_<角色>_侧.png`（侧面，锁鼻梁 / 下颌 / 发型侧轮廓）
  - 背面参考：`图片/定妆_<角色>_背.png`（背面，锁后脑勺发型 / 背部服饰 / 披风 / 腰带绑法）
  - 服装参考：`图片/定妆_<角色>_半身.png` 或 `图片/定妆_<角色>_全身.png`（二选一；锁衣领 / 袖型 / 腰带 / 配色 / 体态）。若使用 `_半身.png`，必须从已通过自检的正面主参考裁切并放大/重采样回 9:16，且人物主体居中、头身中线接近画面中线、左右留白基本均衡；不得新抽半身导致脸漂，不得用白底/浅灰底/空白补满下半截，不得人物明显偏边。
- **人审拼版**：`图片/定妆_<角色>_三视图.png`（由已通过自检的正面 / 侧面 / 背面生产拆图拼成，用于快速审脸、审服装、归档，不作为分镜主参考图）
- **基础脸部参考**：`图片/定妆_<角色>_脸部特写.png` 或至少一张 `图片/表情_<角色>_<情绪>.png`（同源裁切/派生，不重新抽新脸）。登记到 `identity_registry.reference_group.face_anchor_refs[]` 与 `reference_atlas.face_anchor_refs[]`；旧项目的 `expressions[]` 可兼容当脸锚。这是所有人物必备，不是长线角色专属增强项。
- **增强项**：`图片/定妆_<角色>_设定表.png`（可纳入半身/全身/色卡/配饰细节）与完整 `图片/定妆_<角色>_表情.png`（喜 / 怒 / 哀 / 惊，可单张多格或分张）。完整表情库登记到 `reference_group.expressions[]` / `reference_atlas.expression_refs[]`，按镜头风险升档，不是全员基础硬前置；45° 不在增强项里，属于基础包。
- **动作参考项**：`图片/定妆_<角色>_动作_<动作>.png`（持剑 / 御剑 / 施法 / 奔跑等；只给核心/动作重角色按需补）。动作参考仍必须继承角色 DNA 五层，不得为一个动作新抽成新脸、新发型或新衣服。
- **近景脸部锚点**：`图片/定妆_<角色>_脸部特写.png`（从已通过的正面主参考或半身服装参考裁切放大而来，用于 CU/ECU、正反打、过肩反应、表情特写；不得重新抽新脸）。脸部特写登记到 `identity_registry.reference_group.face_anchor_refs[]`；完整情绪表情图再登记到 `identity_registry.reference_group.expressions[]`。
- 形态变体（觉醒态 / 银牌态…）各自至少出标准三视图 + 拼版，均以常态主参考做参考图（强度 0.75-0.85）
- **命名约定**：多张可喂给图 AI 的拆分 PNG 叫「定妆组」；单张合成总览才叫「三视图」或「设定表」。不要把多张散图标成“三视图已完成”。

> **标准三视图生产铁律（定妆＝对齐档案，不是三张好看图）**：定妆“不标准”几乎都不是出得少，而是**没对齐 + 不中性**。闭源平台（即梦/可灵）文生图天生给「三张分别好看的角度图」——身高/比例/视平线/光各漂——拼起来当然不像设定稿。判定「标准」靠两组硬条件，自检必过：
> - **中性档案三铁律**：① **同源**——定妆组全用同一模型、同一基底 prompt，只替换「正面 / 侧面 / 背面 / 半身 / 全身」那一截，背景·妆造·光照全锁死；② **中性**——纯浅灰底 + 柔和均匀光 + 无表情无戏无戏剧光（带戏会污染下游参考图）、双手可见、9:16、≥1024px；③ **对齐**——正 / 侧 / 背**同身高、同比例、水平视平线对齐、同景别距离**。第③条是「标准三视图」与「三张好看图」的分界线。
> - **三条生产路线（按锁对齐能力从优到次，优先用前面的）**：
>   - **路线 A（推荐·一次锁对齐）整张 turnaround 总图同框出 → 拆图**：一个 prompt 出一张含正/侧/背**同框、同身高、视平线对齐、统一灰底匀光**的角色设定总图，再拆成 `定妆_<角色>.png`(正) / `_侧` / `_背`。三视一次成型、天然对齐，**多参考后端（Seedream Universal Reference / Nano Banana / 可灵主体库）尤其适合**。
>   - **路线 B（分别出·靠参考锁）**：先出正面主参考 → 以它为参考图（强度 0.75-0.85）派生侧/背，prompt 显式写「与参考同一身高 / 同景别 / 水平视平线 / 纯灰底匀光」。比独立文生图齐，但仍须按对齐自检逐张核。
>   - **路线 C（工业级正交·闭源给不了）**：要真正正交转身（同高 T-pose 三机位），闭源平台做不到——走 ComfyUI **turnaround pose 模板（openpose/canny 固定三机位同高）+ IP-Adapter FaceID 锁脸**。这与 LoRA 数据集是**同源产物**：详见 `lora_consistency.md` Stage 1/Stage 3，要训 LoRA 的核心角色顺手就把标准三视图出了。
> - 形态变体、`gate` 与落档：对齐不达标的定妆**不得标 ✅**（与脸漂同级硬伤），回路线 A/C 重出；`gate.py --stage image` 不强卡对齐（视平线机检不可靠），由**定妆自检对齐项**作落档闸门。
> - **45°实际角度复核**：`定妆_<角色>_45度.png` 不能只是文件名或 prompt 文案写了 45°，人审拼版必须确认它实际是三分之二侧脸 / 3/4 视角，能看见一侧脸部轮廓与另一侧五官转折；正脸假 45、纯 90°侧脸、脸被发丝/阴影遮住都不得落 `ready`。后续可接视觉分类器，但当前以拼版人审为落档硬闸。

> **半身服装参考裁切 + 居中铁律（落档闸门）**：`定妆_<角色>_半身.png` 是已通过正面主参考的近景服装锚，不是另一张新脸，也不是“上半身 + 下半截补底”的占位图。生成方法固定为：从已通过自检的 `定妆_<角色>.png` 裁切上半身/腰部以上关键服装区域，再放大/重采样回 9:16；人物主体必须居中，头身中线接近画面中线，左右留白基本均衡，不能让大块空白或偏边构图进入参考组。不得新抽半身导致脸漂，不得用白底、浅灰底或空白补满下半截。若下半截出现大块纯色补底，或人物明显偏边，服装参考不得落档，需按本规则重裁。注意：这是定妆/半身参考图的硬闸门，剧情分镜图服从导演构图，不强制居中。

> **关键道具结构唯一性铁律（落档闸门）**：关键道具定妆和重道具分镜必须锁“结构拓扑 + 数量”，防止模型把动作词误解成新增部件。示例：白瓷毒酒壶写“唯一短颈圆口，无侧嘴/斜嘴/双口/额外开口/管状嘴”；短匕首写“一柄一刃，无双刃/多刃”；铜镜写“单面单镜面，无多镜面/重复镜框”；赐死托盘写“白绫、短匕首、白瓷毒酒壶三件套数量锁定”。避免“壶嘴逼近唇边”这类会诱发额外斜嘴的表述，改成“白瓷毒酒壶的唯一短颈圆口靠近唇边，不倒出、不新增嘴/管/斜口”。落档自检必须把侧嘴、斜嘴、双口、重复瓶口、多刃、多镜面、件数错列为硬伤。

> **⚙️法宝 / 特效定妆（仙侠玄幻题材专类）**：法宝按**形态/成长阶段**出多态（类比角色形态变体，如 `图片/定妆_飞剑_初始.png` / `图片/定妆_飞剑_觉醒.png`）；特效（剑气/灵力光效/法术/护体光/阵法）定**颜色 / 形状 / 拖尾 / 强度**，含特效镜头一律多图参考派生（角色定妆+特效定妆+上一关键帧）防漂。详见 `n2d-script/references/打斗分镜.md §五`。

### 自检（生成后逐张过 · 落档闸门）
> 定妆是**锚点**——脸一漂下游每个镜头都继承错误，所以这层比分镜更该卡。与上面"出图前检查"互补；同样按 `重抽预算策略` 两档决定重抽严格度：`预算充足`=所有图严格自检，出到满意为止；`预算一般`=只关键图片严格自检并出到满意为止，普通图无硬伤即可收。**定妆自检的重点不是单张好看，是"多张之间同一个人 + 与角色卡逐项对得上"。**
```markdown
**自检**（轻微偏差放行，只命中硬伤才重抽）：
- [ ] 角色 DNA 五层逐项对上角色卡、角色圣经和 registry（脸 / 发型 / 服装 / 配饰 / 质感；缺一项即漂，配饰无也要显式写无）
- [ ] 人物审美基线已执行：默认主流审美、镜头友好、精致好看；若角色圣经/剧情要求丑、怪、病、老、粗粝或非主流，已在本块写明特殊说明，且没有把角色洗成同质化网红脸
- [ ] 妆造拆解逐项对上角色卡（发型 / 妆容 / 服装 / 配饰 / 色卡，缺一项即漂）
- [ ] `identity_registry.json` 已登记本角色/形态的 `reference_group` / `identity_adapters` / `angle_policy` / `drift_forbidden`
- [ ] `identity_registry.json.reference_atlas` 已登记基础视角 / 表情 / 动作参考的 ready/planned 状态；本次实际传入后端的参考图只来自 ready 路径，planned 缺口已记录，不假装可用
- [ ] 若角色有 `evolution_profile`，本形态已挂到正确成长阶段；身份不变量（脸型/五官比例/核心发际线/体态/标志疤痣）未变，只升级允许项（服装/法宝/气场/VFX/姿态气质）
- [ ] 若登记 `generation_control`，固定 seed pool 已选本次 `requested_seed`；支持 seed 的后端会传入，未支持/未暴露 seed 的后端已准备 `seed_effective=false` 记账口径

- [ ] 标准三视图**对齐达标**（正 / 侧 / 背同身高、同比例、水平视平线对齐、同景别距离；纯灰底匀光无戏无表情）——"三张好看图"≠标准三视图，对齐不达标回**整张 turnaround 总图路线**或 **ControlNet turnaround 路线**重出（见 §1.2「标准三视图生产铁律」），不得当 ✅ 落档
- [ ] 45°参考实际是三分之二侧脸 / 3/4 视角，不是正脸改名或纯侧脸；脸部轮廓、鼻梁、下颌和发型侧前转折可辨，已在人审拼版标确认

- [ ] 半身服装参考符合裁切 + 居中规则：`定妆_<角色>_半身.png` 来自已通过正面主参考裁切并放大/重采样回 9:16；人物主体居中、头身中线接近画面中线、左右留白基本均衡；无白底 / 浅灰底 / 空白补下半截；未新抽导致脸漂

- [ ] 无硬性禁忌（无字幕 / logo / 多余手指 / 现代物件；<本项目专属堵漏，如觉醒态"不要铠甲护臂">）
- 重抽预算：<预算充足=出到满意为止；预算一般=所有人物基础定妆包同等过硬闸，动作参考/完整情绪库/LoRA 等增强项按体量升档> ｜ 实抽__次 → ⬜过 ⬜重抽 ⬜满意落档
```
- **过 = 可落档**：PNG 落 `出图/共享/图片/`，并把 `00_索引.md` 该条状态改 ✅（这一步就是「共享先行硬闸门」放行本集分镜图的前提）。
- 所有人物角色/形态的身份 DNA **零漂移容忍**；一次性/短线配角只在 LoRA、完整情绪库、动作参考等增强项上走普通上限，不能降低基础定妆包。

> **口径说明**：分镜图是剧情镜头，必须按导演视角八维装配，所以使用 `检查清单（八维自查·最易漏②机位/⑥光影/⑦张力）`；定妆图按产线规则是中性档案，不做剧情八维、不带戏剧光和情绪，只锁脸/造型/场景/道具基准，所以使用 `检查清单（定妆自查·最易漏③人物/⑥中性光影/一致性）`。执行时先验证检查结构，再提交生图。

### 2.1 `00_总览.md` 必含字段

- **本集视觉一致性契约**（⚠️像素层先行 · 出图阶段把视觉变量焊死成像素，凡视频改不动的导演决策都在这里下完）。**真值源在上游**：n2d-script 已在分镜设计阶段把这些写进 `脚本/第N集/storyboard.json` 的 `visual_contract` 种子块（场景光位锚/场景轴线视线/角色状态演进/景别阶梯/色调基线）——本契约是把它**誊抄并细化到出图层**（补每场景具体光位措辞、逐角色锚点对应的状态镜号），**不是凭空重新发明**；种子缺失时回 `n2d-script` 补 `visual_contract` 再出图。下游 `出视频/第N集/prompt/00_总览.md` 的「本集导演一致性契约」再**继承本契约**，三层同源、不各写一套。`gate.py --stage image_preflight` / 生成后 `--stage image` 缺契约或缺任一字段即阻断，与出视频侧同级严谨：
  - **色调基线**：本集/本段主色调 + 哪些色彩或光效只能在指定爽点后出现（如金瞳、妖气、系统光）——与出视频契约同源，色一旦烤进像素，视频改不回。
  - **场景光位锚**：逐场景定「主光方向 + 色温 + 动机光源」（如「冷宫正殿：画左前烛光顶侧光 / 3000K 暖 / 动机=残烛」）。**该场所有分镜继承同一光位锚**，跨镜不许各打各的光；剧情改光（吹烛/开窗/点灯）必须显式写理由。光位飘=剪起来闪，和脸漂同级穿帮。
  - **场景轴线·视线**：逐场景定「主要人物左右站位 + 轴线方向 + 默认视线方向」。**正反打两镜按此对位**——轴线/视线在出图阶段焊进首帧像素，出视频救不回（视频只动作不改站位/视线），所以必须在这里先定。换轴必须有反打/空镜/动作理由。
  - **角色状态演进表**：逐角色列「伤 / 泪 / 妆 / 服 / 发」随镜号推进的时间线（如「沈念：镜3 起左颊新伤→镜3+全程保留；镜7 发髻散乱→不再复原」）。**单调不回退**（出血的镜后面不许干净、乱发不许自愈），**状态不提前泄露**（觉醒前不发光、变身前不出现变体）。首帧逐张照此表烤渐进状态。
  - **景别阶梯**：本集/各段落的景别走向（establish→中景→特写…），**相邻镜不撞同景别同机位**（防 jump cut 廉价感）；要刻意 match cut 的同景别接点须显式标注。
- **本集基础视觉风格契约**（⚠️风格层先行 · 把用户选择的基础风格变成可继承规则）。**真值源在上游**：n2d-script 已在 `storyboard.json` 写 `style_contract` 种子块，本步誊抄并细化到出图层；种子缺失时回 `n2d-script` 补 `style_contract`。`gate.py --stage image_preflight` / 生成后 `--stage image` 缺契约或缺任一字段即阻断：
  - **风格名**：来自 `_设置.md` 的 `基础视觉风格`，如写实电影感 / 国漫写实 / 二次元赛璐璐 / 水墨国风 / 厚涂幻想 / 赛博霓虹 / Q版轻喜 / 自定义。
  - **视觉基调**：该风格的整体审美、角色比例、材质层次和画面密度；不是泛化“高清漂亮”。
  - **镜头与构图**：该风格下可用的景别、焦段感、透视、留白/剪影/线稿等构图原则；每镜从这里取，不随机变透视。
  - **光色策略**：主色 + 强调色 + 强调色出现时机；不同风格可以低饱和、平涂高明度、水墨墨色或霓虹高对比，但必须有统一纪律。
  - **运动边界**：出图首帧为视频留的运动空间要与风格相容；写实可克制手持，赛璐璐可更弹性，水墨偏慢，赛博可更锐利，但都禁止无理由乱甩。
  - **风格禁忌**：随所选风格派生。写实电影感可禁插画化/游戏CG；二次元赛璐璐不应禁“插画感”，而应禁照片皮肤/3D塑料/风格跳变。
- **本集专项镜头模板速查**（⚠️复杂镜头先继承模板，再出首帧/尾帧）。**真值源在上游**：`storyboard.json clips[]` 的 `template/template_contract`。凡打斗、追逐、对话反打、法术爆发、飞行、亲密互动、多人站位，逐 Clip 列出模板 ID、beats、blocking、camera_rule、continuity_must、negative 和模板专属字段；逐镜 prompt 必从这里誊抄，避免临场自由写动作。缺模板或字段不全时回 `n2d-script` 补 `专项镜头模板库.md` 契约。
- **本集资产身份速查**（⚠️角色身份先继承 registry）。**真值源在共享层**：`出图/共享/identity_registry.json`。凡本集入镜角色/形态，逐项列 `registry id`、`form`、`reference_group`、`reference_atlas` 可用状态、`evolution_profile` 当前成长阶段、图/视频后端身份状态、`generation_control` 固定 seed pool/后端支持状态、允许角度、高危角度、禁漂项；逐镜 prompt 必写具体 `CHAR_xx/形态` 并从 registry 自动取角色参考组、atlas 选图策略、成长阶段、seed 策略和禁漂约束，不能只看 `00_索引.md` 或中文角色名临场猜参考图。
- **本集资产引用速查**（⚠️关键场景/道具/独立服装/VFX 先继承 registry）。**真值源在共享层**：`出图/共享/asset_registry.json`。凡本集入镜的关键非人物资产，逐项列 `asset id`、`type`、`reference_group.primary`、场景 `scene_dna` 七项摘要、`constraints`、`drift_forbidden`；逐镜 prompt 必写具体 `LOC_xx` / `PROP_xx` / `OUTFIT_xx` / `VFX_xx` 并从 registry 自动取参考图、场景 DNA 和结构/光位/禁漂约束，不能只看 `00_索引.md` 或中文道具名临场猜参考图。
- **本集图数统计**（共享复用 vs 本集分镜，分别列）
- **进度**（已完成 / 总数）
- **已完成图归档**（共享库链接 + 本集出图链接）
- **出图依赖图**（哪些分镜需要哪些定妆作参考）
- **镜头 → 必传参考图 速查表**（路径指向共享库图片目录）
- **不重复**写定妆 prompt（指向共享 `00_索引.md` 链接即可）

```markdown

**剧本描述**：（复制自 分镜剧本.md 画面视觉描述）

  ↓
② 出图/共享/identity_registry.json 追加该角色/形态（reference_group / identity_adapters / angle_policy / drift_forbidden）；若新增的是场景/道具/独立服装/VFX，则追加到 `出图/共享/asset_registry.json`（LOC_/PROP_/OUTFIT_/VFX_ + reference_group / constraints / drift_forbidden）
  ↓

   （来源 = characters/X.md 的 ① 定妆 prompt + Stage 4 的实战包装：图 AI 设置 + 检查清单）
  ↓

  ↓

  ↓

```

## 打斗集出图（含武打/法术时）

> 含武打/法术的集，出图按 `n2d-script/references/打斗分镜.md` 工艺。要点：

- **一招出关键帧定格图**：起手帧 + **命中帧**（供 n2d-video 当首尾帧）。命中帧是打击感核心，画冲击波/火花/凹陷/受击 + 速度线 + motion blur。
- **法术/武器/光效进共享定妆库** `出图/共享/图片/`（如 `图片/定妆_青色剑气.png`），锁颜色/形状/拖尾；含特效镜头走**多图参考派生**（角色定妆 + 特效定妆 + 上一关键帧）防漂。
- prompt 写"动态定格 dynamic action pose / 发力瞬间 / 拧腰送肩 / 拖影"。
- 详见 `n2d-script/references/打斗分镜.md`（§二 五帧拆招、§五 特效一致、§九 示例）。

## 仙侠场面出图（御剑飞行/追逐/渡劫/炼丹炼器/大阵/大场面/斗法对轰/神魂）

> 含这些仙侠奇观的集，出图按 `n2d-script/references/仙侠场面分镜.md` 工艺。要点：

- **奇观元素进共享定妆库** `出图/共享/图片/`（飞剑/祥云、劫雷/护体光/突破光柱、丹炉/丹火/成丹、阵图、地标 establish），和角色脸/法宝特效同等对待，锁颜色/形状/质感——会漂就锁。
- **飞行**：出一张「巡航定妆」（标准飞行姿态）跨镜复用，治"飘"；速度感留给视频（动背景），出图只锁姿态与剑/云形态。
- **渡劫/炼丹/法阵**：**爆发帧单独出图**（雷击命中帧 / 开炉成丹帧 / 全阵激活帧）当 n2d-video 首尾帧——和打斗"命中帧"同地位.
- **大阵**：出一张「全阵俯视锚图」定几何+符文，局部镜从它**多图参考派生**（几何对称 AI 必崩，靠复用治）。
- **大场面 establish**：地标建「场景定妆」跨集复用；按"远全貌→中地标→近人物入画"三镜出，并放比例尺参照物（小人/小舟）衬恢弘。
- **斗法对轰**：撞点（能量对冲炸团）单独出图当首尾帧；双方法术光束**两色区分**（如金 vs 黑）各自入库锁一致。
- **神魂**：元神/神识波纹入库；元神**用肉身定妆做半透明发光态参考派生**（强度 0.75-0.85），治"二我"穿帮；夺舍成败帧（瞳色变）单独出图.
- 含奇观元素的镜头一律**多图参考派生**（角色定妆 + 奇观元素定妆 + 上一关键帧）防漂。
- 详见 `n2d-script/references/仙侠场面分镜.md`（§一~§八 各类拆解，含斗法对轰/神魂；§九 落地速查）。

## 4. 与 Stage 1 文件的关系

| 文件 | 谁写 | 角色 |
|---|---|---|
| `脚本/第N集/分镜剧本.md` | n2d-script | 提供"画面视觉描述"原文（艺术层）|
| `脚本/第N集/素材清单.md` | n2d-script | 简版图清单（理论） |
| `设定库/characters/<X>.md` 的 ① Prompt | n2d-script | 角色定妆 prompt 源头 |
| `出图/共享/prompt/角色|场景|道具定妆.md` | **n2d-image** | **实战定妆 prompt**（含 CLI 调用 + 检查清单 + 已知瑕疵） |
| `出图/第N集/prompt/01_分镜出图.md` | **n2d-image** | **实战分镜 prompt**（含参考图 + 操作） |
| `出图/第N集/prompt/00_总览.md` | **n2d-image** | 本集图清单 + 引用共享 + 进度 |
| `脚本/第N集/故事板.md` | n2d-script | Clip 表，**Stage 3 视频生成**用，不在 image prompt 文件夹中 |

**一句话**：
- `素材清单.md` = **简版图清单**（理论，Stage 1 出）
- `出图/共享/图片/` = **全篇定妆库**（按角色/场景维度组织，跨集复用，Stage 4 实战包装）
- `出图/第N集/图片/` = **本集分镜库**（按集 + 镜头维度组织，Stage 4 出）
- 跨 AI 时（图 AI ≠ 生视频模型）每个 image prompt 末尾要拼生视频模型的"图像风格锚定句"，详见 `platforms.md`。
