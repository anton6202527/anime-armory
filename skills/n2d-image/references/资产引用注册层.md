# 资产引用注册层（场景 / 道具 / 独立服装 / VFX）

目标：把关键非人物资产从“索引里的中文名 + PNG”升级成可执行的 ID 映射。角色脸和角色形态归 `identity_registry.json`；会随剧情变化的伤痕/战损归 `visual_state_ledger.json`；场景、道具、独立服装/套装、法宝/光效/VFX 归本层。

**场景 DNA（Scene DNA）**：观众记住的不是孤立角色，而是“角色 + 环境归属感”。反复出现的地点必须在 `scene_dna` 锁七项：①归属锚（这个场景属于谁/什么组织/哪段剧情）②地标/识别物（悬空仙山、云海、白玉台阶、金色飞檐洞府）③空间布局/轴线 ④建筑材质/主色 ⑤光色/天气/气候 ⑥常驻物件/植被/水体（青石、灵泉、竹林等）⑦禁漂项。角色定妆锁“这是谁”，场景 DNA 锁“他属于哪里”；二者都漂，观众会觉得整部戏换了世界。

**独立服装契约（Outfit Profile）**：`OUTFIT_xx` 只用于可跨角色/跨形态/跨集复用的服装或套装。它必须像角色 `wardrobe_profile` 一样锁剪影、层次、领袖腰摆、材质、纹样、色卡、适配体型、禁漂项和允许状态；普通角色某一形态自带的衣服仍写在 `identity_registry.forms[].wardrobe_profile`，不要重复建 `OUTFIT_xx`。

机器真值文件：

```text
出图/共享/asset_registry.json
```

`出图/共享/prompt/00_索引.md` 继续做人读索引；`asset_registry.json` 负责 gate、批量任务、出图执行和审片漂移分组。

## 1. 何时建 ID

| 类型 | ID 前缀 | 何时登记 |
|---|---|---|
| 场景 / 地点 | `LOC_` | 反复出现、跨镜轴线/光位/布局要稳定的场景 |
| 道具 | `PROP_` | 剧情关键或反复入镜，结构/件数容易被模型画错的道具 |
| 独立服装 / 套装 | `OUTFIT_` | 可在多个角色、多个形态或跨集单独复用的服装资产；普通角色服装仍放 `CHAR_xx/形态` |
| 法宝 / 光效 / VFX | `VFX_` | 颜色、形状、拖尾、强度需要跨镜统一的特效或法宝表现 |

不要给一次性、无复用价值、没有结构要求的小物件滥建 ID；但只要用了共享场景/道具参考图，逐镜 prompt 就必须写对应 ID。

## 3. 字段规则

| 字段 | 规则 |
|---|---|
| `kind` | 必须是 `n2d_asset_reference_registry` |
| `assets[].id` | 必须唯一；前缀必须匹配类型：`scene/location -> LOC_`、`prop -> PROP_`、`outfit/costume -> OUTFIT_`、`vfx/effect -> VFX_` |
| `reference_group.primary` | 必填；作品根相对路径；video/compose/review gate 会检查路径真实存在 |
| `scene_dna` | 场景/地点类 `LOC_` 推荐必填；反复出现或承担角色归属感的地点必须填。锁 `belonging_anchor`、`landmarks`、`spatial_layout`、`architecture_materials`、`color_lighting_weather`、`resident_assets`、`allowed_variations`、`forbidden`。`constraints` 偏执行闸门（布局/轴线/光位），`scene_dna` 偏观众记忆和 prompt 复述。 |
| `outfit_profile` | `OUTFIT_` 推荐必填；可复用服装/套装必须写。字段口径与角色 `wardrobe_profile` 对齐：`silhouette/layers/collar/sleeve/waist/hem/fabric/pattern/palette/fit_rules/allowed_state_modifiers/forbidden_drift`。逐镜引用 `OUTFIT_xx` 时继承本字段，不允许只写中文服装名。 |
| `constraints` | 必填非空；场景至少锁 `layout/axis/light_anchor/structure` 之一，道具必须锁 `structure` |
| `drift_forbidden` | 必填非空；审图/审片零容忍项 |
| `lifecycle` | 可选；自由文本**或**结构化 `{"states":[有序态…], "transitions":[{"from","to","at_clip"/"trigger"}]}`。结构化时 `scripts/asset_lifecycle.py` 机检状态只前进不回退（摔碎的瓶子又完好/特效退级 = `lifecycle_regression` **block**），`from/to` 必须是已声明 state；自由文本只 `info` 提示"升级为结构化可机检回退"，不 block |
| `forms` / `vfx_params` | 可选（武器升级/法宝多形态/特效分级）；`forms[]` 每个形态需 `id`（各自定妆、各自锁颜色拖尾），`vfx_params.color_target`(HSV)/`trail` 锁颜色与拖尾长度防跨镜窜色。`asset_lifecycle.py` 校验结构 |

道具约束要写“结构拓扑 + 数量”，不要只写材质和颜色。示例：铜镜写单镜面；毒酒壶写唯一短颈圆口；托盘写三件套件数；匕首写一柄一刃。

**状态演进结构化（F·治"道具破了又自愈/特效退级"）**：含破损/消耗/升级的道具或分级特效，把 `lifecycle` 升级成结构化 `states`(有序)+`transitions`。`states` 下标即时间序，`transitions` 的 `to` 必须排在 `from` 之后；机检 `python3 skills/n2d-image/scripts/asset_lifecycle.py <作品根>`（也由 `image_qc` 作为 registry 级 advisory 调用，回退/未知态进 hard，自由文本 info）。这和角色的 `state_continuity.py`（伤/泪/妆/服单调推进）同构，把"道具状态"也纳入单调不回退的机检。

**成长 VFX（系统面板等母题·治"面板退档/等级回退"）**：穿越/系统流的"系统面板"是高频复现且带成长的母题 VFX。登记为 `VFX_系统面板`（type=vfx），用 `forms[]` 作**等级档位**（如 `v1_素纹`/`v2_流光`/`v3_符纹`，每档各自定妆参考），`lifecycle.states` 把档位排成时间序、`transitions` 锁档位只进不退（面板退档=`lifecycle_regression` **block**，零新增代码——`asset_lifecycle.py` 已覆盖）；`vfx_params.color_target`(HSV) 锁系统青跨镜不窜色；`drift_forbidden` 写 `color`/`frame_shape`/`text_baked_in`（**禁止 AI 把文字数字烤进面板**）；`constraints.structure` 写"半透明圆角光幕/符纹边框固定/**内部文字区留空**"。等级/属性数值是 n2d-compose 期 overlay 文字层（见 `n2d-script/references/题材母题框架.md`），不进出图。母题桥段与档位推进由 `motif_registry.json` 的 `growth_state_machine` 驱动，VFX 成长状态机本体落本表。示例：

```json
{
  "id": "VFX_系统面板", "type": "vfx", "name": "系统面板光幕",
  "reference_group": {"primary": "出图/共享/图片/定妆_系统面板_v1.png"},
  "forms": [{"id": "v1_素纹"}, {"id": "v2_流光"}, {"id": "v3_符纹"}],
  "vfx_params": {"color_target": {"h": 195, "s": 0.4, "v": 0.95}, "trail": "无"},
  "lifecycle": {"states": ["v1_素纹", "v2_流光", "v3_符纹"],
    "transitions": [{"from": "v1_素纹", "to": "v2_流光", "at_clip": "EP03_CLIP12"}]},
  "constraints": {"structure": "半透明圆角光幕+固定符纹边框，内部文字区留空（数值由 compose overlay 叠）"},
  "drift_forbidden": ["color", "frame_shape", "text_baked_in"]
}
```

## 4. 逐镜 prompt 怎么写

```markdown
**资产引用注册层**：`LOC_01` 冷宫寝殿；`PROP_02` 赐死托盘；从 `出图/共享/asset_registry.json` 继承 reference_group / scene_dna / constraints / drift_forbidden；锁冷宫 scene_dna（斑驳铜镜、残烛、旧床榻、剥落宫墙、冷青灰+残烛+冷月）、layout/axis/light_anchor，锁赐死三件套数量和毒酒壶唯一短颈圆口。
```

规则：

- 参考图块含“场景定妆”或 `定妆_<场景>.png`，必须写对应 `LOC_xx`。
- 场景/地点镜必须写“场景 DNA 摘要”：地标、材质/主色、光色天气、常驻物件/植被/水体。不要只写“青云宗大殿/冷宫外院”这种空名。
- 参考图块含“道具锚”或 `定妆_<道具>.png`，必须写对应 `PROP_xx`。
- 服装如果只是某角色某形态的一部分，不单独写 `OUTFIT_xx`；只有可独立复用或跨角色/跨集复用时才登记。逐镜用了 `OUTFIT_xx` 时，仍要同时绑定穿它的 `CHAR_xx/形态`，并写清“角色身份来自 identity_registry，服装资产来自 asset_registry”。
- 执行端按 ID 读取 `reference_group.primary` 和 `constraints`，不要只靠中文道具名临场猜图。

## 5. gate 规则

`n2d-review/scripts/gate.py` 会检查：

- `asset_registry.json` 是否存在、kind 是否正确、assets 是否非空。
- ID 前缀是否和类型匹配，是否重复。
- 每条是否有 `reference_group.primary`、`constraints`、`drift_forbidden`。
- 场景是否锁布局/轴线/光位，关键道具是否锁结构唯一性。
- 瓶/酒/药/壶类关键 PROP 是否写了 `constraints.must_not_have` 或顶层 `must_not_have`，并在 `constraints.scale` 写清固定尺寸。逐镜引用这类 PROP 后，`image_qc` 会扫描对应已落档 PNG 并生成 `prop_shape_review` 硬复核队列；未重出或未在 `生产数据/image_qc/<ep>/prop_shape_confirmations.json` 逐图确认无禁形且尺寸一致时，`dashboard gate --stage image` 不放行。
- 长线/高频场景是否有 `scene_dna`；缺失时至少在报告中提示补齐，避免场景只靠单张图而没有归属锚。
- 逐镜用了场景/道具参考图但缺 `LOC_xx` / `PROP_xx` 时阻断。

原则：人读索引可以宽松；机器 registry 必须结构化，否则后续批量出图、审片和定向返工无法知道“这个漂移应该对照哪一个资产”。
