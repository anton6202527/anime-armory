# 角色 DNA Checklist（出图必对·跨集锁脸锁发型锁服装锁配饰）

> **目的**：让"同一角色 100 集同一套角色 DNA"成为可勾选的硬流程，而不是凭感觉。
> 一致性不是某一步的事，是一条**建卡 → 定妆 → 复用 → 锚点 → 出视频**的铁律链——任一环断，整集穿帮。
> 本表是 `n2d-image` 出图时的对照清单；规则散见 `n2d-script/references/formats.md`（角色卡）、`n2d/Q&A.md` Q3-Q12/Q16/Q18-Q20/Q24，这里汇成一处。

**角色 DNA 五层定义**：角色不是一张脸，而是 **脸 → 发型 → 服装 → 配饰** 五层叠加。① 脸=脸型、五官比例、肤色、疤/鳞/痣；② 发型=发色、发髻/披发轮廓、发饰；③ 服装=款式、领口、袖型、材质、主辅色、剪影；④ 配饰=发簪、腰牌、护甲、钥匙、法宝挂件等标志物；⑤ 质感=皮肤毛孔、布料经纬、反光率等微相物理细节。只锁脸但发型、服装、配饰漂了，观众仍会判断为换人。作品根 `设定库/角色圣经.md` 是人读总入口，额外记录气质/动作习惯作为表演层；`identity_registry.json` 是机器真值。

**人物审美基线定位**：除非用户、角色圣经或剧情特别说明“丑、怪、老、病、恐怖、喜剧丑角、粗粝写实、非主流”等，人物默认按当下主流可播审美和镜头友好处理：五官比例协调、脸部清晰有辨识度、发型妆造服装精致耐看、光影让脸立体好看。它是角色 DNA 之外的默认审美方向，不允许覆盖年龄、身份阶层、伤病/战损、反派气质和关键缺陷，也不能把不同角色统一成同一张网红脸。

**固定 seed pool 定位**：seed 只锁随机起点，不锁角色身份。支持 seed 的后端要传 registry 中的固定池；不支持或未暴露 seed 的后端要在生产事件里记 `seed_effective=false` no-op 降级，不能把 Codex 这类入口当可复现产线。角色一致性仍以角色圣经、reference_group、原生主体/LoRA 和 QC 为主。

**角色参考图数据库定位**：`identity_registry.reference_atlas` 是 `reference_group` 的增强索引，按 `CHAR_xx/形态` 管正脸 / 45° / 侧脸 / 半身 / 全身 / 背影、表情参考、动作参考和逐镜选图策略。它的作用是让每集出图“按镜头类型取参考”，不是让全员先烧完整图库；只有 `status=ready` 的图能传给后端，`planned` 只记录缺口。

**跨集成长升级定位**：长线角色的炼气/金丹/化神、病弱/掌权/妖力稳定等阶段，走 `identity_registry.characters[].evolution_profile`。原则是**同一张脸，外层升级**：脸型、五官比例、核心发际线/发量、体态、标志疤痣是身份不变量；服装、法宝、气场/VFX、配饰权重、姿态气质才是成长变量。

**角色资产包定位**：核心/长线角色应有项目内 `设定库/character_assets/<CHAR_ID>__<slug>/manifest.json`，把 reference / prompts / lora / voice / adapters / qc 归拢成可迁移包。它不是第二真值，不重新定义角色 DNA；换项目复用时走 `n2d-asset-market` 导出模板并 fork。

优先级（投入产出比从高到低）：
**① 锚点句每镜拼 > ② 定妆多图参考派生（多视图锁脸·禁纯文生图）> ③ 资产身份注册层（角色 ID / Face Lock / LoRA 状态）> ④ 扫共享库防重建（角色+场景）> ⑤ 不中途换工具 > ⑥ 平台建角色/LoRA/多镜故事板**
前四条是量产地基，**必须做满**；后两条是参考图压不住时的升级。

## 一、建卡层（设定先于出图，治"没有锚点可对"）

角色卡（`设定库/characters/<角色>.md`，首次出现即建、全篇唯一）必须含：

- [ ] **角色 DNA**：五层显式列出——脸、发型、服装、配饰、质感；没有配饰也写“无”，避免下游临场补发簪/耳坠
- [ ] **角色圣经**：新增或修改角色后，同步 `设定库/角色圣经.md`；角色卡、角色圣经、`identity_registry.json.character_dna` 三者不一致时先停下对账
- [ ] **妆造拆解**：发型/发色/发饰、妆容、服装（款式·领口·袖型·材质·腰带）、配饰、**色卡（主+辅+点缀）**；妆造拆解必须能回填到角色 DNA 五层
- [ ] **人物审美基线**：默认主流审美、镜头友好、好看但不网红脸；若本角色要丑、怪、老、病、恐怖、粗粝、喜剧丑角或非主流造型，必须显式写特殊说明和不可美化项
- [ ] **识别锚点 3-5 个**：跨集绝不能漂的特征（例：凤眼薄唇 / 乌黑半披素布发带 / 左腕淡疤 / 月白粗布旧宫装）
- [ ] **锚点句**：把锚点压成一句（例「凤眼薄唇·乌黑半披发带·月白粗布·左腕淡疤」）—— 下游每张分镜 prompt 末尾要拼它
- [ ] **形态变体单列**：常态 / 觉醒态 / 银牌态 / 死亡态，各记差异点，**各算独立定妆条目**
- [ ] **反派/易混角色：写"对立特征"**（见第六节）

> 卡没建全 = 后面无据可依。`出图/共享/prompt/角色定妆.md` 是这张卡的"实战 prompt 包装"，妆造拆解必须与角色卡完全一致。

## 二、定妆层（出"参考锚点图"，不是"最美的图"）

**默认审美**：定妆不是单张“最美图”，但人物也不能无故丑、糙、素、路人化。除非特殊说明，正面、45°、侧面、半身/全身和脸部特写都应保持主流可播审美：五官清晰协调、脸型和发型有辨识度、妆造服装精致耐看、材质和光影干净。审美服务角色，不改变角色 DNA、不抹掉伤病/战损/年龄/身份和剧情需要。

**角色定妆组（所有人物必出标准三视图 + 人审拼版，厚锚点）**——单张正脸不再作为人物定妆合格线：

- [ ] **正面主参考**：正脸中性光 + 半身脸部特写 → `定妆_<角色>.png`（下游分镜的主参考图，锁脸）
- [ ] **侧面参考**：标准侧面 → `定妆_<角色>_侧.png`（锁鼻梁 / 下颌 / 发型侧轮廓；侧脸、转头、过肩镜必备）
- [ ] **背面参考**：标准背面 → `定妆_<角色>_背.png`（锁后脑勺发型 / 背部服饰 / 披风 / 腰带绑法；over-shoulder、转身、追逐背身镜不再无参考）
- [ ] **服装参考**：半身或全身 → `定妆_<角色>_半身.png` 或 `定妆_<角色>_全身.png`（二选一；锁衣领 / 袖型 / 腰带 / 配色 / 体态）。若用 `_半身.png`，它必须从已通过自检的正面主参考裁切并放大/重采样回 9:16，且人物主体居中、头身中线接近画面中线、左右留白基本均衡；不得新抽半身导致脸漂，不得用白底/浅灰底/空白补满下半截，不得人物明显偏边
- [ ] **人审拼版**：标准三视图 → `定妆_<角色>_三视图.png`（由已通过自检的正面 / 侧面 / 背面生产拆图拼成，给人快速审脸审服装和归档；不作为分镜主参考）
- [ ] **增强设定表 / 表情条**：`定妆_<角色>_设定表.png` 可纳入半身/全身/色卡/配饰；`定妆_<角色>_表情.png`（喜 / 怒 / 哀 / 惊）用于情绪特写多的角色
- [ ] 定妆组全用**同一 prompt 同一模型**，只改"正面 / 侧面 / 背面 / 半身 / 全身 / 表情"那一截，背景妆造一致
- [ ] **标准三视图＝对齐档案，不是三张好看图**（治"三视图不标准"）：判定靠**中性同源 + 对齐**两组硬条件——① 同模型同基底 prompt 只改正/侧/背一截、纯灰底柔和匀光、无表情无戏（带戏污染下游参考）；② 正/侧/背**同身高·同比例·水平视平线对齐·同景别距离**（这是"标准三视图"与"三张好看图"的分界线）。生产优先**「整张 turnaround 总图同框出 → 拆正/侧/背」一次锁对齐**（多参考后端最适合）；其次以正面主参考派生侧/背并锁同身高/同视平线；要工业级正交转身（同高三机位）闭源平台给不了，走 ComfyUI turnaround pose 模板 + IP-Adapter FaceID（与 LoRA 数据集同源产物）。对齐不达标 = 与脸漂同级硬伤，不得标 ✅。详见 `prompt_format.md §1.2「标准三视图生产铁律」` / `lora_consistency.md Stage 1·3`
- [ ] **审美不牺牲标准**：可以追求更好看，但不能为了漂亮牺牲中性光、同身高、同视平线、同景别、双手可见和角色 DNA；也不能为了“档案照”把人物写得无质感、无主流审美或像随机路人
- [ ] **半身服装参考裁切＝服装锚，不是占位画布**：`定妆_<角色>_半身.png` 来自已通过正面主参考的上半身/腰部以上裁切，再放大/重采样回 9:16；无下半截白底/浅灰底/空白补画布。出现大块纯色补底会污染下游多图参考，必须重裁后才可标 ✅
- [ ] **命名不要混**：多张可喂给生图模型的参考 PNG 叫「定妆组」；单张合成总览才叫「三视图 / 设定表」
- [ ] 短线配角 / 路人：仍按标准三视图建人物定妆；若只是人群剪影、无明确身份且不会复用，按场景元素处理，不建角色定妆

**定妆库两层：中性锚（锁身份）/ 风格氛围（锁调性）（①·机检 `image_qc.face_anchor_lighting_audit`）**：业界做定妆的铁律是**平光、中性背景**——`face_anchor_refs` 这类**身份锚**必须是中性平光纯背景板，否则模型会**把光当身份烤进脸**（戏剧光/烛光/逆光的氛围板做脸锚，换个光就"换了个人"，正是定妆阶段脸漂的成因之一）。带戏剧光的好看图归**风格氛围层**：另存、用 `layer:"atmosphere"`（或 `lighting:"dramatic"`）标注，只用来锁画面调性 / 给导演看 mood，**绝不进 `face_anchor_refs`**。脸锚若误用氛围板，`image_qc` 名/标签启发命中（烛光/暗调/逆光/夜景…或显式 `layer:atmosphere`）记 warn，应换中性平光板。反过来，中性锚显式标 `lighting:"neutral"` / `layer:"identity"` 可盖过命名启发。

**脸部锚信噪比门（①·机检 `image_qc.weak_face_anchor` / `weak_face_anchor_core`）**：`face_anchor_refs` / `表情_*` / `脸部特写`
这类**应当紧裁**的脸锚，2026 锁脸教头一致要求 **≥1024px、脸占画面 30–50%**——脸太小=身份信号弱，喂给下游每镜
都把脸漂带进去。`image_qc` 对已落档脸锚机检脸占比（<12%）+ 裁切短边（<768px），普通角色过弱记 warn；核心/长线角色过弱记 block，必须重出更紧的脸部
特写后再放行。注意：本门**只管脸锚**，不碰「双手可见」的宽身位主参考（那张本就该脸小，分工见下条）。检测器漏检风格化脸时
只按分辨率判，不据占比误杀。

**主参考张本身的硬要求**（它要当参考图复用，歪一张毁整集）：
- [ ] **干净浅灰纯色背景 + 柔和均匀光**（不是场景、不上电影级强阴影——便于锁脸锁妆造）
- [ ] **双臂、双手可见**（后续动作戏 / 图腾 / 抓握要用，藏手就废；脸因此偏小是正常分工——脸的信噪比交给脸部锚那张紧裁图，见上「脸部锚信噪比门」）
- [ ] **竖版 9:16**，模型与该角色所有图**同一个**（换模型脸会跑）
- [ ] **分辨率 ≥1024px·定妆组至少覆盖正/侧/背标准三视图**（可扩到 3–6 角度；2026 多参考后端实战下限：参考图越清晰、角度越全，锁脸越稳）
- [ ] **身份锁定句与锚点句叠加用（别混）**：锚点句锁"特征词不漂"、身份锁定句锁"与参考图①就是同一张脸"（多参考/编辑类模型对后者最敏感）——含角色镜头两句都拼，见 `prompt_format.md §2.2`
- [ ] **挑图优先级**：① 姿态最中性 ② 手臂可见 ③ 脸最像设定 ④ 视觉冲击排最后
- [ ] **挑图 6 条核对**：脸型对 / 发型发色对 / 服装色对 / 配饰对 / 设定细节(疤·雀斑) / 背景纯色
- [ ] 4 张全废 → **同 prompt 再抽一轮**（别改 prompt；即梦同 prompt 不同种子差异大）

**重抽 vs 接受**（治"无止境刷图烧 credit"）：

| 偏差 | 处理 |
|---|---|
| 服装色错（月白→紫）、发型错（双环髻→披发） | **重抽**（全集穿帮） |
| 气质/表情风格错（伪善画成凶相） | **重抽**（气质定角色） |
| 年龄 ±3-5 岁、缺疤/雀斑等小细节 | **接受**（分镜阶段圆） |
| 多/少配饰 | 看是否破坏身份——破坏才重抽 |

> 形态变体（觉醒态…）**必须用常态定妆做参考图**（强度 0.75-0.85），否则"觉醒前/中/后"变三个人。

- [ ] **一致性高危镜预案（2026 公认崩脸带：极端角度 / 大暗部 / 人物在画面太小）**：这三类镜跨图与 image2video 都最易脸漂——出图时**提参考强度 + 补对应角度定妆（侧/背）**，视频用后端 Character-ID/Face-Lock；能在分镜阶段避就避（极端俯仰改常规角度、过小人物改中近景、纯黑环境留一束补光照脸）。分镜侧约定见 `n2d-script/references/分镜语法.md`「一致性高危镜」。

- [ ] **视频近景升格预案**：如果视频落幅会把锚帧中的小脸/远景/侧背/遮挡人物推成 CU/MCU/半特写，必须先补同源近景锚帧/表情参考并过 full `image_qc`；否则视频模型会临场补脸，最终 MP4 可能出现“不是这个角色”的新脸。缺锚帧时改 OTS/侧脸/手部/物件反应镜，或保持原景别。

- [ ] **角色参考图数据库（Reference Atlas）按“基础硬包 + ROI 增强”分层建**：
  - **基础硬包（所有人物/形态）**：正脸、45°/three_quarter、侧脸、背影、半身或全身服装锚、脸部特写基础锚全部 `ready`；planned 只能表示待补，不能放行。
  - **45°/三分之二侧脸是全员基础角，不再只按 CU 重角升档**：2026 共识是 **正面 + 3/4 + 侧面 是身份核心集**，纯 90° 正侧是较弱的重投影锚。`face_drift_risk.py` 对任一入镜人物若 `base_views.three_quarter.status != ready` 会出 `missing_3q_baseline` 缺口：先把 3/4 侧脸从 `planned` 补成 `ready` 再出图，别等近景脸漂了才补。落 `ready` 前必须在人审拼版确认它实际是 3/4 角，不是正脸改名或纯侧脸。
  - `core_full`：全篇核心/长线主角/主反派，在基础硬包外优先补完整表情库和高频动作（如持剑/御剑/施法/奔跑）。
  - `supporting_selective`：中线/功能角，基础硬包齐，表情/动作按本集需要补；没有大表情近景就不预制全套表情。
  - `minimal_base`：短线单元反派/路人，基础硬包齐；动作/表情临近需要时补。
  - `restricted_partial`：不露脸/只局部角色，只登记允许的手部/剪影/背影；正脸/表情槽位写 restricted，不得 planned 后被误引用。
  - 每个槽位都写 `ready|planned|restricted|deprecated`；逐镜只允许引用 `ready`。缺 45° 或脸部特写基础锚必须先补共享参考；缺表情/动作时写 `reference_gap` + 回退/保真实现方案（MCU/OTS、拆正反打、先补共享参考）。

- [ ] **服装契约（Wardrobe Contract）已建**：
  - 每个会复用、会影响身份识别、或会被 prompt 明确点名的角色形态，都在 `identity_registry.characters[].forms[].wardrobe_profile` 写清剪影、层次、领型、袖型、腰封、下摆、材质、纹样、主辅点缀色、禁漂项和允许状态。
  - `character_dna.outfit` 只做摘要；真正执行和 QC 继承 `wardrobe_profile`。没有独立服装变化的短线角色也至少写 `silhouette/palette/forbidden_drift/aliases` 四项，避免下游只记“白衣/黑衣”。
  - `reference_atlas.outfit_refs` 至少登记全身服装锚；核心/长线角色补领口袖口、腰封下摆、纹样材质色卡。只有 `ready` 的服装局部锚可进入分镜参考。
  - 本镜临时血迹、灰尘、破损、雨湿走 `visual_state_ledger`；跨镜复用或改变主色/剪影的换装必须新建 `CHAR_xx/形态`。

- [ ] **服装选择评分卡已过**（出图前、付费重抽前先判）：剧情身份/阶层信号、剪影辨识度、与其他角色主色差异、竖屏小图可读性、AI 可复现难度、动作/视频友好度、跨集复用价值。任一主角/主反派低于可接受线，先回角色卡/角色圣经改服装，不进出图。

- [ ] **角色服装对比矩阵已过**：把本集重要角色/形态按全身剪影 + 主辅色 + 标志配饰并排审；若两名以上角色在同场景里同时出现且服装主色、剪影、发型都接近，必须至少改一项锚点，避免模型和观众都分不清。

- [ ] **跨集成长升级机制（Evolution Profile）已建**：

## 三、复用层（共享库 + 5 步 SOP，治"跨集脸漂移"）

**最容易翻车的一环：每集出图前必走 5 步 SOP，第 ① 步跳了必漂移。**

- [ ] **① 扫共享库**：先读 `设定库/角色圣经.md`，再读 `出图/共享/prompt/00_索引.md`、`identity_registry.json`、`asset_registry.json`，盘清已有角色（含形态变体）/场景/道具及状态；长线场景额外看 `scene_dna` 是否齐
- [ ] **② 列本集需求**：读 `分镜剧本.md` + `素材清单.md`
- [ ] **③ 差集 = 新增**：本集需求 − 共享已有（含"新角色" + "已有角色的新形态"）
- [ ] **④ 仅追加新增项**到共享库（索引 + 定妆 prompt 块）
- [ ] **⑤ 建本集 prompt**：`出图/第N集/prompt/{00_总览,01_分镜出图}.md`，总览**引用**共享、不重画

- [ ] **共享 vs 本集归档**：角色/场景/反复入镜道具定妆 → `出图/共享/图片/`（全篇一份）；一镜一图分镜 → `出图/第N集/图片/`
- [ ] **场景图同样建库复用**：反复出现的场景（宫殿/冷宫/庭院）= 共享定妆，出一次 `出图/共享/图片/定妆_<场景>.png`，跨集所有该场景镜头都引用它做参考图——**别每集重画背景**（背景漂移和脸漂移一样穿帮）。新场景走和角色相同的 5 步 SOP 入库
- [ ] **关键反复场景出多视图（场景四视图·题材自适应）**：贯穿多集的核心场景（主殿/洞府/山门/大阵地）除主图外，按机位需要补不同朝向/景深参考 → `定妆_<场景>_<向>.png`（如正向全景 / 侧向 / 反向（过肩背景）/ 俯瞰），让**跨镜头切换背景自洽**——同一空间这面墙切到那面墙不穿帮。一次性/单镜场景单图即可，**不必铺四视图**（按反复程度自适应，别给路人场景浪费额度）
- [ ] **共享 PNG 先行硬闸门**：本集分镜 PNG 生成前，`出图/共享/prompt/00_索引.md` 中本集引用的共享角色/场景/道具必须全部 ✅，且对应 PNG 文件真实存在；**✅ = 该定妆已过「生成后落档闸门自检」**（妆造逐项对卡 / 三件套同一个人 / 主要角色零漂移，见 `prompt_format.md §1.2` 自检块），出了图但没过自检不算 ✅；缺任一项或自检未过时**禁止生成本集分镜图**，先补共享层并过自检
- [ ] **Clip 图前完整资产基础包**：本集引用的人物/形态必须先完成正面、45°、侧面、背面、半身或全身、脸部特写或同源表情、三视图人审拼版，并核对配饰/标志物；本集引用的场景、道具、配饰、武器/法宝、VFX 必须先有共享参考图与 registry 约束。缺基础包时只能补共享层，不许先生成 `Clip_*` / `镜头*` 分镜 PNG。
- [ ] **参考图/图生图复用**：定妆照设为"角色参考图"，每张分镜基于它生成；重生成分镜图时也必须先加载/引用共享定妆 PNG
- [ ] **外部人物参考图只借身份，不借衣装**：生成定妆照若喂了外部人物参考图，参考范围只允许脸型 / 五官 / 眼睛神态 / 体态比例 / 身材气质；发型、发饰、服装、配饰、妆容、身份阶层和剧情状态必须按小说原文、角色圣经、当前形态变体和本集剧情定。参考图里的衣服、首饰、现代发型、拍摄妆造不得继承；除非角色卡明确要求同款，否则 prompt 要写“不要继承参考图服装/发型/配饰，只继承脸与体态”。

## 四、锚点层（每镜拼锚点句 + 多图参考派生 —— 双保险）

- [ ] **多图参考派生（铁律）**：含角色的镜头图**一律基于参考图派生**（image-to-image / 多图参考 / 平台角色绑定），**禁纯文生图**。喂：正面主参考（主 ~0.8）+ 侧面锚（~0.5-0.6）+ 背面锚（背身/转身/过肩镜加，~0.5-0.6）+ 半身/全身服装锚（~0.5，全身动作或服装易漂时加）+ 本镜场景定妆（~0.4-0.5），并在 prompt 写入 `LOC_xx.scene_dna` 的地标/材质/光色/常驻物件摘要
- [ ] **锚点句 + 多图参考叠加用，不互斥**：参考图锁"像不像"，锚点句锁"特征词不漂"；两条都做，跨镜相似度才稳到 90%+
- [ ] **每张含角色的分镜 image prompt 末尾，拼该角色卡的『锚点句』**（比单纯调参考图强度更稳，直接治脸漂移）
- [ ] prompt 结构：`主体 + 外貌锚定 + 动作 + 环境 + 景别 + 画风词 + [锚点句] + [固定生视频模型锚定句 / 通用视频兼容锚定句]`
- [ ] 锚点句放**最后做风格说明**，不要插进主体描述（会扰乱构图）
- [ ] 多角色同框：每个角色各拼各的锚点句
- [ ] **多角色同框是高危触发点（`gate.py` 对单镜 ≥2 清晰具名角色缺槽位/策略会 BLOCK）**：单图参考后端难保多人各自不漂；同框由剧情决定，要求是把它做对，不是删镜或降人数。**按 ROI 从高到低处置（前两步默认、后三步兜底）**：
  - **① 分镜调度服务剧情（默认·最高 ROI）**：双人/多人 CU 优先拆「单人 CU + 反打」；必须同框时默认中景/全景 + 景别分层（清晰主角领镜，其余过肩/前后景/反打承接）。**任一清晰同框 ≥2 具名角色都必须登记** `多人同框身份槽位` + `多人同框执行策略`；2-3 张清晰脸只是相对省钱/稳定的构图区，不是免登记区。≥4 清晰脸、多人近景、强交互/遮挡镜优先拆反打、景别分层或分别出图+合成（远景群像标 `远景/群像` 豁免）。
  - **② 路由强后端（有则用·无则回退 Codex）**：含 ≥2 具名角色镜优先路由可注册持久主体后端（Nano Banana Pro 最多 5 人 / Seedream 多图编辑 / 可灵 Character ID / Sora Cameo）写 `native_subject_slots`。当前默认 Codex，路由不到时不强切，继续 Codex 做 ③④。多参考 2–5 张最佳，过阈反降精度。
  - **③ 物理空间锁定与深度合成（2025 SOTA·首选实现）**：写 `split_composite_required` + `多人同框身份槽位`（LEFT/RIGHT/FOREGROUND/BACKGROUND 逐一绑定 `CHAR_xx/形态`、画面位置、视线、face_priority、自己的脸部参考/表情库、primary 星标）。实现 = 放弃纯 Prompt 抽卡，改用 **Spatial Control Block-out**：先出空场景底板，提取或手绘人物剪影/深度/骨骼图 (Depth/Pose) 锁死物理站位与空间透视关系；再通过 IP-Adapter/Redux 分区域重绘人物；最后使用 **IC-Light** 进行全局光照重匹配 (Relighting) 消除抠图感。不要用普通多参考硬抽多人同框反复烧 credit。
  - **④ 锚点去重**：逐主体 5–7 个互斥锚点（唯一发色/发型/服装主色 HEX/标志配饰），两两不撞色；reference_planner 的 `distinct_anchors` 给撞色对，逐镜写 `区分锚点` 字段（缺则 gate WARN）。
  - **⑤ LoRA 兜底**：核心角必须 CU 同框且前四步压不住 → `n2d-lora`，一角一 LoRA。

## 五、跨工具 / 跨阶段（治"风格中途跳变"）

- [ ] **同一集绝不换生图模型/渠道**（换模型或渠道=整集所有定妆重做，"一致性税"）；集间要换也得重做全部定妆

- [ ] **有角色的镜头一律用图生视频**（首帧=定妆/分镜 PNG 锁脸），不用文生视频
- [ ] **图片质检环境先告知（不静默降级）**：跑 `image_qc` / `dashboard gate --stage image` 前，记录并告知 `precision_level=full|degraded|none`、当前解释器、缺失依赖、建议安装、当前应停/回退阶段。`full` 需要 Pillow + cv2 + insightface + onnxruntime + buffalo_l；优先用 `facefusion` conda env 跑，系统 Python 3.14 不作为重视觉依赖首选
- [ ] **本集分镜出完跑出图落档机检**：首选 `/opt/homebrew/Caskroom/miniforge/base/envs/facefusion/bin/python skills/n2d-image/scripts/image_qc.py <作品根> 第N集 --json`，再跑同解释器的 `skills/n2d-dashboard/scripts/dashboard.py gate <作品根> 第N集 --stage image`。机检覆盖角色 DNA 第1层脸 G1 / 第2层发型 H1 / 第3层服装 N1 / 场景 O2 / 接缝 / 锚点门 N3（复用 n2d-review 阈值）+ 逐镜 prompt lint（参考图块/视线/锚点句/`CHAR_xx` 合法性；第4层配饰由 registry + 人审对照）。`block`（崩脸/纯文生图/非法ID/接缝断/降级精度近景）必修，`review`（像素初筛）人判。这是把审片阶段的一致性机检前移到落档、最便宜的点抓漂移
  > **风格化项目的脸机检后端（选择点 `脸一致性机检后端`·见 `n2d/references/选择点与偏好.md`）**：审片侧崩脸机检（`n2d-review/face_consistency.py`）的人脸 embedder 默认 ArcFace，对**风格化/漫剧脸 TPR 系统性偏低 ~0.76**（StyleID 论文 arXiv:2604.21689）；插画/动漫项目应切 `脸一致性机检后端: styleid`（需 StyleID 权重，缺则回退 arcface 标 `arcface_fallback`，绝不用裸 CLIP）。**诚实边界**：本 `image_qc.face_reference_coverage` 的 full 精度脸比对仍走 insightface(ArcFace) 同一栈、**尚未接该选择点**——风格化项目读 image_qc 脸覆盖结论时按此偏差留余量，styleid 接入 image_qc 是 follow-up
- [ ] **阶段跳转写清**：`full+ok` 才能进 `video`；`full+block` → `return_to_stage=image`，列受影响 PNG/镜头/prompt 并最小范围重出；`full+review` → 停在 `image_human_review` 人审；`degraded` → 停在 `image` 补装 full stack 后重跑或记录人审放行理由；`none` → 停在 `image_qc_setup`，先装依赖，不得把缺依赖当作图片通过

## 七、进阶层（参考图压不住时才上重武器）
