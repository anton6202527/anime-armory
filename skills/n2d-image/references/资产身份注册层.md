# 资产身份注册层（角色 ID / Face Lock / LoRA）

目标：把“定妆库”升级成**资产身份注册层**。同一角色不只是一组 PNG，还要有可被图/视频后端复用的身份记录：角色 DNA 五层、参考组、后端角色 ID / Face Lock / reference controls、LoRA 状态、允许角度和禁忌漂移项。

**角色 DNA 五层**：角色身份统一按 **脸 / 发型 / 服装 / 配饰 / 质感** 管。脸只是一层；发型、服装、配饰漂了，观众仍会判断为换人。registry 用 `character_dna` 持久化这五层，审图/审片和逐镜 prompt 都应引用同一份口径。

**角色圣经（Character Bible）**：作品根 `设定库/角色圣经.md` 是人读总入口，负责把 `CHAR_xx/形态`、锚点句、角色 DNA 五层、气质/动作习惯和参考组串成一张表；`identity_registry.json` 是机器执行真值。角色卡、角色圣经、registry 必须对齐；生成/修改 prompt 时先引用角色圣经，再按 `CHAR_xx/形态` 读取 registry。气质/动作习惯属于表演层，不写进 `character_dna` 五键。

**角色资产包（Character Assets）**：核心/长线角色可在 `设定库/character_assets/<CHAR_ID>__<slug>/manifest.json` 建项目内资产包，归拢 reference / prompts / lora / voice / adapters / qc 和缺口。registry 只用 `characters[].asset_bundle` 指向它；资产包不是第二真值，不得另写一套角色 DNA。跨项目复用时走 `n2d-asset-market` 导出模板并 fork，后端角色 ID、Face Lock、LoRA ready、voice id 默认重置。

**固定 seed pool（辅助随机起点锁）**：seed 不是身份锁，只是可复现随机起点。registry 可在每个 form 下登记 `generation_control.seed_strategy=fixed_pool`、`seed_pool` 和用途映射；执行时**支持 seed 的后端传入固定 seed，不支持或未暴露 seed 的后端记录 no-op 降级**（`seed_effective=false`），继续依赖角色圣经、`reference_group`、后端主体/LoRA 和 QC。Codex/OpenAI/Dreamina 等入口不得默认宣称 seed 可复现。

**角色参考图数据库（Reference Atlas）**：`reference_group` 是旧流程和 gate 的核心参考组；`reference_atlas` 是其上的可扩展索引，按 `CHAR_xx/形态` 记录基础视角（正脸 / 45° / 侧脸 / 半身 / 全身 / 背影）、同源表情参考（微笑 / 愤怒 / 震惊 / 哭泣等）、动作参考（持剑 / 御剑 / 施法 / 奔跑等）和逐镜选图策略。执行时**有图就传图，不支持/缺图就降级记录 gap**，不得把 planned 槽位当成已完成参考图。**所有人物/形态的基础视角中，45°/three_quarter 与脸部特写基础锚必须是 ready，不再按角色体量或近景占比延后。**

**服装契约（Wardrobe Contract）**：`character_dna.outfit` 只写摘要，`forms[].wardrobe_profile` 才是服装机器契约。每个可复用形态必须锁 **剪影 / 层次 / 领型 / 袖型 / 腰封 / 下摆 / 材质 / 纹样 / 主辅点缀色 / 禁漂项 / 可变状态**；这些字段既用于 prompt 继承，也用于 `image_qc` 从 registry 派生服装别名，拦“prompt 写玄青官袍却绑定月白寝衣 form”这类换装串形态。

**跨集成长升级（Evolution Profile）**：长线角色会从炼气到金丹、从冷宫病弱到掌权、从凡身到妖力稳定态，少年主角还会从幼年/14岁/18岁/成年/长生态一路变化。升级不是换角色：`characters[].evolution_profile` 把多个 `forms[]` 串成同一条成长线，规定**身份不变量**（脸型、五官比例、核心发际线/发量、体态、标志疤/痣等）与**允许升级项**（年龄体量、衣服、法宝、气场/VFX、配饰权重、姿态气质）。每次新阶段定妆必须从上一阶段/身份锚图 image2image 派生，保持同一张脸，只升级外层视觉。若 `age_sensitive=true`，新阶段 form、`age_band`、`target_file_prefix` 和共享 PNG 文件名都必须带年龄或年龄档；旧无年龄 form/文件只能登记为 `legacy_alias` 并补 `age_band/stage_label`。

边界：本文件只管**人物角色身份**（`CHAR_xx/形态`）。场景、道具、独立服装/套装、法宝/VFX 走 `出图/共享/asset_registry.json`，详见 `资产引用注册层.md`；受伤、战损、脏污等会变化状态走 `visual_state_ledger.json`。

机器真值文件：

```
出图/共享/identity_registry.json
```

`出图/共享/prompt/00_索引.md` 继续做人读索引；`identity_registry.json` 负责 gate、批量任务和后端适配。没有 registry，就无法判断“这个镜头该喂哪组参考、哪个后端 ID、哪些角度高危、哪些漂移绝对不能放行”。

闭环报表由 `n2d-identity` 生成：

```bash
python3 skills/n2d-identity/scripts/identity.py <作品根> --write
```

输出 `生产数据/identity_adapter_matrix.json/md`（reference group / Face Lock / Character ID / LoRA 后端 binding 矩阵）和 `生产数据/identity_drift_report.json/md`（跨集角色漂移报表）。出图/出视频/审片不要只读 registry 原文，应优先读 adapter matrix；registry 是真值，matrix 是可执行视图。

## 2. 字段规则

| 字段 | 规则 |
|---|---|
| `kind` | 必须是 `n2d_asset_identity_registry` |
| `characters[]` | 每个明确角色一条；人群剪影/无复用路人可不登记 |
| `evolution_profile` | **长线角色推荐·跨集成长升级机制**。角色级字段，串联同一角色多个 `forms[]` / 年龄 / 境界 / 权势阶段。`identity_anchor_form` 指向最初身份锚；`age_sensitive` 表示年龄/年龄档会影响定妆；`form_naming_policy` / `filename_policy` 规定年龄敏感 form 与 PNG 路径必须带年龄；`identity_invariants` 列不许变的“同一张脸”指标；`allowed_evolution_axes` 列允许升级的外层（年龄体量/服装/法宝/气场/VFX/姿态气质）；`stages[]` 记录阶段 ID、年龄档、集数范围、绑定 forms、目标文件前缀、从哪个上一阶段派生和视觉变化；`transition_policy` 必须写“新阶段从上一阶段定妆/脸部锚 image2image 派生，保留身份不变量”。**边界**：受伤、泪痕、脏污、临时战损走 `visual_state_ledger`；会跨多集复用并改变年龄体量/服装/法宝/气场识别的升级，走 `evolution_profile + 新 form + 新 reference_group`。 |
| `asset_bundle` | **核心/长线角色推荐·可迁移资产包引用**。角色级字段，指向 `设定库/character_assets/<CHAR_ID>__<slug>/manifest.json`，并记录 package_dir、role、sections、truth_policy。manifest 归拢 reference/prompts/lora/voice/adapters/qc、已有资产和缺口；不重新定义 `character_dna`、`forms[]` 或后端 ready 状态。短线角色可无此字段。 |
| `forms[]` | 常态、觉醒态、幼年态、换装态、18岁少年态、成年态、高阶长生态分别登记；形态变体不能共用同一身份状态。年龄敏感角色每个 form 必须填 `age_band`；新增/重出的 `asset_key` / `reference_group` 路径和 `reference_atlas` 路径应使用同一带年龄前缀。旧无年龄 form 可保留兼容，但必须在 `evolution_profile.stages[].legacy_alias` 写明。**服饰/形态定妆铁律**：会复用、会改变轮廓/主色/身份识别的可见状态（红衣觉醒态、白衣常态、战甲态、伪装态、妖化态、年龄阶段态等）必须独立 form + 独立 `asset_key` + 独立 `reference_group`。短期可逆的伤、泪、血迹、脏污、破损、能量光效属于 `visual_state_ledger`/分镜状态演进，不在 registry 新开 form，除非它跨镜复用并改变年龄体量、服饰主色或剪影。 |
| `character_dna` | **必填·机器真值**。五个键固定为 `face / hair / outfit / accessories / texture`，分别描述脸、发型、服装、配饰、质感；没有配饰写 `"无"`，不要省略。内容必须与角色卡「角色 DNA」/妆造拆解、`设定库/角色圣经.md`、`anchor_phrase`、`drift_forbidden` 对齐。新增或修改角色形态时先补本字段，再出定妆和逐镜 prompt。 |
| `physical_scale` | **可选·体态/相对身量**。`relative_scale` 是**唯一进 prompt 的字段**——写"以某角色为标尺的相对身量"（如 `比沈念高半个头` / `三人中最高、肩最宽`），多人同框时由 `reference_planner.plan_multi_subject_strategy` 收进 clip 策略并要求写进镜头 prompt，`n2d-review` 的「物理尺寸对账」据此对账。`height_cm`/`body_type` 是**写作连续性元数据，不注入出图 prompt**——绝对数字（175cm/60kg）对图像模型基本是装饰、占 token 却 steer 不动像素；只用于人读连续性和推导 `relative_scale`。体型的定性词（精瘦运动型/宽肩/娇小）写进 `character_dna.face`/角色卡「固定体态」即可，避免"壮/大/丰满"这类量级模糊词。身份级体型不漂仍由 `evolution_profile.identity_invariants` 的 `body_type` 与 `drift_forbidden` 锁。 |
| `wardrobe_profile` | **强烈推荐·服装机器契约**。`character_dna.outfit` 写摘要，本字段写可执行细节：`silhouette/layers/collar/sleeve/waist/hem/fabric/pattern/palette/accessory_lock/allowed_state_modifiers/forbidden_drift/aliases`。服装会跨镜复用、会影响身份识别或会被 prompt 明确点名时必须补齐；`image_qc` 会从本字段和 `character_dna.outfit` 派生服装别名，用来阻断换装串 form。 |
| `reference_group` | 至少包含 `front/side/back/outfit/turnaround`；路径为作品根相对路径。**多形态文件名必须去重且含本 form 的 `asset_key`**：路径文件名必须含形态标签（如 `定妆_柳娘子_人皮态_侧.png` / `定妆_沈念_红衣觉醒态.png`），不同 `form` 的同视图绝不允许同名，也不得把白衣/旧形态参考挂到红衣/新形态 form 下——registry 只存路径字符串，同名或串形态会让读方锁错脸/服装。`gate.py` 会阻断核心 reference_group 路径不含 `asset_key` 的注册。 |
| `reference_group.expressions` | **近景高频/情绪戏角色必填**一组**同源情绪定妆**（一脸多情绪），其余角色可选。每条登记 `{emotion, path}`，emotion ∈ `中性/喜/怒/悲/惊`（按本角色戏份取子集，核心角建议 ≥3 档含中性）；**同源铁律**——必须同模型同基底、与正面定妆同一张脸，只换面部肌肉表情，脸型/五官比例/发型/痣疤不变（哭脸≠新抽一张脸）。作用：下游 `n2d-video` 近景大表情变化镜用「起表情图→止表情图」做**首尾双帧只插值**，避免模型自由生成跨情绪表情时把脸重画。若暂缺，回退裁 `定妆_<角色>_脸部特写.png`（中性），并在 `00_索引.md` 标「表情库缺，大表情近景须降级 MCU」。列表里的路径必须属于同一 `asset_key`，例如 `CHAR_03/人皮态` 只能挂 `定妆_柳娘子_人皮态_...`，不能串到其他角色/形态。命名建议 `定妆_<角色>_表情_<情绪>.png` |
| `reference_atlas` | **人物/形态必填·角色参考图数据库**。不替代 `reference_group`，只做扩展索引和选图策略：`base_views` 管正脸/45°/侧脸/半身/全身/背影，`expression_refs` 管微笑/愤怒/震惊/哭泣等同源表情，`action_refs` 管持剑/御剑/施法/奔跑等动作姿态，`outfit_refs` 管服装全身、领口/袖口、腰封/下摆、纹样/材质色卡等局部锚，`selection_policy` 告诉逐镜 prompt 按镜头类型选哪些参考。每条有 `status=ready|planned|restricted|deprecated`；只有 `ready` 才能作为实际参考图传入后端，`planned` 只表示缺口和待补计划。**基础视角硬要求**：所有人物/形态的 `front / three_quarter / side / back / half_body 或 full_body` 必须为 `ready` 且有路径；`face_anchor_refs` 或 `expression_refs` 至少一项 ready/可用。**ROI 分层只影响完整表情库、动作参考、主体库/LoRA**：`core_full`（全篇核心）优先补完整表情+高频动作+服装局部锚；`supporting_selective`（中线/功能角）只补本集需要的表情/动作/服装细节；`minimal_base`（短线/路人）仍必须保基础视角；`restricted_partial`（不露脸/只局部）只登记允许的手部/剪影/背影/服装局部。 |
| `identity_adapters.image` | 图阶段后端适配；Codex 默认无持久 ID，写 `fallback_reference_group` |
| `identity_adapters.video` | 视频阶段 Face Lock / Character ID / reference controls；无能力时写 fallback |
| `identity_adapters.lora` | LoRA 状态；`ready` 时必须写 `base_model` + `model_path` + `trigger` |
| `generation_control` | **可选但推荐·固定 seed pool 执行口径**。`seed_strategy=fixed_pool`；`seed_pool` 至少 4 个整数；`usage.turnaround/expression/closeup/shot` 从池内取值；`backend_support` 用 `supported / unsupported_or_unknown / backend_dependent_verify_adapter` 等结构化值。执行规则：后端明确支持 seed → 传 `effective_seed`；后端不支持/未暴露（如 Codex 这类入口）→ 记录 `requested_seed` 但 `effective_seed=none / seed_effective=false / seed_support=unsupported_or_unknown`，并继续靠 reference group/主体/LoRA/QC。seed 不能替代角色 DNA 五层、参考组和审图。 |
| `angle_policy` | 允许角度、高危角度、需要额外参考的动作/角度 |
| `drift_forbidden` | 审图/审片零容忍项；必须覆盖角色 DNA 五层中会导致“换人感”的项：脸型/五官、发型/发色、服装主色/剪影、标志配饰、体态等 |
| `self_check_passed` | **可选·机器可读 finalize 真值**（补 `00_索引.md` 的人读 ✅）。该形态过「生成后落档闸门自检」（妆造逐项对角色卡 / 三件套同一人 / 主要角色零漂移）后置 `true`；自检未过留 `false`。**纯 opt-in**：不写此字段 = 未启用机器追踪（现有作品/先出视频 demo 不受影响）。写法：人工/AI 复核通过后跑 `python3 skills/n2d-image/scripts/image_qc.py <作品根> --mark-finalized CHAR_xx/形态`（资产用 `--mark-finalized PROP_xx`；标脏定妆加 `--unfinalize`）。一旦启用，`gate --stage image` 会拦「本集逐镜引用了 `self_check_passed=false` 的脏定妆/资产」——治 `00_索引.md` 只标 ⬜ 不标 ⏳ 的漏网 + 没列进就绪表就静默放行的软肋 |
| `anchor_sha` | **可选·锚点指纹钉死（治跨集脸漂结构根因·锚点静默漂移）**。form 的 `reference_group.front` 主参考定妆图的内容 sha256。钉死后 `gate --stage image` 的 `check_anchor_fingerprints` 校验磁盘上 front 当前 sha 与登记值一致；锚点被悄改/丢失 → **BLOCK**（锚点一漂，所有引用它的集都继承换脸）。**①a 落档自检自动钉死（默认）**：`image_qc.py <作品根> --mark-finalized CHAR_xx/形态` 在过落档自检时会**自动**把 front 的 sha 写进 `anchor_sha`（等价于顺手 `--pin-anchor`），过自检的脸即刻受指纹保护，不再依赖人手记得单独 pin；front 锚点图缺失则优雅跳过（不阻断落档，回执提示补图后手动 pin）。要保留旧的纯 opt-in 行为加 `--no-auto-pin`。也可独立 `--pin-anchor CHAR_xx/形态`（停用加 `--unpin-anchor`）。有意更新锚点时：重出依赖镜后重新落档（自动重钉）或 `--pin-anchor`。锚点版本可追：`n2d-identity` 的 adapter_matrix 会把全 registry 的锚点指纹（`anchor_fingerprint`）留痕，锚点一改指纹即变、diff 里可见。 |
| `expression_anchors` | **可选·表情库跨集共享锁定**（治「第2集的怒和第5集的怒各画各的」）。一组 `[{emotion, path, self_check_passed?, anchor_sha?}]`——把 `reference_group.expressions` 里的同源情绪定妆升为「逐条可落档+可钉死」的共享锚，让**所有集**同情绪近景都从同一情绪锚 image2image 派生。`gate check_expression_anchors`：登记后该情绪锚必须存在、`self_check_passed≠false`、`anchor_sha`（若钉了）不被悄改，否则 **BLOCK**。**纯 opt-in**。写法：`python3 skills/n2d-image/scripts/image_qc.py <作品根> --finalize-expr CHAR_xx/形态/情绪`（落自检真值 + 自动钉 sha；标脏加 `--unfinalize-expr`）。 |
| `backend_pin` | **可选·一角一后端跨集钉**（治同一角色跨集换出图后端导致的脸漂——不同模型脸的先验不同）。记该角色身份建立/锁定的出图后端（如 `Codex`/`Seedream`）。`gate check_character_backend_pin`：本集项目 `生图AI` 与之不同 → **WARN**（advisory），提示切回原后端或先升原生主体/LoRA 再换。**纯 opt-in**。 |
| `source_asset_pack` / `source_asset_slug` | 可选·角色级；`n2d-asset-market` 导入 fork 时写入：来源资产包路径 / slug（单层溯源，兼容旧导入） |
| `fork_history[]` | 可选·角色级；多级 fork 溯源链（A→B→C 不断链）。每条 `{from_pack, from_slug, from_character_id, forked_at, reason}`——键名以契约 `IDENTITY_FORK_HISTORY_ENTRY_FIELDS` 为准。导入时先继承源角色自带的链，再追加本次条目；只有 `n2d-asset-market` 写它 |

## 3. 状态枚举

推荐状态：

| 状态 | 含义 |
|---|---|
| `unsupported` | 该后端无持久身份能力 |
| `fallback_reference_group` | 使用定妆参考组 + 锚点句兜底 |
| `unregistered` | 后端支持，但本角色尚未注册 |
| `candidate` | 已决定要注册/训练，素材准备中 |
| `registered` | 已拿到后端角色 ID / handle / reference |
| `ready` | LoRA 或后端身份已可用于生产 |
| `not_needed` | 该角色不需要 LoRA 或后端 ID |

`registered/ready` 状态必须同时写实际句柄：`id`、`handle`、`reference` 或 `model_path`。否则等于假登记，gate 会阻断。

后端 mode 必须匹配能力，不能自由写：

| 区域 | 后端 | 允许 mode |
|---|---|---|
| image | `codex/openai` | `reference_group` |
| image | `kling` | `character_id` / `subject_library` / `custom_model` / `element_library` |
| image | `seedream` | `universal_reference` |
| image | `sora` | `character_cameo` |
| video | `dreamina` | `first_last_frame` / `reference_group` |
| video | `kling` | `character_id` |
| video | `seedance` | `face_lock` |
| video | `veo` | `reference_controls` |

## 4. 生成阶段怎么用

### n2d-image

1. 建共享定妆时同步创建/更新 `identity_registry.json`。
2. 跑 `n2d-identity` 生成 adapter matrix；每个含角色分镜的 `资产身份注册层` 必须写具体 `CHAR_xx/形态`，执行端从 matrix/registry 自动取 `reference_group` + `reference_atlas.selection_policy` + `evolution_profile` 当前阶段，而不是临场猜参考图或只靠中文角色名。
3. 读取 `generation_control`：本镜用途命中 `usage` 后得到 `requested_seed`；后端支持 seed 就传参并记 `seed_effective=true`，不支持就记 `seed_effective=false` no-op 降级，不得把该图标成 seed 可复现。
4. 多角色同框时先看 registry 是否有可用多参考/主体库 ID；没有就登记降级：分别出图 + 合成同框，或拆正反打。
5. 当前剧情跨入新境界/成长阶段/年龄阶段时，先在 `evolution_profile.stages[]` 加阶段，再新建对应 form/reference_group/reference_atlas；年龄敏感角色同步填 `age_band` 与 `target_file_prefix`，共享 PNG 用 `定妆_<角色>_<年龄或年龄档>_<形态>*.png`。新 form 的正/侧/背/半身必须以上一阶段身份锚为参考派生，锁 `identity_invariants`，只改 `allowed_evolution_axes`。
6. 核心/长线角色新增、升档或迁移时，创建/更新 `设定库/character_assets/<CHAR_ID>__<slug>/manifest.json`，并在 registry 写 `asset_bundle` 引用；manifest 记录可继承资产和缺口，不复制角色 DNA。
7. `angle_policy.risky` 或动作/表情高危命中时，先查 `reference_atlas`：基础 45°/侧/背/脸部特写必须已经 `ready` 并可直接传入；表情/动作参考只有 `planned` 时记录 `reference_gap`，回退基础视角/脸部特写，必要时改分镜避开极端角度或降级 MCU/OTS。

### n2d-video

1. 生成 `01_clips.md` 前跑 `n2d-identity`，读取 `identity_adapter_matrix.json`。
2. 若视频后端对应角色 `registered/ready`，平台参数里写入角色 ID / Face Lock / reference controls。
3. 若未注册但后端支持：核心/长线角色先给 BLOCK，注册完主体/Character ID 后再付费出图；短线配角仍给计划项或按参考图兜底。高危镜头（极暗、极小、极端角度、多角色接触）应优先注册。
4. 若后端无能力，明确回退到首帧 + 尾帧 + 强 `continuity` 文字。

### n2d-review

1. gate 检查 registry：字段、状态枚举、后端 mode、ready 句柄、LoRA ready 三件套。
2. 审片跑 `n2d-identity` 生成跨集漂移报表；有 `first_bad_episode` 时，修法回到该集对应镜头或共享定妆adapter 注册层。
3. 报表中的角色/集/镜头可交给 `n2d-batch` 生成定向 rerun，不整集重来。

## 5. gate 规则

`n2d-review/scripts/gate.py` 会检查：

- registry 是否存在、kind 是否正确、characters 是否非空。
- 每个角色/形态是否有 `reference_group`、`identity_adapters`、`angle_policy`、`drift_forbidden`。
- 若 form 登记了 `generation_control`，检查 `seed_strategy/seed_pool/usage/backend_support/fallback_policy/record_required` 是否完整；旧项目缺该字段先 warn，不直接 block。一旦 image 生成事件写了 `requested_seed`，必须同时写 `seed_strategy/seed_support/seed_effective`；`seed_effective=true` 时还要写 `effective_seed`。
- `reference_group` 的五个核心路径是否齐：front / side / back / outfit / turnaround。
- `reference_atlas.base_views` 的基础视角是否齐且 `ready`：front / three_quarter / side / back / half_body 或 full_body；planned 只能当待补计划，不能放行。基础脸锚 `face_anchor_refs` 或 `expression_refs` 也必须存在。
- `reference_group.expressions` 是否是同角色/同形态参考，防止 `CHAR_01` 下误挂 `CHAR_03` 的脸部特写；每条是否有 `emotion`/`path`，路径是否真实存在。**warn（不硬阻断）**：被分镜标为近景高频/情绪戏的核心角缺 `expressions`（或仅中性一档）——提示「大表情近景须降级 MCU 或补表情定妆」，让 `n2d-video` 风险表据此把该角大表情镜标高危。
- 含角色分镜 prompt 是否写了具体 `CHAR_xx/形态`，否则无法自动从 registry 取定妆组。
- 正反打/反应/表情近景 prompt 是否写 `近景/反打身份锁定`，并引用脸部特写/表情参考或明确锁脸型、五官比例、发型发髻、标志配饰。
- `image/video` 每个 adapter 是否有 `mode/status`。
- `lora.status=ready` 是否写了 `base_model`、`model_path` 和 `trigger`。
- adapter `status` 是否使用枚举，`mode` 是否匹配后端能力。
- `registered/ready` 的后端身份是否写了真实 ID / handle / reference / model_path。
- 视频及之后阶段会检查核心参考图路径是否真实存在。

**跨集脸漂专项闸（2026-06，弱后端结构根因）**：

- **每镜 i2i 强制**（`生图AI` 为无持久主体锁后端 Codex/OpenAI/Dreamina/Nano 时）：**每个**角色镜（含首帧，不止尾帧）prompt 必须声明从共享定妆 `image2image/多图参考派生`，否则纯文生图=跨集换演员 → **BLOCK**。原生主体锁后端豁免。
- **锚点指纹钉死**（`anchor_sha`，落档自检默认自动钉死，`--no-auto-pin` 可退回 opt-in）：front 主参考被悄改/丢失 → **BLOCK**；锚点版本由 adapter_matrix 的 `anchor_fingerprint` 留痕可追。
- **表情库跨集共享锁定**（`expression_anchors`，opt-in）：情绪锚缺失/未过自检/被悄改 → **BLOCK**（`check_expression_anchors`）。
- **表情库覆盖闸**（把表情锚提到与脸锚同级，付费出视频前强制回连）：本集存在跨情绪大表情近景镜（`continuity.expression_span=大` + 近景/特写/反打）且引用了**核心长线角色**，而该角色所有 form 的 `expression_anchors` 皆空（没建表情库）→ **BLOCK**（`check_core_expression_anchor_coverage`，video_preflight/video 阶段）。与脸锚的 `check_core_anchor_pinning`（WARN 提醒「该钉没钉」）同款双层结构，但在「大表情近景 + 核心角色 + 即将花钱」的确定跨集情绪漂移场景升 BLOCK。**纯 opt-in**：本集无 `expression_span=大` 镜则跳过；非核心/单元角色不前置 BLOCK。
- **一角一后端跨集钉**（`backend_pin`，opt-in）：本集 `生图AI` 与角色锁定后端不同 → **WARN**。
- **跨集 embedding 漂移**：`n2d-identity` 逐角色按集质心 vs 锚点接近度，揪「每集各自过 floor 但整体逐集偏离」的系统性漂移，写入 `identity_drift_report`，并喂 LoRA 升档建议（含弱后端长线角色**主动**升档）。

> 原则：后端不支持可以 fallback，但必须登记；支持却未注册不是立即阻断所有镜头，但 registry 必须让产线知道“这是未注册状态”，后续可按高危镜头/核心角色优先注册。

## 6. 和 LoRA 的关系

LoRA 仍是最重的一档，不默认启用。registry 只负责把 LoRA 的状态结构化：

- `not_needed`：短线角色或参考组已够稳。
- `candidate`：核心长线角色，参考图压不住，准备训练。
- `training`：训练中。
- `ready`：已有可用 LoRA，必须填 `model_path`、`trigger`、`base_model`，并建议带 `validation_report`、`train_job`、`model_hash`。

LoRA 具体训练执行走 `skills/n2d-lora/scripts/lora.py`；训练策略与交互判断仍读 `references/lora_consistency.md`。

## 7. 多角色同框绑定规则（崩脸最高发场景）

多数后端的单图主体锁（Face Lock / Character ID）只支持 1 个主体，多参考后端也有总图数上限（如 Seedream ≤14 图）。同框 ≥2 个注册角色时按以下**确定性规则**分配，不靠临场发挥：

1. **主体名额给最高优先角色**：按 registry 角色的 `priority` 字段（缺省时按本集出场行数多者优先，再按 registry 顺序）排序；Face Lock / Character ID / LoRA 名额只给第 1 名。镜头 prompt 必须显式标 primary（写法：`CHAR_01*`，星号=本镜主体锁持有者）。
2. **其余角色降级为参考图组**：每人最多 2 张（正面 + 当前形态服装），并在 prompt 用各自 `anchor_phrase` 锁特征词。
3. **参考图总配额裁剪**：超后端上限时，primary 角色参考组优先满额，其余按优先级均分；裁剪顺序 turnaround → 表情图 → 侧面，**正面与当前服装图永不裁**。**例外**：本镜 primary 角色且 `表情幅度=大`（要做首尾双帧的近景大表情镜）时，**该角色的起/止表情图视同正面图、不裁**——表情图正是这镜锁脸的关键料，裁了等于丢掉双帧引导。
4. **三人以上群像**：只锁前 2 优先级角色，其余靠 global_style + 锚点句兜底；该镜在 storyboard 标 `crowd: true`，QA（face_consistency / n2d-score）对 crowd 镜降低同人脸预期，避免把背景群演误报成崩脸。
5. **prompt 槽位约定**：同框镜必须新增 `多人同框身份槽位`，把每个主体绑定到确定画面槽位（`LEFT_SLOT` / `RIGHT_SLOT` / `FOREGROUND_SLOT` / `BACKGROUND_SLOT` / `EXTRA_SLOT_N`）。每个槽位至少写：`CHAR_xx/形态`、画面位置、前后景/遮挡、视线方向、face_priority、该角色自己的 face/expression/reference_group；不得用“参考图①”泛化锁所有人。
6. **执行策略约定**：无持久角色 ID 后端（Codex/OpenAI/Dreamina/Nano/Gemini）同框镜必须写 `多人同框执行策略=split_composite_required` 或拆成正反打；持久主体后端写 `native_subject_slots` 并逐槽位引用主体/角色 ID。该策略是本镜硬执行，不是条件式兜底。
7. **gate 约定**：同框镜 prompt 引用 >1 个 `CHAR_` 而没有星标 primary → warn（绑定歧义，后端会随机挑主体）；无持久主体后端写了分层/合成但缺 `多人同框身份槽位` → block（合成阶段仍会串脸或无法追责）。

> 设计依据：同框崩脸的根因多半是"两个角色都想锁、后端只锁得住一个、锁了谁不确定"。把"锁谁"变成确定性规则 + 把"没说锁谁"变成机检 warn，崩脸从随机事件变成可追责事件。
