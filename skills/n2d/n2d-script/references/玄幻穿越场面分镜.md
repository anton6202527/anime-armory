# 玄幻 / 穿越场面分镜

本文件补强仙侠之外的玄幻、穿越、系统流、学院流、血脉/武魂觉醒、魔兽契约、秘境试炼等高频场面。它们的共性不是“动作快”，而是**信息密度高、视觉规则固定、跨镜一致性容易崩**：系统面板乱码、穿越落点换脸换衣、测灵结果不可读、契约兽每镜不同、阵法几何乱画、丹炉和成品漂移、元神像另一个人。

原则：风格可以是国风玄幻、暗黑魔法、二次元、写实国漫，但模板字段不省。视觉风格只影响光色、材质、镜头质感；不改变场面契约。

---

## 1. 穿越 / 传送 / 秘境入口（`realm_portal`）

**使用场景**：现代人穿到异界、魂穿/身穿、时空裂缝、传送门、传送阵、秘境入口、遗迹门、跨界落点。

**拆法**：
- 入口建立：锁裂缝/传送阵/秘境门形态、颜色、符纹和空间位置。
- 进入/卷入：人物只做进入、跌入、被吸入或落地一个动作。
- 目的地显景：给异界/秘境/宗门/遗迹的环境锚，观众知道“到了哪里”。

**额外必填字段**：`portal_lock`、`source_world_anchor`、`destination_anchor`、`entry_exit_path`、`body_continuity_lock`、`transition_vfx`、`readability_beats`、`degrade_plan`

**保真实现**：穿越前后不要一镜换脸换衣。先锁入口，进入动作短，落地后单独显景；换装、身份转变、系统绑定放后续镜头。

---

## 2. 系统面板 / 任务奖励 / 属性跳变（`system_panel`）

**使用场景**：系统绑定、属性面板、任务发布、签到、抽奖、奖励、经验条、升级提示。

**硬规则**：
- 套 `system_panel` 母题模板，不新增一套面板模板。
- AI 只画空光幕底框、符纹、发光底板；数值、文字、等级、任务内容由 n2d-compose overlay。
- 面板形态、颜色、边框、符纹按 `VFX_系统面板` 入库跨集复用；只用 `panel_tier` 表现成长。

**常见拆法**：系统音提示 → 空面板浮现 → overlay 文字/数值跳变 → 主角反应。

---

## 3. 测灵 / 天赋测试 / 血脉觉醒（`talent_test`）

**使用场景**：测灵石、灵根测试、资质测试、学院入学测试、血脉觉醒、武魂觉醒、天赋等级暴露。

**拆法**：
- 测试道具：测灵石/水晶柱/觉醒台先锁形态和测量规则。
- 结果显现：颜色、刻度、光柱高度、符号阶段只按一套规则变化。
- 反应链：众人震惊、长老转身、主角身份/天赋被揭示。

**额外必填字段**：`test_artifact_lock`、`measurement_rule`、`result_stage`、`overlay_policy`、`crowd_reaction_chain`、`vfx_asset_lock`、`readability_beats`

**保真实现**：天赋名、等级、数值、系统提示都走 overlay。若要“全场震惊”，接 `reveal_reaction_chain` 或 `public_confrontation`，不要在测试道具镜里塞完整群戏。

---

## 4. 契约召唤 / 魔兽认主（`contract_summon`）

**使用场景**：灵兽契约、魔兽契约、血契、认主、召唤阵、法灵显形、契约印记落定。

**拆法**：
- 仪式锚：血滴/手印/召唤阵/契约阵先建立。
- 召唤显形：召唤兽或法灵出现，给尺度、剪影和特征。
- 归属落定：契约印记、眼神呼应、低头臣服、主仆/伙伴关系成立。

**额外必填字段**：`summon_entity_lock`、`contract_mark`、`ritual_anchor`、`summon_path`、`scale_relationship`、`ownership_transition`、`readability_beats`、`degrade_plan`

**保真实现**：召唤兽必须进 `BEAST/MOUNT` 或 `PROP` 资产库。契约成立后若要骑乘，下一镜切 `mount_ride`；不要在契约镜里直接“召唤并骑着狂奔”。

---

## 5. 炼丹 / 炼器 / 铸剑（`alchemy_forging`）

**使用场景**：炼丹炉、开炉成丹、炼器、铸剑、法器淬炼、材料入炉、火候控制、失败炸炉。

**拆法**：
- 建立炉体：丹炉/锻炉/器台、材料、火焰颜色和工具手势。
- 过程蒙太奇：材料入炉、火候变化、灵纹流转，只做 2-3 个可读阶段。
- 成品落点：开炉、成丹、出剑、器成或失败爆烟，产品停半拍。

**额外必填字段**：`furnace_or_forge_lock`、`material_sequence`、`flame_control`、`tool_hand_pose`、`product_lock`、`success_or_failure_beat`、`readability_beats`

**保真实现**：丹炉、火焰、主材料、成品进资产库。成品不能让模型临场发明；开炉前憋一拍，开炉后产品可读。

---

## 6. 阵法 / 结界 / 封印 / 仪式（`array_ritual`）

**使用场景**：阵法起势、传送阵、护宗大阵、结界、封印、祭坛仪式、破阵、阵眼点亮。

**拆法**：
- 几何锚：先出俯视阵图或固定角度阵图，锁几何、阵眼和符文层。
- 启动顺序：阵眼/光轨按顺序点亮，不自由变图案。
- 用途释放：传送、封印、困敌、防护或攻击，只给一个结果。

**额外必填字段**：`array_geometry_lock`、`activation_steps`、`symbol_layer_policy`、`caster_positions`、`energy_flow`、`purpose_lock`、`vfx_asset_lock`、`readability_beats`

**保真实现**：几何/符文优先用定妆图、overlay 或局部阵眼拆镜，不让视频模型自由画完整对称符文。

---

## 7. 神魂 / 元神 / 夺舍（`soul_manifestation`）

**使用场景**：神识探查、元神出窍、魂魄显形、识海、夺舍、搜魂、神魂攻击。

**拆法**：
- 肉身锚：肉身姿态、脸、服装、环境先锁。
- 元神显形：元神由肉身定妆派生，同脸同发型，用透明度和光边表现“魂”。
- 探查/相争/成败：只做一次探查波纹、夺舍成败或神魂命中。

**额外必填字段**：`body_soul_identity_lock`、`soul_form_lock`、`opacity_curve`、`emergence_path`、`host_body_lock`、`conflict_or_probe_target`、`readability_beats`、`degrade_plan`

**保真实现**：“二我同框”必须是同一个人：元神用肉身参考派生，不另画一张新脸。夺舍不要一镜两个魂自由缠斗，拆成扑入、拉锯、成败。

## 8. 宗门大比 / 学院擂台 / 拍卖会

这些是玄幻高频剧情场，不必新增模板，但必须选对现有模板：

| 场面 | 首选模板 | 备注 |
|---|---|---|
| 擂台比试 / 学院考核对打 | `fight_exchange` | 命中帧、受击、裁判/观众反应拆开 |
| 赛前叫阵 / 当众压迫 | `public_confrontation` | 锁赌注、身份、围观反应和权力翻转 |
| 宝物拍卖 / 抬价 / 亮宝 | `public_confrontation` + `reveal_reaction_chain` | 宝物进 PROP，价格文字走 overlay |
| 秘境试炼开始 | `realm_portal` + `large_establishing` | 先入口，后秘境全景，再任务/危险 |
| 血脉觉醒被发现 | `talent_test` + `reveal_reaction_chain` | 测试结果可读后再给众人反应 |
