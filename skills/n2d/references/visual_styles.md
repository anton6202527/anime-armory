# 基础视觉风格（选择点 `基础视觉风格`）

本文件只定义可选风格和派生规则。用户的实际选择写入 `<作品根>/_设置.md`，不写进 skill 源码。新项目在写 `设定库/global_style.md` 前先定本项；已有项目按 `_设置.md` / `global_style.md` 沉默沿用。脚本侧预设落在 `skills/n2d/_lib/n2d_visual_styles.py`，改菜单或预设时需要同步本页与脚本。

## 使用规则

1. 读取 `基础视觉风格`：`_设置.md` → 全局默认 → 首次给菜单让用户选一次。**首跑的「预选默认」是题材感知的**：`split_novel.py` 跑 `recommend_style()`（`_lib/n2d_visual_styles.py`），按 `detect_genre(正文)` + 书名/`题材` 自由文本打分，挑一个最贴本剧的风格当预选，并把依据写进 `global_style.md` 的「风格推荐依据」区块。这只是预选、不是铁律——菜单仍展示、用户一句话即可覆盖；`_设置.md`/全局已有「非裸默认」的明确选择时，推荐不覆盖它（只作信息展示）。
2. 将选择写进 `设定库/global_style.md` 的「基础视觉风格」和「基础视觉风格契约（style_contract 源头）」。
3. 阶段2 分镜时在 `storyboard.json` 写 `style_contract`，字段固定为：`风格名 / 视觉基调 / 镜头与构图 / 光色策略 / 运动边界 / 风格禁忌`。
4. `n2d-image` 和 `n2d-video` 只继承并细化 `style_contract`，不得把某一种风格（如写实电影感）重新追加成硬规则。
5. 旧项目已有 `cinematic_contract` /「本集真实电影感契约」时可以继续通过 gate；下次修改故事板或总览时迁到 `style_contract` /「本集基础视觉风格契约」。
6. 若用户选择 `参考图片/视频自动识别`，这是**临时入口，不是最终风格值**：先让用户上传参考图或视频；图片直接观察，视频先抽 6-12 张关键帧（开场/人物近景/动作/环境/光色变化都要覆盖），再判断画风、题材气质、镜头节奏、角色审美、色彩光影和可制作难度。随后把结果归一成一个已有预设，或写成 `自定义（<一句话风格名>）` 并补齐 `style_contract` 六字段；不要把 `参考图片/视频自动识别` 原样写入 `_设置.md` 或 `storyboard.json.style_contract.风格名`。
