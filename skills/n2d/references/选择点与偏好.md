> 本线（n2d）私有的偏好/选择点约定。原 `skills/n2d/references/选择点与偏好.md` 已按线拆分，本线自带这一份，

# 偏好约定（所有自定义 skill 共用 · 通用机制）

> 这是**共享代码侧**的通用约定，不含任何具体用户的选择。
> 用户的实际选择是**私有的**，落在用户自己的空间，绝不写进 skill 源码。
> 任何 skill 涉及「让用户选」的地方，都按本约定读写，不要把某个平台/后端写死成唯一路径。

## 三句话原则
1. **skill 通用**：不写死平台/后端/分辨率；这些是「选择点」，由用户私有文件决定。
2. **选择私有**：用户的选择存在用户自己的空间（见下），不外发、不进共享 skill。
3. **持续记录 · 最新为准**：选择点首次遇到 → 问一次 → 写入 `_设置.md` → 同项目之后**沉默沿用**；用户随时可改（说一声或直接改文件）。**用户在任何一句输入里显式点名某选择点的值（哪怕之前已设过、哪怕在流程中途、哪怕和当前任务无关）→ 立刻以新值覆盖 `_设置.md` 对应行 + 追加一条 `## 记录`，最新选择永远优先于旧值 / 全局默认 / 缺省。** 听到即落档，不要"等下次用到该选择点再写"。

## 候选项刷新与用户输入口

选择点目录里的可选值只是**候选快照**，不是永久真值，也不是对用户输入的封死枚举。

- **可刷新来源**：候选项可来自项目 references、已有生产数据/投放回灌、模型/平台官方文档、实时搜索、以及 AI 代理的专业知识库。模型、平台、价格、规格、法规、榜单、API 能力等高变化信息，在正式花钱/不可逆/合规相关步骤前必须按需要核验；刷新时写清核验日期和来源，不能联网或不能确认时明确标注“未核验”。
- **用户输入口**：每个选择点都保留 `自定义` / `manual` / 直接手输值的入口。`skills/n2d/_lib/settings.py` 的 schema 只用于安全校验和常见别名归一，不得把用户的合理新选择挡在 skill 外；确属实验值时用 `python3 skills/n2d-settings/scripts/settings_cli.py set <作品根> <选择点> <值> --force` 落档，并在 `## 记录` 说明原因。
- **菜单不等于执行逻辑**：菜单文案服务于人类决策；脚本执行时必须先把值归一成能力、参数、后端入口和回退/保真实现策略。不要在任一 stage 里写 `if 菜单文案 then 唯一路径` 的硬绑定。
- **机检与刷新工具**：易变候选清单都在 `skills/n2d/_lib/freshness.py:CANDIDATE_SOURCES` 登记并带 `采集日期：YYYY-MM-DD` 戳记；`python3 skills/n2d/_lib/freshness.py` 机检谁过期；`本线 `_lib/refresh.py`` skill 跑「搜索核验 → 改候选 → bump 日期 + 落 provenance」的刷新流程。新增易变清单 → 登记 + 加戳，否则机检看不到。

## 适配层原则

不同选择带来的差异由适配层消化，产线正文只消费统一契约。

- **模型指代铁律（设计宪法 C5）**：凡指名「由什么**生成**这张图/这段视频」，指代必须落到**具体模型名+版本**（GPT Image 2 / Seedream 4.5 / Seedance 2.0 / Veo 3.1），**不写 agent/渠道/厂商/壳**（Codex / 即梦 / 渠道商 / 某后端）。模型(`生图模型`/`生视频模型`)与渠道(`生图AI`即渠道/`生视频渠道`)**两个字段分列**；route/记账/per-run 证据以**模型为主键、渠道为副**。模型名仍带采集日期、可刷新（C2），但不准退化成渠道壳。
- **剧情/质量先行（设计宪法 C6）**：分镜要不要多人同框、近景给多大表情、镜头多长，由**剧情与质量**决定，**不为迁就后端短板而下调/回避创作决策**。后端只决定**实现路径与补偿**（换更强模型/分别出图+分区合成/首尾双帧/拆段接力/人审），不决定「镜头能不能存在」。质量硬闸拦的是「没做对」，不是「难」。
- **标准先行**：skill 标准只写“必须达到什么”，不写“某后端怎么做”。选择点不得降低标准；只能改变实现路径、成本、速度和需要的弥补措施。
- **归一化**：把用户选择映射为 canonical key、能力标签（如多参考/主体库/原生音画/最大时长/分辨率上限）、实际 CLI/API/网页入口、参数包、fallback/degrade plan、合规 gate 和输出 schema。
- **专门适配**：用户选定某模型/平台/风格/规格后，下游 prompt、分镜约束、镜头时长、首尾帧/参考图策略、字幕/交付规格等都应按适配结果生成，不只是在 `_设置.md` 里记一个名字。
- **生图后端适配**：生图统一标准在 `skills/n2d/_lib/image_backend_standards.py`；生成轴的真值是 `生图模型`（默认 GPT Image 2·见 C5），访问入口是 `生图AI`(渠道)，两者统一走 `skills/n2d/_lib/image_backend_adapter.py`（adapter 每条登记 `model`+`channel` 两字段，记账/证据以模型为主键）。每次正式付费出图前先跑 `python3 skills/n2d/_lib/image_backend_adapter.py scan --json`：若扫描出多个可自动落 PNG 的官方/已登录后端，必须让用户选一个并写回 `_设置.md`；若一个都没有，停止并提示“当前无可用生图后端，请准备好可以生图的生图后端”；`needs_confirmation_backends` 只列为待人工确认，不当作可用。选定后再查官方文档/实时资料与本机 CLI/API help，把生成、编辑、多参考预算、主体库/Character ID、掩码、输出 schema、额度/价格等能力写入 per-run 证据：`python3 skills/n2d/_lib/image_backend_adapter.py record-refresh <作品根> --backend "<生图AI>" --source "<官方文档或CLI/API证据>" --source-url "<链接或留空>" --evidence-kind official_docs --note "<本次能力结论>"`。`image_preflight` 只认当天结构化能力证据；缺 `capability_assertions` 或每项能力缺 source/source-url/evidence-kind/observed_text 就停，不用旧菜单猜 API。后端原生能力不足时，适配层自动输出标准补偿：参考组/脸嵌入、主体槽位、分层合成、文字 overlay、整图重抽、full QC、人审队列等。
- **生视频后端适配**：视频静态能力档在 `skills/n2d/_lib/n2d_platform_profiles.py`，执行适配层在 `skills/n2d/_lib/video_backend_adapter.py`。出视频前由 `n2d-model-router` 写 `video_model_routes.json`，再把 route 中实际会用的 primary/fallback 逐个查官方文档、本机 CLI/API help 或最小 smoke test，记录 per-run 证据：`python3 skills/n2d/_lib/video_backend_adapter.py record-refresh <作品根> --backend "<后端>" --channel "<生视频渠道>" --source "<官方文档或CLI/API证据>" --source-url "<链接或留空>" --evidence-kind official_docs --note "<本次能力结论>"`。`video` gate 只认当天结构化证据；缺证据、缺 `capability_assertions` 或每项能力缺 source/source-url/evidence-kind/observed_text 就停，不用旧模型矩阵猜单 Clip 上限、首尾/多帧消费、原生音画/口型、身份绑定或输出 schema。中段锚帧执行也读 `anchor_consumption_plan`：`native_multiframe` 才能一次消费首/中/尾，`split_relay` 要拆段，`reference_only_qc` 不得假装时间轴锚。
- **透明失败**：适配层缺能力、缺凭证、缺官方入口或候选项已过期时，停下列明缺口和可选替代；不要静默改用另一个后端，也不要把旧候选清单当作当前事实。
- **解耦边界**：候选项目录、用户私有选择、执行适配、质量/合规闸门分开维护。新增模型/平台优先补适配表或 capability profile；只有真正影响用户决策的项目才进入本文件的选择点目录。

## AI 代理交互约定 (Interactive Flow)

**原则：把枯燥的脚本命令藏在背后，让用户只做决策。**

当一个工作流包含**「机器负责结构计算（如拆分 Clip），紧接着需要大模型负责语义理解（如写 Prompt）」**的组合操作时，**绝对不要**把两段割裂的 CLI 脚本硬塞给用户让他们自己去敲。

- **正确的做法**：在第一个脚本跑完后，建立明确的**【AI 代理交互节点】**。
- **用户体验**：AI 代理应主动弹出高亮提示，或者用自然语言询问：“已完成基础切分。是否需要我启动 XXX 引擎为你自动补全提示词？”
- **后台执行**：用户回答“是”之后，AI 代理在后台默默**跑脚本 → 读取提示词 → 调用自身的 LLM 生成 JSON 结果 → 注入项目**，一气呵成。使用户感受到的是一个连贯、智能的“创作助理”，而不是一本枯燥的代码说明书。

## 两层私有存储

| 层 | 路径 | 谁写 | 作用 |
|---|---|---|---|
| **作品级** | `<作品根>/_设置.md` | skill 自动读写，用户可手改 | 本作品/曲/小说的实际选择（**权威**，覆盖全局） |
| **全局默认** | 私有全局默认 `创作偏好-默认.md`（仓库根或 `.agents/` / `.codex/` 等用户空间） | 用户维护 | 跨项目的个人默认（如「生图后端 / 视频后端 / 720p / CosyVoice / Suno」），开新项目时**预填** `_设置.md` |

- `<作品根>`：`创作区/制漫剧/<剧名>/`，与 `_进度.md` 同级。
- 全局默认使用工具中立路径：优先读仓库根 `创作偏好-默认.md`，再读 `.agents/创作偏好-默认.md`、`.codex/创作偏好-默认.md`；旧项目的 `.claude/创作偏好-默认.md` 仅作兼容读取，不作为新的共享入口。skill 文本引用「全局默认偏好文件」即指这些私有候选文件。

## 解析顺序（每次要用某选择点时）
0. **（最高优先）用户本轮输入显式指定了该选择点** → 立刻按新值覆盖 `_设置.md` + 记一行，**用新值**，跳过下面的读取。这条对**所有**选择点恒成立，且不限于"正要用到"时——只要用户一句话点名某选择，当场落档（见三句话原则 #3）。
1. 读 `<作品根>/_设置.md` 里该选择点 → 有就**直接用，不问**。
2. 没有 → 读全局默认 `创作偏好-默认.md` → 有就用其值**预填**，并**首次告知一句**（"默认 X，要改说一声"），随即写进 `_设置.md`。
3. 全局也没有 → **问用户一次**，写进 `_设置.md`。
4. 之后同项目同选择点：**沉默沿用**，不再问。
5. 无作品根的独立调用：能定位项目就读其 `_设置.md`，否则用全局默认 / 现问，不强行落文件。

> 例外：**合规/不可逆/花钱多**的点（真人嗓授权、版权来源、删除回流）即便记录过也要确认——安全 > 省事。

## 选择点目录（各家族暴露给用户的选择 + 缺省回退）

> 缺省值仅作**全局默认的初始建议**；真正生效的是 `_设置.md` 里的值。关键首跑选择点（如 `制作模式`、`基础视觉风格`）必须在项目 `_设置.md` 里带来源留痕：`# source=explicit_user` 或 `# source=cli` 才算已显式确认；`source=global_default` 或旧项目无来源只作为预选，不能跳过首次确认。


### 制漫剧 n2d 系列
- `制作模式`: 配音先行 \| 原生音画 \| 先出视频后配音　（默认 **先出视频后配音**（2026-07-02 起）：后配音线——先用估算/占位时长推进分镜、无声 Image2Video、出图出视频，默认到 `视频` 完成即收尾；若用户启用 `合成阶段`，真实对白由 CosyVoice / Fish Speech / MiniMax Speech / 其他 TTS 在出视频后补，并在 compose 前拟合到已锁镜头。优点是先看画面、推进快，风险是合成尾段配音时长溢出时需要重定时或重出部分镜头。`配音先行`=低返工/声音一致性优先：先真实 TTS 锁定句长，再做无声视频，后期 FFmpeg 分层混音。`原生音画`=快速预览或特殊后端：说话镜一次出台词+口型+环境声，最快看到同步音画，但少了逐句音色控制，仿真人音色仍需授权。三种流程图 + 完整理由 + 闸门放行方式见 **n2d SKILL「制作模式」节**。用户说“后配音”时归一为 `先出视频后配音`。**⚠️ 例外——首跑必给菜单**：此点是影响全程的出片顺序决策，**不**走"全局默认静默预填"那条；**新作品首次拆集时必须把三模式 + 一句话原因念给用户选一次**（即便全局默认是先出视频后配音），用户选后落 `_设置.md`、之后沉默沿用、随时可改。菜单原话见 n2d SKILL「制作模式 · 首跑选择」段）
- `合成阶段`: 跳过 \| 启用　（默认 **跳过**：`视频` 列完成即默认主流程完成，不自动进入 `n2d-compose` / `n2d-review`。用户需要母带、BGM、烧字幕、屏幕文案 overlay、系统面板数值层、交付矩阵、release manifest 或发布证据包时，设为 `启用`；直接调用 `n2d-compose` 也视为用户选择本集进入合成尾段。旧项目若 `成片/验收` 已开始，路由会保留该尾段，不因默认值跳过已做工作。）
- `项目规模`: 短 demo \| 单集 \| 多集长线 \| 长篇量产 \| 自定义　（**首跑必问**，影响一致性投入而不改变剧情。`短 demo/单集` 可从 GPT Image 2 经 Codex/OpenAI 的参考派生起步；`多集长线/长篇量产` 必须在首跑就提醒主体库/Face Lock/face_embedding/LoRA 的一致性税，核心/常驻角色默认推荐可注册主体的官方后端或等效身份锁。此选择点只决定默认后端建议和 gate 提前预警，不允许静默替用户换后端；正式付费前仍由 `image_preflight` 和 per-run evidence 决定。）
- `题材`: 系统流 \| 穿越 \| 修仙 \| 都市 \| 宫斗 \| 赘婿 \| 战神 \| 自定义　（**弱选择点·检测预填可覆盖**——非铁律。n2d-script 在拆集/分镜阶段跑 `motif_detector.py`，按 `n2d_const.GENRE_KEYWORDS` 自动识别题材并**预填建议值**，不静默生效：识别到后给"我判定为 X 题材、发现 N 处母题桥段（系统面板出现/升级…），要启用母题增强吗"的菜单一次，用户确认/改写后落 `_设置.md`，同项目沉默沿用。题材本身不烧钱、不必每次重确认；但它驱动的母题增强若注入出图/出视频，那一步仍走 `生成粒度` 每次确认。题材决定哪些复现桥段套用母题模板，见 `n2d-script/references/题材母题框架.md`）
