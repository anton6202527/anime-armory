# 模型矩阵 — 各轴 SOTA vs n2d 默认 vs 升级触发（防过期快照）

**这是一张会过期的快照表**。它的唯一作用：给"该不该换模型/后端"一个可对照的基准，避免各 `platforms.md / backends.md` 里散落的版本名悄悄腐烂。

铁律（与 `n2d-review` 防过期铁律一致）：
- **正文写能力，不绑版本号**——讲能力/取舍的散文不钉版本；具体版本名只活在本表的"SOTA 快照"列 + 各档案里，且**都带采集日期**。
- **但指代生成者必须落到具体模型（设计宪法 C5）**——「由什么**生成**这张图/这段视频」的指代，必须是**具体模型名**（GPT Image / GPT Image 2 归一名 / Seedance 2.0 / Veo 3.1），**不得写 agent/渠道/厂商/壳**（Codex / 即梦 / 渠道商 / 某后端）。这与上一条不冲突：散文写能力可以不钉版本，但凡**指名生成者**必到模型；模型名仍带采集日期、可刷新（C2）。渠道/CLI/API 只作访问入口单独记。
- 本表由 `n2d-review` 模式②（流程自审）**每次检查**：默认 report-only 只给刷新建议 / diff 草案；用户确认“刷新矩阵/落地本轮自审”后，才更新快照、改采集日期、调升级触发。落地任何升级 → 改对应档案 + 同步 `skills/README.md`。
- 读到本表先看顶部日期；过了几个月就当它**可能已过时**，以一次新的流程自审为准。

> **采集日期：2026-08-26**　（本轮实时核验：Seedance 2.5 官方 30s/延展/多模态参考/时间戳编辑与 API 待开放边界；Gemini Omni Flash 当前 model id；GPT Image 2 alias/snapshot；CosyVoice 3、Fish Audio S2、IndexTTS-2.5）
>
> **执行口径**：本表只是带日期的候选快照，不是永久真理。任何 2026 模型/后端能力进入付费生产、批量放量或写入 production event 前，仍必须以官方文档、CLI/API help、最小 smoke 和本次 `--exact-model-id` / 等价 model id 证据逐项落档；证据不足只能写“当前未证实”，不得把候选快照当放行依据。

> **一致性「机检」后端（与生图后端正交·2026-06-22 落地选择点 `脸一致性机检后端`）**：崩脸机检的人脸相似度后端默认 **arcface**(insightface buffalo_l)，但 ArcFace 按真人脸标定，**风格化/漫剧脸 TPR 系统性掉到 ~0.76**（StyleID 论文 arXiv:2604.21689·2026-04；裸 CLIP 更差 0.17–0.25）。当 `基础视觉风格` 命中二次元/国漫/国风/漫剧/韩漫/日漫/厚涂/水墨/Q版/美漫/动态漫画/低多边形/纸片定格/插画/动漫时，doctor 与 `image_preflight` 会主动提示项目级切 `脸一致性机检后端: styleid` 并配置 `N2D_STYLEID_MODEL`（CLIP-L+StyleID LoRA 权重）；缺权重自动回退 arcface 标 `arcface_fallback`，绝不用裸 CLIP，且 `character_consistency_kpi` 标为降级档。StyleID 就绪后需重标定 `N2D_CONSISTENCY_RELEASE_LINE`。同轴新增 **fidelity-gate**（崩 canonical 的镜不进一致性均值·EntityBench 2026）+ **报告型一致性 KPI**（`n2d-score` 的 `character_consistency_kpi`·对标 EntityBench/MSVBench）。详见 `n2d-review`「角色 DNA 用图判」+ 选择点 `脸一致性机检后端`。**KPI 基准补登（2026-06-22）**：风格化脸可投放线再标定除 EntityBench/MSVBench 外另参 **Face Consistency Benchmark for GenAI Video**（arXiv 2505.11425·专测 GenAI 视频人脸一致）；**剧级/长视频叙事一致性**参 **NarrLV**（Temporal Narrative Atom）、**EntityBench**（per-shot entity schedule）与 **DirectorBench**（长视频多代理诊断）——对应 n2d 跨集 P0/P1 + 伏笔回收(SP1) + 逐镜实体排程叙事连续性轴。均 report-only 标定参考，不改扣分口径。**已接线（2026-06-24）**：`n2d-score` 的 **`narrative_continuity_kpi`**（`scripts/narrative_kpi.py`）把这条轴落成报告型 KPI——聚合 伏笔已回收率 + 伏笔已规划率 + 冷开场链(P2) + 反套路(跨集同质化) + 情绪起伏 + 叙事原子密度 + 实体排程覆盖率，按 `demo/standard/production/overseas` profile 调整权重和参考线（可用 `N2D_NARRATIVE_RELEASE_LINE` 覆盖），与 `character_consistency_kpi`(角色) 正交、同样不参与扣分。

## 横切：音画联合生成趋势（可控性）

市场正走向**原生音画联合生成**（Veo 3.1 48kHz 对白、Seedance 2.0 原生音视频、Kling Omni 原生口型），"一次出音效/口型/音乐/画面同步"。

n2d 默认 `混合自动路由`：先建立声音选角和无 WAV 时间基准，再逐镜选择表演音轨驱动、neutral-mouth base plate 后置口型、旁白/口外音后配、动作/空镜/蒙太奇画面先行或已核验 native AV。最终声音在音色定妆后批量生成；后配镜在合成前强制生成带输入/输出哈希的 voice-fit 报告。仿真人音色仍需 compliance 授权。项目级 `配音先行` / `原生音画` / `先出视频后配音` 仅作显式兼容模式。`reference_to_video` 是单独通道：PixVerse C1 已按 2026-07-11 官方资料登记为能力候选，但 adapter 未接通前只允许人工/job package，不进入自动路由。

## 怎么用这张表
1. 起新项目 / 接新模型 / 准备升级前，先读这张表对照当前默认。
2. 决定升级 → 改对应 `references/{platforms,backends}.md` 档案（写能力 + 版本快照 + 日期），并**同步 `skills/README.md`**。
3. 跑 `n2d-review` 流程自审时刷新本表（更新快照列 + 顶部日期 + 升级触发），把"市场又变了"沉淀回来。
4. 路由优先级不靠新闻或单个 demo：用 `n2d-model-router/scripts/shot_class_benchmark.py plan` 建立分镜类别分层 pilot，再用当前产物哈希 + QC 收据 + 实际观看收据聚合 one-pass yield、repair yield、每接受秒成本与延迟；样本不足就保持 `insufficient_evidence`。
