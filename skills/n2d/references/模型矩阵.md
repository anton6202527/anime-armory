## 零、批量工业化判断（2026-06-09）

| | 现状 |
|---|---|
| **外部生态** | Veo 3.1 / Kling 3.0 / Runway / Luma 等都已把视频生成做成 API/任务化能力；Veo 3.1 官方 API 支持 8s、720p/1080p/4K、原生音频并按秒计费，Kling 3.0 官方强调 15s、原生多语言音频、多镜头故事板、参考视频/多图一致性，Runway/Luma 则提供 image-to-video、text-to-video、keyframe/extend 等可编排任务。|

| **当前级别** | 可定位为**工作室级工业化雏形**：能批量、能记账、能审查、能回流，但还不是完全无人值守的重工业产线。|
| **硬瓶颈** | 成本/重抽率、跨集身份一致性、复杂物理交互、口型/音画同步、动作节拍、多机调度、投放数据回灌。|

## 横切：音画联合生成趋势（可控性）

市场正走向**原生音画联合生成**（Veo 3.1 48kHz 对白、Seedance 2.0 原生音视频、Kling Omni 原生口型），"一次出音效/口型/音乐/画面同步"。

n2d 自 2026-06-16 起**默认 `原生音画`**（最快出图/出视频、原生音轨即成片音轨、无重同步返工）；说话镜走原生同步音画后端。**强配音控制（逐句音色/语速、特定配音演员、克隆音色）或后端是 image2video-only 时改 `配音先行`**——该模式 + 默认丢弃 clip 原生音轨（避免与克隆配音双人声）是为**角色音色一致性 + 节奏可控**的主动取舍。注意：`原生音画` 下仿真人音色仍需 compliance 授权；正面说话/旁白/系统音在 `配音先行` 下仍禁止原生人声接管，由配音层产出。

**口型 lip-sync（正面说话特写才值得，默认不做）**：

| | 现状 |
|---|---|
| **SOTA 快照(2026-06)** | 平台原生：Kling Omni 原生 5 语种口型、Veo 3.1 原生对白。后期开源：**LatentSync**（扩散、身份保持最好——连痣/胡须都保，2026 实测）/ **MuseTalk**（口型+画质均衡、近实时，但不保面部特征·胡须会变稀）/ Wav2Lip（SyncNet 同步精度最稳但偏糊）/ HighSync（2026·同步分最高） |
| **n2d 默认** | 默认不做；启用时优先平台原生（可灵 3.0），否则后期 pass **首选 LatentSync**（漫剧脸=命门，身份保持优先于实时）；要近实时/速度才用 MuseTalk（见 `n2d-video` SKILL「对口型 lip-sync」节，工具优先序与此一致）。〔口型档 2026-06-19 校正：原写"首选 MuseTalk"与 `n2d-video` 实际工具序及 2026 身份保持实测相悖，已翻转〕 |
| **升级触发** | 正面说话特写多、口型对不上很跳时启用；规模化/真人底片 → Wav2Lip。能不做就靠分镜规避（侧脸/背身/空镜配旁白）最省 |
