# 制作模式与视频路由

本文件承接 `n2d/SKILL.md` 中过长的制作模式与视频路由细则。调度入口只保留摘要；需要解释选择代价、路由边界或排查旧项目时读这里。

## 制作模式

选择点：`制作模式`，写入作品根 `_设置.md`。机器真值源是 `skills/n2d/_lib/n2d_const.py::PRODUCTION_MODE_DEFAULT`；本文、`contract.md`、`architecture.md` 只复述同一契约。

四种制作模式：

- `混合自动路由`：**默认路径**。先建立声音选角与无 WAV 时间基准，再按每个镜头选择音频驱动、粗时间后配、画面先行、原生音画或基础视频后置口型。
- `配音先行`：兼容/强控制模式。整项目先出真实配音，再用实测时长驱动分镜和视频。
- `原生音画`：显式项目级 native AV 模式。适合后端能力、音色控制和合规条件都匹配的项目。
- `先出视频后配音`：显式整项目画面先行模式。适合纯视觉 demo 或用户明确接受重定时风险的项目。

阶段1/阶段2入口会运行：

```bash
python3 skills/n2d/n2d-voice/voice_preflight.py prepare <作品根> 第N集
python3 skills/n2d/scripts/production_mode_router.py <作品根> 第N集 --write
```

前一条只写 `voice_casting.json` 和 `timing_estimate.json`，不生成音频；后一条把逐镜策略写入 `生产数据/production_mode_route_第N集.json/md`。路由不会自动改用户设置，但其逐镜生产合同会被视频、口型、合成和 gate 消费。

### 默认：混合自动路由

真正默认的是“时间基准先行”，不是“最终配音先行”：

```
剧本改编
  → 声音选角 + 文本估时（无 WAV）
  → 分镜/OTIO
  → 按镜头生成画面或表演
  → 音色定妆后生成最终配音
  → 必要镜头独立口型 pass
  → 合成/验收
```

| 镜头条件 | `audio_strategy` | 前期要求 | 最终处理 |
|---|---|---|---|
| 对白近景、正反打、口型可见，已有获批表演/guide 轨 | `performance_audio_first` | 真实表演时序/可信导引音轨 | 可替换最终音色；替换后重验口型与时长 |
| 同类镜头暂无可信表演轨 | `base_video_then_post_lipsync` | neutral-mouth base plate，禁止模型猜台词口型 | 最终/获批表演轨到位后跑独立 lipsync pass |
| 旁白、内心戏、口外音 | `rough_timing_final_dub_later` / `post_dub` | `timing_estimate.json`，不生成占位 WAV | 最终配音后置，按画面微调表演与停顿 |
| 动作、空镜、蒙太奇 | `picture_first` | 画面节奏/剪辑点 | 后期配音、拟音、BGM 设计 |
| 适合且后端已核验的同步音画镜头 | `native_av` | 台词事实锁、模型能力和授权 | 保留/整理原生音轨并做字幕对齐 |

`配音=⏳rough` 在新默认里表示“时间基准已建立”，不等于已有粗配音。可见口型镜头若没有表演轨，可以推进到 base plate，但 `video/compose/review` 最终闸门会要求对应 `视频_lipsync/Clip_XX_lipsync.mp4`；成片需要外部声音的 route 还必须有锁定的 casting 和 final 音轨。

### 旧项目兼容模式

- `配音先行`：`剧本 → 最终配音 → 实测时长 → 分镜/OTIO → 画面 → 合成`。适合全项目都有稳定配音供应、强口型/声音控制且不介意等待声音的情况。
- `先出视频后配音`：`剧本 → 无 WAV 估时 → 画面 → 最终配音 → 拟合/重切 → 合成`。不再要求用 `say` 或静音 WAV 填状态；真实配音偏离估时仍可能导致局部重切。
- `原生音画`：说话镜由后端一次出台词、口型、环境声；固定模型/身份锁无法满足 native speech 时，route 必须显式回退到外部配音。付费/发布仍需词级字幕对齐、声源/物理 sidecar 与授权证据。

## 首跑选择

新作品第一次拆集时必须把菜单给用户，不能因全局默认而静默预填。选后写 `_设置.md`，之后沉默沿用，随时可改。简明菜单：

> 先定音画制作策略（之后默认沿用，随时可改）：
> - A. 混合自动路由（默认）——先选角和无 WAV 估时，再按镜头决定音频驱动、画面先行、原生音画或后置口型；最终配音在音色获批后生成。
> - B. 配音先行——整项目先出最终配音，适合稳定配音供应和强声音控制。
> - C. 原生音画——整项目优先同步音画后端，少逐句音色控制，仍需授权与字幕对齐。
> - D. 先出视频后配音——整项目画面先行，接受后期拟合、重切或重出口型镜的风险。
>
> 你选哪个？（不选默认 A）

实战注脚：用户只说“后配音”时不再把整个项目强制归一成 D；默认仍采用 A，再让动作/旁白/口外音等适合后配的镜头自然后置。只有用户明确要求“整集/整项目全部先出画面”才选 D。`合成阶段` 是独立选择点。

## 视频模型路由

新作品默认写入/沿用 `视频模型路由=自动按镜头路由`。开局不问 `生视频模型` + `生视频渠道`；它们只是出视频阶段的普通镜兜底、执行入口偏好或固定模式参数。

真正后端决策发生在 `n2d-video`：

- 先跑 `n2d-model-router`、CLI/API 探测、适配层能力归一。
- 按每个 Clip 写 primary/fallback/degrade plan。
- 旧项目的 `生视频AI` 兼容读取，新项目不要再写这个合并字段。

`n2d-image` 的“同项目统一生图模型+渠道”只管首帧、定妆、分镜 PNG 的身份和画风一致。视频阶段允许按镜头能力逐 Clip 路由，但 `video_model_routes.json` 必须声明 `backend_consistency_scope=per_clip_allowed_with_baseline`，并配齐跨集路由基线、身份交接、执行配方和成片 QC。

只有以下情况才在 `n2d-video` 出视频前询问并落档具体模型/渠道：

- 用户明确要求固定用某个模型或渠道。
- `_设置.md` 已设 `视频模型路由=固定生视频模型`，或客户/交付/预算/账号要求单后端。
- router/probe 找不到可执行后端，必须让用户选择可用渠道或 `manual`。
- 平台审核、发行地区、原生音画、口型、多人/打斗/多帧等能力缺口需要用户确认降级、重出图或换后端。

固定模式菜单：

> 你要求固定生视频后端，本项目将不再逐镜自动换模型。请选择默认模型与调用渠道：
> - 模型：Seedance 2.0 / Veo 3.1 / Kling 3.0 / Hailuo / Runway / Luma / Pika / 开源 / manual
> - 渠道：即梦/Dreamina / 豆包 / 海螺AI / 可灵Kling / Google Gemini API / Runway API / 本地开源 / manual
> 选后写 `_设置.md`；若后续某类镜头能力不足，router 只写回退/保真实现方案或暂停询问，不偷偷切走。

长镜/故事版多图按后端能力档处理，不拆段硬接。`生视频渠道=即梦` 时，长镜或“一段多镜”优先用即梦官方 CLI 的 `multiframe2video` 智能多帧。其他渠道按首尾帧、多帧、时长、参考图等真实探测结果走适配层；未核验的新/未知后端不得假定支持多帧，必须 refresh/probe/smoke 或人工确认后再升级能力。
