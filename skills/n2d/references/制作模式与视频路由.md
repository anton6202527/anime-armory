# 制作模式与视频路由

本文件承接 `n2d/SKILL.md` 中过长的制作模式与视频路由细则。调度入口只保留摘要；需要解释选择代价、路由边界或排查旧项目时读这里。

## 制作模式

选择点：`制作模式`，写入作品根 `_设置.md`。机器真值源是 `skills/n2d/_lib/n2d_const.py::PRODUCTION_MODE_DEFAULT`；本文、`contract.md`、`architecture.md` 只复述同一契约。

三种制作模式：

- `原生音画`：默认。说话镜由 Seedance 2.0 / Veo 3.1 类后端一次生成同步音画；最快看到出图/出视频，少了前期配音和对口型返工。
- `配音先行`：先出真实配音，再用实测时长驱动分镜和视频；适合强配音控制、逐句表演、或后端是 image2video-only 的项目。
- `先出视频后配音`：快速 demo 路径；先用估算时长推进画面，真实配音后补。仅适合比稿/预览/配音暂缺，代价是后期可能重切重出。

### 配音先行

```
剧本改编 → 真实配音(测每句时长) → 分镜设计(时长驱动) → 出图 → 出视频 → 合成
```

真实配音时长驱动镜头/Clip 时长，音画最稳、节奏最可控、返工最少。

### 先出视频后配音

```
剧本改编 → 估算时长(按台词文本/或 say占位) → 分镜设计(估时驱动) → 出图 → 出视频 → 【后期】真实配音 → 合成(配音拟合到已成片镜头长)
```

选这条时，每个阶段入口都要提醒用户：

- 时长只能估算，真实配音常与估算差 20-40%；后期可能出现音画不同步、变速、留白、重切或重出视频。
- 念白情绪、语速、停顿没有参与分镜，留存节奏精度会下降。
- 正面说话特写的口型无法在配音前精准对齐。

可接受场景：纯视觉 demo、比稿、客户风格预览、内部快速预览。demo 过审后仍要补真实配音并重定时，可能重切或重出部分镜头。

闸门放行：`配音先行` 下的占位硬闸门在本模式下由用户主动选择后放行。finalize 用 `FINALIZE_ALLOW_PLACEHOLDER=1`，`n2d-video` 见占位时复述风险后继续。放行只代表用户知情，不代表该路径安全。

### 原生音画

```
剧本改编 → 分镜设计(脚本时长驱动) → 出图 → 出视频(说话镜=原生同步音画: 台词+口型+环境声) → 合成
```

- 说话镜绕过前期配音链路：`n2d-model-router` 在 `制作模式=原生音画` 时，把对话反打、说话特写、`mouth_visible` 镜头路由到原生音画后端，写 `mode=native_av`、`native_audio_policy=native_speech`。
- 台词文本、情绪、单镜时长来自脚本。这些镜头不出逐句 `时长清单`，不单独跑 `n2d-voice` 配音。
- 动作/空镜等非说话镜与配音先行一致。
- 若固定模型或身份优先模板让说话镜不能走 `native_speech`，路由必须写 `requires_voice_fallback=true`；gate 会重新要求真实 `n2d-voice` 配音，避免无声对白镜。
- `n2d-script/finalize_storyboard.py` 在原生音画模式下，无配音清单时从 `storyboard.json` 的脚本规划 `duration` 生成 `镜头时长.json`。
- `gate.py` 的 image/video 阶段对原生音画不要求“配音”列就绪，占位检查放行。
- `n2d-compose` 检测到原生音画时自动把 `视频原生音轨` 转为“保留原片音轨”；台词在 clip 自带音轨里，丢弃会丢台词。
- 说话镜字幕不在 finalize 按配音重定时。compose 可先出 draft，成片后必须用 whisperx 或等效词级对齐生成 `字幕_中文.srt`，并写 `生产数据/native_av_subtitle_alignment_第N集.json`；review/付费投放缺该 sidecar 会 BLOCK。
- 合规不变：模仿真人音色与声音克隆同级，必须有授权。AI 标识、披露、水印走 compliance/release gate。

## 首跑选择

新作品第一次拆集时必须把菜单给用户，不能因全局默认而静默预填。选后写 `_设置.md`，之后沉默沿用，随时可改。简明菜单：

> 先定出片顺序（之后默认沿用，随时可改）：
> - A. 原生音画（默认·推荐 / native AV / Seedance 2.0 类一次出同步音画）——说话镜由原生音画后端一次出台词+口型+环境声，绕过前期配音/对口型，最快看到出图/出视频、无重同步返工；代价是需要原生音画后端，少了逐句音色控制；仿真人音色仍需授权。
> - B. 配音先行（强配音控制时选）——先出真实配音、用实测时长驱动镜头，音画最准、逐句音色/语速可控、返工最少。追求配音表演、或后端不支持原生音画时选这条。
> - C. 先出视频后配音（快速 demo / 配音还没就绪）——先用估算时长把画面推起来，真实配音留到出视频后再补。代价是后期补音对不准、可能重切重出，仅 demo/比稿或配音暂缺时用。
>
> 你选哪个？（不选默认 A）

实战注脚：旧项目可能因为早期配音没准备好而走 C。用户明确说“用后配音”“先把画面做出来”时，按 `选择点与偏好.md` 解析并落档 `制作模式=先出视频后配音`，不必反复追问。

## 视频模型路由

新作品默认写入/沿用 `视频模型路由=自动按镜头路由`。开局不问 `生视频模型` + `生视频渠道`；它们只是出视频阶段的普通镜兜底、执行入口偏好或固定模式参数。

真正后端决策发生在 `n2d-video`：

- 先跑 `n2d-model-router`、CLI/API 探测、适配层能力归一。
- 按每个 Clip 写 primary/fallback/degrade plan。
- 旧项目的 `生视频AI` 兼容读取，新项目不要再写这个合并字段。

`n2d-image` 的“同项目统一生图模型+渠道”只管首帧、定妆、分镜 PNG 的身份和画风一致。视频阶段允许按镜头能力逐 Clip 路由，但 `video_model_routes.json` 必须声明 `backend_consistency_scope=per_clip_allowed_with_baseline`，并配齐跨集路由基线、身份交接、执行配方和成片 QC。

只有以下情况才在 `n2d-video` 出视频前询问并落档具体模型/渠道：

- 用户明确要求固定用某个模型或渠道。
- `_设置.md` 已设 `视频模型路由=固定生视频模型`，或客户/交付/预算/账号要求单后端。
- router/probe 找不到可执行后端，必须让用户选择可用渠道或 `manual`。
- 平台审核、发行地区、原生音画、口型、多人/打斗/多帧等能力缺口需要用户确认降级、重出图或换后端。

固定模式菜单：

> 你要求固定生视频后端，本项目将不再逐镜自动换模型。请选择默认模型与调用渠道：
> - 模型：Seedance 2.0 / Veo 3.1 / Kling 3.0 / Hailuo / Runway / Luma / Pika / 开源 / manual
> - 渠道：即梦/Dreamina / 豆包 / 海螺AI / 可灵Kling / Google Gemini API / Runway API / 本地开源 / manual
> 选后写 `_设置.md`；若后续某类镜头能力不足，router 只写回退/保真实现方案或暂停询问，不偷偷切走。

长镜/故事版多图按后端能力档处理，不拆段硬接。`生视频渠道=即梦` 时，长镜或“一段多镜”优先用即梦官方 CLI 的 `multiframe2video` 智能多帧。其他渠道按首尾帧、多帧、时长、参考图等真实探测结果走适配层；未核验的新/未知后端不得假定支持多帧，必须 refresh/probe/smoke 或人工确认后再升级能力。
