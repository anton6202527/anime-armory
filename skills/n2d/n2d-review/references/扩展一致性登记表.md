# 扩展一致性登记表 Schema（2026-06 一致性加固第二批）

`scripts/extended_consistency.py` 消费的几张登记表 / sidecar 的字段约定。登记表由对应**生产 stage** 写入，
审计层只读。缺登记表时检查器**优雅 WARN**（先提示建库，不硬阻断）；缺 sidecar 时**优雅跳过**（交人判兜底）。

所有路径相对作品根 `创作区/制漫剧/<剧名>/`。

---

## 1. `设定库/ui_asset_registry.json` —— UI/系统面板/HUD 定妆（UI1，n2d-image 写）

把穿越系统流的**系统面板/血条/等级框/属性条/签到/抽奖**当作和角色脸同级的**锁定资产**：跨集复用同一张面板
定妆底图，image2image 只换数值/文案区；面板里的中文文字（也含牌匾/匾额等图中文字）渲染最不稳，单列锁。

```json
{
  "kind": "n2d_ui_asset_registry",
  "assets": [
    {
      "id": "UI_system_panel",
      "frame": "鎏金描边圆角矩形，半透明靛蓝底",
      "palette": ["#1B2A4A", "#E8C46B", "#9FE3FF"],
      "font": "方正准雅宋 / 像素等宽数字",
      "layout": "顶部标题栏 + 左侧头像 + 右侧三行属性条 + 底部确认键",
      "text_template": "等级 {lv}｜修为 {exp}/{max}｜状态 {status}",
      "reference_png": "出图/共享/图片/定妆_UI_system_panel.png",
      "appears_in": ["第1集", "第2集"]
    }
  ]
}
```

- **必锁四字段**：`frame`(边框) / `palette`(配色) / `font`(字体) / `layout`(版式)。缺任一 → WARN。
  （也接受中文键 `边框/配色/字体/版式`，检查器同时认。）
- storyboard 里被判为面板镜的 clip，其 prompt 文本须出现 `UI_*` 绑定；未绑定 → WARN，绑了未登记 id → WARN。
- 面板镜识别词：系统面板/血条/等级框/属性条/签到/抽奖/HUD/界面元素… + 图中文字（牌匾/匾额/招牌/对联…）。

## 2. `设定库/leitmotif_registry.json` —— 音乐母题（LM1）

**用户/AI 在 n2d-script 阶段1 登记的可选配置**（与 `voicemap.json`/`motif.json` 同类——SKILL 步骤手工/AI 写，**无脚本自动产出**；登记步骤见 `n2d-script/SKILL.md` 音乐母题登记段）。下游：n2d-review LM1（`extended_consistency.check_leitmotif`）按它对账，n2d-compose 据 motif 混 BGM。**缺该文件不阻断**——音乐/多角色集只给 WARN 建议登记，无音乐信号集直接跳过。

声音侧的 `voice_key` 类比：一角色/一情绪主题 = 一主题动机，跨集 BGM 可复现且不串用。

```json
{
  "kind": "n2d_leitmotif_registry",
  "motifs": [
    {"id": "MOTIF_hero",    "subject": ["CHAR_shen"],          "desc": "上行五声音阶、古筝主奏"},
    {"id": "MOTIF_villain", "subject": ["CHAR_liu"],           "desc": "低频持续音、不协和"},
    {"id": "MOTIF_reveal",  "subject": ["情绪:真相揭晓"],       "desc": "弦乐渐强 + 鼓点"}
  ]
}
```

- `subject` 可填 `CHAR_*` 或情绪主题串。storyboard clip 的 `bgm`/`music`/`配乐` cue 里若同一 `CHAR_*`
  指向了 ≠ 登记 motif（`MOTIF_*`/`LM_*`）→ WARN（母题串用）。
- 有配乐 cue 或 ≥2 角色但整表缺失 → WARN（建库）。

## 3. `设定库/series_grade.json` + `合成/<集>/grade_applied.json` —— 系列调色（GRD，n2d-compose 写）

剧级**色彩基调锁**（一部剧一套 LUT/白平衡/对比/饱和基线），compose 统一套用，逐集留套用证据。
`tone_light_contract` 只焊片内像素冷暖，这层补"跨集观感色温/对比漂"。

```json
// 设定库/series_grade.json
{"kind": "n2d_series_grade", "lut": "teal_orange_v2.cube",
 "white_balance": "5600K", "contrast": 1.08, "saturation": 0.95}

// 合成/第1集/grade_applied.json
{"kind": "n2d_grade_applied", "grade_version": "teal_orange_v2", "applied_at": "2026-06-22"}
```

- 成片已出但缺 `series_grade.json` → WARN；存在但未声明 LUT/白平衡/对比/饱和任一 → WARN；
  本集成片缺 `grade_applied.json` 套用证据 → WARN。成片未出 → 跳过（compose 后复跑）。

## 4. `设定库/ambient_map.json` —— 环境声床（AMB，n2d-compose 写）

每场景的环境底噪（雨/集市/宫廷夜风…）跨镜/跨集连续。`reverb_profile` 管混响，这层管 ambient bed。

```json
{
  "kind": "n2d_ambient_map",
  "scenes": {
    "LOC_palace_hall": {"bed": "宫殿夜·远处更鼓+风", "loudness_lufs": -30},
    "LOC_market":      {"bed": "集市白日·人声鼎沸",   "loudness_lufs": -26}
  }
}
```

- 本集出现的每个 `LOC_*` 在 `scenes` 无登记 → WARN（补 LOC→bed）。
- 同一 LOC 内各 clip 的 `ambient`/`环境声` 字段互相冲突 → WARN（同场景声床应一致或标转场）。

## 5. 跨集体型 R2（无独立登记表，复用 `出图/共享/identity_registry.json`）

读 `characters[].character_dna.身形/体型/body`（或 `forms[]` 内同字段）作跨集**体型锁**。
- 长线角色（`appears_in` ≥2 / `core` / `long_line`）缺体型锁 → WARN（此前只有脸有跨集质心漂移追踪）。
- 本集 prompt 体型描述与登记锁出现**对立词组冲突**（纤细↔魁梧 等）→ WARN（跨集体型漂移嫌疑）。

## 可插拔 sidecar（重模型 runner 产出，缺则跳过）

### `生产数据/object_presence_<集>.json` —— 视觉级在场检测（O3V）

关掉"O3 物件常驻只有契约文本、无视觉在场检测"的 backlog。由可选 owlv2 / grounding-DINO / VLM 在场
检测 runner 产出（见 `scripts/object_presence_runner.py`）。

```json
{"kind": "n2d_object_presence",
 "findings": [{"shot": "Clip_03", "asset": "PROP_jade", "expected": true, "present": false, "severity": "block"}]}
```

- `expected=true & present=false` → 默认 block（登记常驻对象缺席，object permanence 违例）。
- `expected=false & present=true` → 默认 warn（应消失/遮挡后未恢复的对象出现）。

### `生产数据/resident_presence_<集>.json` —— 场景常驻陈设(set-dressing)在场检测

补 LOC `scene_dna.resident_assets`（残烛/铜镜/碎梁这类陈设）此前只查「非空」、从不验证真画进场景的缺口。
由 `scripts/resident_presence.py` 产出，复用 O3V 同一 OWLv2 后端（`N2D_PRESENCE_BATCH_CMD`），
**场景级判定**（特写不框到地砖→某镜没拍到不算丢；只有一个陈设在该场景**所有**被探镜里全部缺席才判它消失），
同 kind `n2d_object_presence`，由 `extended_consistency.check_object_presence_visual`（O3V）一并消费。
核心场景丢陈设→block，其余→warn；无后端时只产探针清单 + advisory note，不凭空 block。

```bash
python3 skills/n2d/n2d-review/scripts/resident_presence.py <作品根> 第N集 --write
```

### `生产数据/appearance_judge_<集>.json` —— VLM-Appearance 判官（VAP）

ArcFace(insightface) 测身份 embedding 之外，补"人眼可感外观相似度"的模型判官，在 insightface 降级
（无库 / 侧背脸）时补盲区。由可选 VLM runner 产出（见 `scripts/appearance_judge_runner.py`）。

```json
{"kind": "n2d_appearance_judge",
 "findings": [{"shot": "Clip_05", "character": "CHAR_shen", "verdict": "warn", "similarity": 0.61,
               "message": "发饰与定妆不符、脸型偏圆"}]}
```

- 只消费 `verdict` ∈ {block, warn} 的条目；其余视为通过。`similarity` 仅作展示。

### `生产数据/text_render_<集>.json` —— 图中文字 OCR 校验（OCR1）

AI 生图的中文字渲染（系统面板数值/属性、牌匾/匾额/招牌、卷轴书页）是 2026 仍未解的弱项，必须**实读
校验**而非假设画对。`text_render_runner` 从 `ui_asset_registry.text_template` 或 storyboard clip 的
`图中文字`/`render_text`/`on_image_text` 字段取**预期文字**配 probe，OCR 后端实读后比对（见
`scripts/text_render_runner.py` + `backends/text_ocr_easyocr.py`）。

```json
{"kind": "n2d_text_render",
 "findings": [{"shot": "Clip_01", "verdict": "block", "expected": "等级 8 修为 120",
               "ocr_text": "等级3修为120", "similarity": 0.875,
               "message": "图中数字渲染错误：预期数字 ['8','120'] OCR 实读 ['3','120']"}]}
```

- 预期含数字且 OCR 数字不符 → block（面板数值错=硬伤，即便文字整体相似度高）；否则按归一相似度
  `< block_floor(0.5)`=block / `< warn_floor(0.8)`=warn。无 sidecar 时 OCR1 做 first-pass：文字镜
  缺声明预期文字 → WARN（OCR 无对照基准）。

## 6. `设定库/translation_glossary.json` —— 译名一致（TX1，n2d-script 阶段2 写）

海外投放/双语项目：专有名词/称谓（人名/门派/功法/称呼）跨集 EN 译法必须统一，否则红果/海外观众认不出。
从角色卡/称谓表种一份 canonical 译名表。纯标准库检查（无需后端）。

```json
{"kind": "n2d_translation_glossary",
 "terms": [{"cn": "青云宗", "en": "Qingyun Sect"}, {"cn": "沈念", "en": "Shen Nian"}]}
```

- 本集台词出现 `cn` 但 EN 字幕未见约定 `en` → WARN（译名漂移）；glossary 自身一个 `cn` 多个 `en` →
  WARN（收敛 canonical）；有 EN 字幕但缺 glossary → WARN（建库）。

## 跑后端（本机已装·Apple Silicon）

重模型走 out-of-repo conda 环境，runner 通过 **batch 命令**（模型只加载一次）就地填 sidecar 的
`findings`。两个适配器在 `skills/n2d/n2d-review/scripts/backends/`：

```bash
# O3V 在场检测 —— OWLv2 开放词表检测（复用 facefusion 环境，已装 torch(MPS)+transformers）
N2D_PRESENCE_BATCH_CMD="conda run -n facefusion python skills/n2d/n2d-review/scripts/backends/presence_owlv2.py" \
  python3 skills/n2d/n2d-review/scripts/object_presence_runner.py <作品根> 第N集 --write
#   阈值 env N2D_OWLV2_THRESHOLD（默认 0.10，按风格用 golden set 标定）；模型 N2D_OWLV2_MODEL
#   场景常驻陈设(set-dressing)在场用同一 OWLv2 后端：resident_presence.py（场景级判某陈设是否整场缺席）
N2D_PRESENCE_BATCH_CMD="conda run -n facefusion python skills/n2d/n2d-review/scripts/backends/presence_owlv2.py" \
  python3 skills/n2d/n2d-review/scripts/resident_presence.py <作品根> 第N集 --write

# SCNX 跨集场景**语义嵌入** —— DINOv2 全图嵌入（facefusion 环境，torch(MPS)+transformers）
#   给跨集场景漂移补一条学习型指纹（连材质/几何/布局都能测，是 HSV 色调直方图的盲区）；
#   无后端时 SCNX 优雅退回色调直方图 + 结构 dHash 原型（既有），不硬失败。
N2D_SCENE_EMBED_BATCH_CMD="conda run -n facefusion python skills/n2d/n2d-review/scripts/backends/scene_embed_dinov2.py" \
  python3 skills/n2d/n2d-review/scripts/scene_embed.py <作品根> 第N集 --write
#   模型 env N2D_DINOV2_MODEL（默认 facebook/dinov2-base）

# 场景几何（floor_plan/门窗）一致性 —— OWLv2 门窗侧位检测（position-aware·facefusion 环境）
#   把登记的结构开口（门/窗/破顶开口）应在画面侧 vs 实测对照，场景级判朝向漂/缺席；并进 O2 段消费。
#   无后端则只产开口探针 + advisory，不凭空 block。
N2D_SCENE_GEOMETRY_BATCH_CMD="conda run -n facefusion python skills/n2d/n2d-review/scripts/backends/scene_geometry_owlv2.py" \
  python3 skills/n2d/n2d-review/scripts/scene_geometry_conformance.py <作品根> 第N集 --write

# VAP 外观判官 —— MLX-VLM（专用 n2dvlm 环境，Apple 原生 4-bit）
N2D_APPEARANCE_BATCH_CMD="conda run -n n2dvlm python skills/n2d/n2d-review/scripts/backends/appearance_mlxvlm.py" \
  python3 skills/n2d/n2d-review/scripts/appearance_judge_runner.py <作品根> 第N集 --write
#   模型 env N2D_VLM_MODEL（默认 Qwen2.5-VL-3B-Instruct-4bit·16GB 安全；内存富裕可换 7B-4bit）
#   单图 N2D_VLM_CMD 与 batch 外观判官接口不同，模板与自动接入说明见 `vlm_backend.md`

# OCR1 图中文字校验 —— EasyOCR（专用 n2docr 环境，中英）
N2D_TEXT_OCR_BATCH_CMD="conda run -n n2docr python skills/n2d/n2d-review/scripts/backends/text_ocr_easyocr.py" \
  python3 skills/n2d/n2d-review/scripts/text_render_runner.py <作品根> 第N集 --write
#   floor env N2D_OCR_WARN_FLOOR(0.8)/N2D_OCR_BLOCK_FLOOR(0.5)；语言 N2D_OCR_LANGS（默认 ch_sim,en）
#   译名一致(TX1) 纯标准库无需后端：建 设定库/translation_glossary.json 后 consistency_audit 自动核对
```

跑完 sidecar 落进 `生产数据/`，下一次 `consistency_audit.py` 的 `在场检测(O3V)`/`外观判官(VAP)`/
`文字渲染(OCR1)` 自动读取出 findings（无 sidecar 时这几维优雅跳过、交人判）。首次运行会下载模型权重
（owlv2≈600MB、Qwen2.5-VL-3B-4bit≈2.5GB、EasyOCR 中英模型≈100MB）到缓存。
