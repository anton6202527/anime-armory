# 专项镜头模板库（复杂镜头）

复杂镜头不要每次从零写 prompt。凡涉及高动作、高空间关系或多人调度的镜头，先在本库选模板，再写 `分镜剧本.md`、`故事板.md` 和 `storyboard.json`。模板的目标不是把画面写死，而是把 AI 最容易失控的变量提前锁住：轴线、站位、动作节拍、起幅落幅、关键帧、负向约束和下游回流点。

## 0. storyboard.json 必填契约

命中本库任一模板的 Clip，必须在 `clips[]` 里写：

```json
{
  "id": "EP01_CLIP04",
  "label": "王敦追入山洞",
  "template": "chase",
  "template_contract": {
    "template_id": "chase",
    "beats": ["起跑", "障碍", "距离变化", "落幅"],
    "blocking": "王敦画面左前向画右深处奔跑，追兵只用影子/脚步声提示",
    "camera_rule": "跟拍或侧向平移，不越轴，不做无理由旋转",
    "continuity_must": ["出入画方向保持左→右", "衣服发型不变", "洞口光位不跳"],
    "negative": ["不要瞬移", "不要新增人物正脸", "不要让角色换方向"],
    "speed_curve": "起跑加速→障碍半顿→再加速",
    "spatial_path": "画左前景沿洞壁折线到画右深处",
    "camera_path": "侧向跟拍，不环绕",
    "parallax_layers": ["前景石柱快", "洞壁中速", "洞口光慢"],
    "readability_beats": ["障碍前半拍看清方向", "落幅停在转弯点"]
  }
}
```

通用必填字段：

| 字段 | 要求 |
|---|---|
| `template` | 模板 ID，必须取本库模板；旧项目允许 legacy `multi_person_blocking` |
| `template_contract.template_id` | 与 `template` 完全一致 |
| `beats` | 2-6 个动作/表演节拍，按时间顺序写 |
| `blocking` | 人物左右/前后/距离/出入画方向 |
| `camera_rule` | 允许的机位和运镜边界 |
| `continuity_must` | 必须继承到出图/出视频的连续性约束 |
| `negative` | 该模板最容易翻车的负向约束 |

> gate 会在出图/出视频前检查：复杂镜头缺 `template/template_contract`，或模板字段不全，必须回 `n2d-script` 补。

## 0.1 Motion Control 分级

涉及真实接触、遮挡、高速追逐或飞行的模板要先决定是否直接生成，不能留给视频 prompt 临场猜：

| 风险 | 适用模板 | 下游要求 |
|---|---|---|
| required | `fight_exchange`、`chase`、`flight`、`intimate_interaction`、`hug_or_pull`、`multi_character_same_frame`、`ensemble_blocking`、`multi_person_blocking` | `n2d-model-router` 会写 `motion_control.level=required`；出视频前必须有 `motion_control_manifest.json`，状态为 `ready` 或 `degrade_only` |
| none | 普通单人反应、空镜、低幅度动作 | 不需要 Motion Control manifest |

`ready` manifest 代表已有 pose/depth/instance/contact 或 camera_path/spatial_path/parallax_layers 等控制资产。`degrade_only` 代表不直接生成全身复杂接触或长连续高速动作，改成手部特写、过肩反打、正反打追逐、巡航/机动/抵达拆镜等可控短镜。OpenPose/DWPose 只能锁姿态；拥抱、抓腕、刀剑命中还要写清 `occlusion_order`、`body_part_ownership` 和接触点，必要时用 depth/instance masks/contact_map。追逐/飞行不需要接触点，但必须锁 `camera_path`、`spatial_path` / `parallax_layers`，否则高速镜很容易翻方向、丢距离或变成背景贴图。

## 0.1b 高动作编排契约

`fight_exchange`、`chase`、`flight` 不能只写“精彩打斗/高速追逐/御剑飞行”。这三类必须把动作拆成可读节拍，写进 `template_contract`，并由 `n2d-video` 继承到 `动作编排契约` 字段。

通用必填：

| 字段 | 要求 |
|---|---|
| `speed_curve` | 明确慢→快→顿→收，或巡航→加速→减速；禁止全程匀速 |
| `spatial_path` | 人/剑/云/追逐路线在画面里的路径，含入画/出画方向 |
| `camera_path` | 跟拍/侧移/快推/固定的路径和速度边界 |
| `readability_beats` | 观众看清命中、距离变化、穿云/转向的半拍或落点 |

模板专属补充：

| 模板 | 额外字段 |
|---|---|
| `fight_exchange` | `force_direction`、`recovery_beat`；`attack_path` 与 `impact_frame` 必须能支持命中帧 |
| `chase` | `parallax_layers`、`overtake_or_escape_beat`；距离曲线只能“追近”或“拉开”选一条主变化 |
| `flight` | `flight_path`、`altitude_curve`、`parallax_layers`、`mount_or_cloud_lock`；御剑/祥云/法器形态必须锁定 |

## 0.2 通用 motif（母题）模板形态

上面 §1–§10 是**动作/空间调度**模板。还有一类是**母题/复现场景**模板：穿越/系统流爽文里高频复现、相对固定但每次出现带成长属性的桥段——系统面板出现、主角升级、系统刷新、签到、抽奖、爆装备。它们由 `motif_detector.py` 自动检测、人确认后注入（见 `题材母题框架.md`）。母题模板与动作模板共用 §0 必填契约，但多三条铁律：

1. **固定模板 + 成长递进**：同一母题跨集套同一套视觉语言（机位/构图/色彩/台词腔调），但每次出现要有成长（面板进化、等级只增不减、属性攀升）。成长用 `motif_registry.json` 的 `growth_state_machine.progression`（单调，机检退级=block）+ 绑定 VFX 的 `lifecycle`（forms 即档位）。
2. **混合渲染（关键）**：AI 生图渲染不准清晰文字/数字，而面板恰恰全是数值。所以模板必须声明 `text_layer=overlay`：**AI 只画发光底框/符纹（VFX，锁色锁形），等级/属性/标题等数值由 n2d-compose 期 Pillow overlay 叠上**。模板的 `negative` 必须禁掉 AI 画任何可读文字/数字。
3. **台词母题腔**：系统音机械简短（`narrator_role=系统`→字幕灰小字、配音系统音色），主角反应是爽点释放（可标 `钩子=climax`→暖金大字）。

母题模板专属字段（写进 `template_contract`）：

| 字段 | 含义 |
|---|---|
| `motif_id` | 绑 `motif_registry.json` 的母题（如 `MOTIF_系统面板`） |
| `vfx_asset` | 绑成长 VFX（如 `VFX_系统面板`），从 `asset_registry` 继承 forms/lifecycle/锁色 |
| `text_layer` | `overlay`（数值走合成期文字层）/ `baked`（少数无文字纯特效母题才用） |
| `growth_ref` | 指向 progression 当前快照（at_clip） |

**系统面板是首个落地母题样板（§12）。** 后续 level_up / system_refresh / signin / gacha / loot 复用本形态：面板家族统一套 `system_panel` 模板 + `VFX_系统面板`，只在 `motif_registry` 加配置，**不新增模板代码**。

## 1. `fight_exchange` 打斗攻防

**使用场景**：拳脚、刀剑、掌法、法术近身命中、受击反应。完整武打拆招仍按 `打斗分镜.md`，本模板用于把 Clip 级契约写进 `storyboard.json`。

**拆法**：
- 起手：谁先动，力从哪里来。
- 发力：攻击路径清楚，不让 AI 自由编招。
- 命中/错身：命中帧或擦身帧单独锁图。
- 受击/反应：被打者只做一个明确反应。
- 收势：落到可接下一镜的姿态。

**额外必填字段**：`attack_path`、`impact_frame`、`action_scope`、`speed_curve`、`spatial_path`、`readability_beats`、`force_direction`、`recovery_beat`

**提示词规则**：多人混战拆成单人/双人正反打；命中类 Clip 优先首尾双帧；镜头运动只服务打击感，不乱飞。若出现刀剑/手掌/身体接触，出视频前必须 ready Motion Control 或 degrade_only 拆成起手、命中特写、受击反应。

---

## 2. `chase` 追逐

**使用场景**：追杀、逃跑、巷道/山路/洞穴追逐、飞行追逐。仙侠飞行追逐还要同步读 `仙侠场面分镜.md`。

**拆法**：
- 建立方向：先锁屏幕方向和地理关系。
- 距离变化：追近/拉开只能选一个主变化。
- 障碍节拍：门槛、石壁、雨帘、树枝等只放 1-2 个。
- 落幅：停到转弯、回头、跌倒、藏入暗处等可剪点。

**额外必填字段**：`screen_direction`、`distance_curve`、`obstacle_beats`、`speed_curve`、`spatial_path`、`camera_path`、`parallax_layers`、`readability_beats`、`overtake_or_escape_beat`

**提示词规则**：速度感来自背景流动、前景掠过、脚步/衣摆/雨丝，不来自人物变形；同一 Clip 不要同时写追逐、打斗、法术爆发三件事。

## 3. `dialogue_shot_reverse` 对话反打

**使用场景**：逼问、谈判、对峙、男女主互相试探、主仆/师徒/敌我正反打。普通台词不必都套；只有需要正反打、过肩、视线对位、权力关系变化时使用。

**拆法**：
- 建立轴线：谁在画左/画右，视线朝向哪里。
- A 面：说话者景别、情绪、压迫感。
- B 面：反打对象反应，不改变左右关系。
- 插入物/手部：必要时用茶杯、剑柄、符纸、手指动作缓冲。
- 落幅：停在眼神或反应，服务下一句台词。

**额外必填字段**：`axis`、`eyeline`、`shot_pairing`

**提示词规则**：反打不是随机换角度；同场景主光、背景深度、人物左右关系必须守住。若要越轴，必须在 `camera_rule` 写明确剧情理由和过渡镜。

## 3.1 `reveal_reaction_chain` 真相揭示 / 身份曝光反应链

**使用场景**：身份曝光、掉马、真相揭示、旧案证据公开、内鬼暴露、身世认亲。重点不是“把信息说完”，而是把证据、知情顺序和反应链拍清楚。

**拆法**：
- 证物/证据入画：血书、密信、信物、伤痕、系统提示、证人口供等先给可读视觉锚。
- 揭示句/动作：谁把真相说出或展示出来。
- 第一反应：最受冲击的人先反应，通常给 CU/ECU。
- 连锁反应：第二、第三个关键人物按知情顺序反应，不能随机切。
- 落幅/断点：停在不可逆选择、半露真相、证物被抢或称谓改变。

**额外必填字段**：`reveal_object`、`knowledge_order`、`reaction_beats`、`cut_point`

**提示词规则**：证据物要稳定，不让 AI 把信物/血书/面板文字画乱；可读文字仍优先走 overlay 或字幕，不烤进图。反应链用正反打和特写，不在同一镜里塞所有人的脸。`knowledge_order` 写清谁已知、谁刚知道、谁假装不知道，避免下游剪辑把反应顺序切乱。

## 3.2 `public_confrontation` 公开对质 / 审讯 / 谈判智斗

**使用场景**：公堂、朝堂、宴席发难、当众揭穿、审讯逼问、谈判交易、权谋智斗。它比普通反打多了“现场规则、证据阶梯、权力翻转、围观反应”。

**拆法**：
- 建立现场：裁决者、被质问者、证人/围观者的空间层级。
- 第一筹码：证据、口供、把柄、利益、时间或武力威胁。
- 反扑：被质问者反驳、改口、反咬或转移焦点。
- 权力翻转：证据升级、站队变化、裁决者表态或谈判底线暴露。
- 落幅：定罪、交易、逃脱、灭口、结盟或更大嫌疑。

**额外必填字段**：`stakes`、`evidence_ladder`、`power_shift`、`crowd_reaction_order`

**提示词规则**：人群不要人人清脸；主角、对手、裁决者和关键证人分层。证据阶梯要能被镜头看见：手中文书、桌上物证、证人出列、系统面板、令牌等。围观反应只点 1-3 个代表，不把镜头切成无意义群像。

## 4. `magic_burst` 法术爆发

**使用场景**：灵力爆发、符阵亮起、剑气冲出、雷落、火焰/光束/护盾炸开、斗法撞点。

**拆法**：
- 蓄力：颜色、形状、来源位置先锁。
- 释放：光效路径明确。
- 爆点/撞点：爆发帧或命中帧单独出图。
- 余波：尘、光点、衣摆、地面裂纹等二级动态。
- 落幅：爆后角色状态和场景状态。

**额外必填字段**：`charge_frame`、`release_frame`、`effect_asset`

**提示词规则**：高频复现法术/阵法/剑气必须进 `出图/共享/图片/特效定妆`；不要每镜换颜色、形状和轨迹。爆发只允许照亮既有场景，不新增无关奇观。

## 5. `flight` 飞行

**使用场景**：御剑、腾空、坠落、空中掠过、飞檐走壁、云海穿行。

**拆法**：
- 起飞/入画：姿态和方向先锁。
- 巡航：人物姿态尽量固定。
- 机动：只做一个转向、俯冲或急停。
- 抵达/落地：落到明确接点。

**额外必填字段**：`pose_lock`、`background_motion`、`altitude_path`、`speed_curve`、`flight_path`、`altitude_curve`、`camera_path`、`parallax_layers`、`mount_or_cloud_lock`、`readability_beats`

**提示词规则**：飞行核心是“锁姿态，动背景”。人物脸、发型、衣服不要被速度拉变形；速度感来自云、山、雨、前景掠过和镜头跟随。

## 6. `intimate_interaction` 亲密互动

**使用场景**：搀扶、牵手、抚脸、扶肩、疗伤、暧昧靠近、近距离低幅度互动。这里的“亲密”指人物距离与接触调度，不等于情色；若有拥抱、抓腕、推开、拉扯，改用 `hug_or_pull`。

**拆法**：
- 距离变化：远→近或近→分开，只选一个。
- 接触点：手腕、肩、背、额头、衣袖等必须写清。
- 视线/呼吸：用眼神、停顿、身体微动表现关系。
- 落幅：停在接触点或表情反应。

**额外必填字段**：`contact_points`、`distance_boundary`、`body_overlap_limit`

**提示词规则**：多角色接触最容易崩手和肢体重叠；优先用半身/手部特写、过肩、遮挡，而不是全身复杂拥抱。合规边界不清时回避情色化描述。直接生成近距离接触时，manifest 必须写 `contact_points`、`occlusion_order`、`body_part_ownership`。

---

## 7. `hug_or_pull` 拥抱 / 拉扯 / 抓腕

**使用场景**：拥抱、抱住、抓腕、拉袖、推开、拉扯、拽住、扶起时带明显力量方向的接触互动。它比普通亲密互动更容易崩手、穿模、肢体重叠，所以单独模板化。

**拆法**：
- 接触前：先锁两人左右、距离、手的位置。
- 接触点：抓腕/抱肩/拉袖/推胸口等只选一个主接触点。
- 力量方向：谁拉谁、往画左/画右/前景/后景移动，必须写清。
- 释放/停住：落到松手、被拉近、被推开、半步踉跄等可剪点。

**额外必填字段**：`contact_points`、`force_direction`、`body_overlap_limit`、`release_frame`

**提示词规则**：优先用首尾帧或手部特写承接，不要让 AI 在一个 Clip 里完成“冲上去、抓住、拥抱、挣扎、推开”全链路。全身拥抱不稳时，拆成靠近反应、手部接触、脸部反打。没有 ready Motion Control manifest 时，不直接生成全身拥抱/拉扯，写 `status=degrade_only` 并按拆镜执行。

## 7.1 `relationship_turn` 关系转折 / 告白 / 决裂 / 和解

**使用场景**：告白、心动兑现、决裂、误会爆发、和解、救赎、互相救场、吃醋、护短。若核心是明确肢体接触（抓腕、拥抱、拉扯），仍用 `hug_or_pull` / `intimate_interaction`；本模板锁“关系状态变化”和表演节拍。

**拆法**：
- 关系前态：两人本场前的距离、称谓、视线和阵营。
- 触发动作：承认、停步、递物、挡刀、收回信物、改称谓、转身离开。
- 潜台词反应：嘴上说的与动作表达的矛盾。
- 新关系态：更近、更远、暂时结盟、正式决裂、重新信任或留下误会。
- 落幅：停在手、眼神、背影、门关上、称谓变化或救场后的沉默。

**额外必填字段**：`relationship_state_before`、`turning_action`、`subtext`、`relationship_state_after`

**提示词规则**：关系转折镜头吃脸和微表情，优先 MCU/CU 正反打，不硬塞双人大头同框。动作要小而明确，避免“一镜完成争吵、拥抱、和解、亲吻”这类多段复杂表演。大表情跨度按 `continuity.expression_span=大` 规划首尾帧或 MCU 保真实现。

## 8. `multi_character_same_frame` 多人同框

**使用场景**：两名及以上具名角色必须同时清楚出现在同一画面：双人同框、三人同框、主角与关键配角同场对峙、同桌/同车/同殿但需要看清主角脸。2-3 张清晰脸只是相对省钱/稳定的构图区，不是免登记区；>2 或多人近景/遮挡/强交互应优先拆反打、景别分层或分区构建。

**拆法**：
- 角色槽位：每个具名角色固定画左/画右/中央/前景/后景。
- 脸优先级：只允许 1-2 张脸作为清晰焦点，其余侧脸/背影/虚焦。
- 遮挡规则：谁可以被前景遮挡，谁不能被挡脸。
- 焦点切换：若要 A→B 反应，优先拆正反打，不在同框里乱转。

**额外必填字段**：`character_slots`、`face_priority`、`overlap_rules`

**提示词规则**：多人同框的目标是“槽位稳定”，不是让每个人都完整表演。任一清晰同框 ≥2 具名角色都必须写 `character_slots` + 执行策略（`native_subject_slots` / `regional_construct_required` / `split_composite_required` / `shot_reverse_shot`）。角色身份从 `identity_registry` 继承；如果出现脸互换、左右互换、服装串色，必须拆成两人 OTS / 反打 / 手部插入。

---

## 9. `ensemble_blocking` 群像站位

**使用场景**：三人以上群戏、群臣/门徒/追兵围堵、宴席、审讯、围观、队伍站位、宗门大殿群像。重点是主次层级和空间关系，不要求人人清脸。

**拆法**：
- 建立层级：主角、对手、群体分别在前/中/后景。
- 站位图：画左/画右/中央/前景/背景写清。
- 焦点层级：一次 Clip 只突出一个说话者或动作点。
- 人群简化：背景人用剪影/虚焦/背影/局部，别要求人人清脸。

**额外必填字段**：`screen_positions`、`focus_hierarchy`、`crowd_simplification`

**提示词规则**：三人以上不追求每张脸都精确；主要人物用定妆参考，次要人物按视觉层级处理为虚焦、剪影或局部。若主角与两名以上角色都要清脸互动，优先拆正反打。

---

## 10. `multi_person_blocking` 多人站位（legacy）

旧项目已写 `multi_person_blocking` 的 Clip 仍可通过 gate；新项目优先按镜头目的拆成：

- 2-3 名具名角色同框：`multi_character_same_frame`
- 3 人以上群戏 / 队列 / 围堵 / 群像：`ensemble_blocking`

**额外必填字段（legacy）**：`screen_positions`、`speaker_focus`、`crowd_simplification`

## 12. `system_panel` 系统面板（母题·首样板）

**使用场景**：穿越/系统流的系统面板出现、主角升级、系统刷新/进化、签到、抽奖——任何"虚拟面板/光幕浮现 + 数值刷新 + 主角反应"的复现桥段。面板家族母题（system_panel/level_up/system_refresh/signin/gacha）统一套本模板。是 §0.2 通用 motif 形态的首个落地实例。

**拆法（beats）**：
- 面板浮现：发光光幕/符纹底框从主角视野浮现（位置/透明度先锁）。
- 数值刷新：面板内容跳变（升级镜在此给等级/属性跳变的特写时机——但数值本身是 overlay 层，AI 不画）。
- 主角反应：惊喜/狂喜/凝重——爽点释放点，可标 `钩子=climax`。
- 落幅：面板稳定悬浮 或 收起，主角进入下一动作。

**camera_rule**：面板正对屏幕、不随镜头透视畸变、不位移变形；机位可给主观镜（主角视角看面板）或过肩（面板 + 主角侧脸同框）。面板悬浮位置跨镜稳定。

**continuity_must**：① 面板跨集锁色锁形（继承 `VFX_系统面板` 的 color_target/frame_shape）；② 等级/档位只增不减（progression 单调）；③ **面板内部文字区留空**给 overlay；④ 面板进化只能往前（v1_素纹→v2_流光→v3_符纹，lifecycle 不回退）。

**negative（关键·混合渲染）**：面板内**不出现任何可读文字 / 数字 / 汉字 / 等级数值 / 属性条刻度 / 进度条数字**；不要 AI 自行编造面板内容；只画发光光幕底框 + 符纹边框 + 内部空白发光区。

**额外必填字段**：`motif_id`（=`MOTIF_系统面板`）、`vfx_asset`（=`VFX_系统面板`）、`text_layer`（=`overlay`）、`growth_ref`（progression 当前 at_clip）、`panel_tier`（当前面板档位/form）。

**提示词规则**：系统面板是高频复现奇观，**必须进 `出图/共享/图片/特效定妆`（`VFX_系统面板`）锁色锁形**，不要每镜换颜色/形状/符纹。升级/进化只换 `panel_tier`（form 档位）+ overlay 数值，不重画风格。台词走系统音腔（机械简短，`narrator_role=系统`）。完整链路与 registry schema 见 `题材母题框架.md`。
