# 群像与角色弧光：配角辨识度 + 弧光逐章推进

2026 多家测评点名 AI 写小说的最后一块短板：**配角太多记不住、性格雷同、对话缺辨识度、群像力不从心，主角弧光也常原地踏步**。`dialogue.md` 管"一句台词怎么有戏"、`角色语感.json`+`voice_drift.py` 管"一人一腔的机检"、`setting-bible.md` 角色卡有静态"成长弧线"——本篇补两件**跨章的活**：① 群像怎么不糊成一团；② 每个主要角色的弧光怎么逐章真的在走。写章、编章纲、`novel-review` 查"配角脸盲/性格雷同/主角不成长"时读。

> 一句话法则：**每个上场的人都要有"不可替代的功能 + 认得出的腔调 + 在动的弧光"**；糊在一起的群像 = 读者弃书。

## 一、配角辨识度三维（防"脸盲/雷同"）

每个有名字、会反复出现的配角，立项时至少定**三个维度**，任一维度和已有角色撞车就重做：

| 维度 | 是什么 | 撞车 = 雷同 |
|---|---|---|
| **功能（plot function）** | 他在故事里"干什么用"：盟友/对手/导师/信息源/麻烦制造者/镜像 | 两个配角功能重合 → 合并成一个，或删一个 |
| **声音（voice）** | 一人一腔：句长/用词层/口头禅/攻击或回避习惯（落 `角色语感.json`，机检见 `dialogue.md`） | 遮住名字分不清谁说的 → 给指纹 |
| **标记（tag）** | 一句话外部辨识：标志性外形/小动作/随身物/立场（读者记忆抓手） | 没有记忆点 → 配角即背景板 |

- **群像场景调度**：一场戏 ≥3 个有名角色同台时，**给每人至少一个"只有他会做的反应"**，别让配角沦为应声虫或人肉背景。谁不在场也要清楚（视角纪律见 `chapter.md`）。
- **配角也要微弧或鲜明功能**：重要配角给一条小弧（哪怕一个转变）；功能性配角则把"功能 + 标记"做足，不必给弧，但不能脸盲。
- **数量克制**：黄金三章别一次涌入太多名字（`opening.md`）；新角色错峰登场，登场即给"功能+标记"。

## 二、角色弧光逐章推进（防"主角原地踏步/弧光断裂"）

主角和重要配角各有一条**弧光**，用经典 want / need / lie 三件套钉死，再切成阶段，逐章问"这章谁的弧光动了"：

- **want（外在目标）**：他要的、推动情节的东西（夺回家族 / 查清真相）。
- **need（内在课题）**：他真正缺的、决定成长的东西（学会信任 / 放下执念）。
- **lie（信念误区）**：他一开始信的错的东西，弧光就是这条 lie 被冲击→动摇→打破/坐实的过程。
- **arc_stages（阶段）**：把 lie 的瓦解切成几段，绑大致章位（如 第10章固守→第25章动摇→第40章醒悟代价）。

逐章纪律：
- **每章至少推进一个人的弧光**（与 `chapter.md`「每章推进读者契约至少一项」同源：人物弧光就是其中一项）。连续多章无人成长 = 注水/弧光停滞，`arc-pacing.md` 卷级回扫会抓。
- **成长要由代价/选择挣来**，不是作者宣布"他变了"——用一个**和过去的他相反的选择**兑现转变（show-don't-tell，见 `chapter.md`）。
- **不可逆**：弧光阶段只进不退（像力量体系等级只增不减）；要写倒退必须是有动机的"至暗时刻"，且服务后续反弹。
- **力量题材**：战力/等级的逐章成长已由 `power_system_registry`+`power_system.py` 机检（见 `力量体系设计.md`）；本篇管的是**心理/关系弧光**，两者并行别混。

## 三、结构化登记（可选机检/注入）

把上面两件事落成 `设定/角色弧光.json`，写章任务包会自动注入"在场角色的当前弧光阶段 + 辨识度锚"，让 agent 写时记得住群像、推得动弧光：

```json
{
  "schema_version": 1,
  "characters": {
    "林越": {
      "role": "protagonist",
      "function": "主角/复仇者",
      "want": "夺回被夺的家族基业",
      "need": "学会信任他人、不再独行",
      "lie": "强者不需要任何人",
      "distinct_tag": "沉默寡言，用刀不用话；左手总攥着半枚旧铜钱",
      "arc_stages": [
        {"by_chapter": 10, "stage": "固守谎言：拒绝一切结盟"},
        {"by_chapter": 25, "stage": "谎言动摇：被迫依赖同伴活命"},
        {"by_chapter": 40, "stage": "醒悟代价：为护人第一次主动求助"}
      ]
    }
  }
}
```

- 字段都可选、可增量补；缺文件时任务包优雅跳过（不强制建）。长篇/群像多的项目强烈建议建。
- 与既有文件分工：`角色卡.md`（人读全量设定）→ `角色弧光.json`（机器读的弧光阶段+辨识度，供注入）→ `角色语感.json`（一人一腔声纹，供注入+`voice_drift` 机检）→ `character_guardrails.json`（底线护栏，`logic_sentry` 机检）。各司其职不重复。

## 自检

- [ ] 本章每个上场的有名角色，功能/声音/标记三维都立得住、互不撞车吗？
- [ ] ≥3 人同台的戏，每人是否都有"只有他会做的反应"，没有人肉背景板？
- [ ] 这章推进了谁的弧光？是用"与过去相反的选择"兑现，还是作者口头宣布？

- [ ] 新登场角色是否一登场就给了"功能 + 标记"，没糊成名字堆？
