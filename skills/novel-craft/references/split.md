# 拆分标准 — 章 / 集 边界

适用于所有 novel-* 写作 skill（spinoff / expand / continue / condense / 完全原创）的章节划分。**节拍优先，字数兜底**：一章是一个戏剧节拍单元，不是一个字数桶。字数只负责容量估算、风险预警和平台适配，不拥有最终边界裁决权。

本文件是 novel-* 家族的"拆分标准"说明；机器单一真值源在 `novel-craft/scripts/contract.py`。

## 核心原则

- **章 = 戏剧节拍单元**：一个完整的"冲突 → 升级 → 反转 / 决断 → 钩子"。
- **章 ≠ 字数硬切**：宁可前后章字数略不均，也别为了凑字数把高潮戏拦腰断成两章。
- **章 ≠ 原作章**：派生作品（spinoff / expand / continue / condense）的新章节边界由你按节拍重切，**和原作章节不必一一对应**。
- **章数随平台**：漫剧友好 vs 短剧 vs 网文长篇 vs 短篇，章数 / 字数差一个量级。
- **粗胚优先**：先按规则切粗胚脚手架，写完后可重切（合章 / 拆章），章节文件名按 `第NN章.md` 重排即可。

## 建议篇幅分档（按小说用途 + 目标平台）

| 平台 / 用途 | 单章建议篇幅 | 质检预警带宽 min-max | 默认项目章数 | `novel-create --scale` |
|---|---|---|---|---|
| **短故事** / **超短篇**（番茄短故事 · 短剧选品池） | **2000–6000**（整篇） | 1500–8000 | 1 | `microstory`（别名 `短故事`/`超短篇`） |
| **抖音漫剧** / **红果短剧**源书短章 | **1000–1500** | 800–1800 | 90 | `漫剧` |
| **微短剧**源书短章 | 1500–2500 | 1200–3000 | 50 | `微短剧` |
| **网文中篇**（起点 / 番茄连载） | 3000–5000 | 2500–6000 | 20 | `medium` |
| **网文长篇**（起点 V 后 / 卷级推进） | 5000–8000 | 4000–10000 | 40 | `long` |
| **短篇集** | 6000–10000 | 5000–15000 | 3 | `short` |

> **短剧/漫剧注意**：这里的 `漫剧` / `微短剧` 是“小说源书短章”档，不等于一章原文可以逐字变成一集配音或成片。进入视频脚本/台词/分镜时还要二次压缩为可播放的信息量；不要用“90 秒”倒逼小说章在高潮中间硬切。

按 100k 字总长粗估的章数仅供容量估算，不能和默认项目章数混用：

| 档位 | 100k 字约多少章 |
|---|---:|
| `漫剧` | 70–100 |
| `微短剧` | 40–70 |
| `medium` | 20–35 |
| `long` | 12–20 |
| `short` | 10–17 |

> **机器配置**：`novel-craft/scripts/contract.py` 的 `SCALE_PROFILES` 与本表 1:1（`words_per_chapter` / `min_max` / 默认章数严格相等）。init 脚本会把 `target_words_per_chapter` 与 `target_wordcount_min_max` 写入 `_meta.json`；字段名因兼容旧项目仍保留 `target_*`，语义是“建议篇幅 + 预警带宽”，不是单章硬限制。`novel-review/scripts/mechanical_check.py` 默认读取这些字段，不再固定用漫剧带宽。改分档先改 `contract.py`，再同步本说明和测试。

**判断口诀**：节拍 1-2 个 → 1000-2500 字；节拍 3-4 个 → 3000-8000 字。

> **短故事档（`microstory`）注意**：这是**单篇成篇**（默认 1 章，2000–6000 字），不是连载，**不进 100k 估章表**。结构是「100 字内抛冲突+金手指 → 中段一次冲突升级 → 结尾强反转」的闭环 + 一句话简介，写法见 [`short-story.md`](short-story.md)。短故事是否优先进入当前选品池，以 `novel-score` market baseline 或 `novel-research` 平台资料包为准。需要拉成连载时再换 `medium`/`漫剧` 档。

## 软约束（target / max / min）

- **target**：容量建议（按上表），只用于估算、任务包提示和质检预警。
- **max**：预警上限。超过时先做边界复核：是否存在第二个完整节拍、是否能给后半章单独留钩、下一章能否冷开场。三项成立才拆；否则保留长章并标记“偏长但节拍完整”。
- **min**：预警下限。低于 min 时先判断是否是短促强钩章 / 过渡后爆发章；若没有完整闭环，再并入相邻章或补足冲突。
- 表内档位以 `SCALE_PROFILES.min_max` 为准；自定义章长没有匹配档时，机检按 `target_low × 0.8` / `target_high × 1.2` 推导预警带宽。

## 切分边界（优先级从高到低）

1. **戏剧节拍**：节拍闭合处 = 章末（章尾必有钩子）
2. **原作章节**（派生 skill 中）：原作章边界可作参考但非必须
3. **段落**：自然段边界
4. **句子**：句末标点 `。！？……"`
5. **绝不在词中或短语中切**

## 流程

1. **估总长** —— 按 `小说用途` + `target_platform` 粗估总章数：总章数 ≈ 总字数 / target。
2. **定弧线** —— 按章数划三幕（≥12 章时）。详见 `outline.md`。
3. **列节拍** —— 每章一个核心节拍，节拍序列就是章纲。
4. **写章纲** —— 详见 `outline.md`。章纲未敲定不进逐章写。
5. **边界复核** —— 对低于 min / 高于 max / 弱钩 / 纯过渡章做一次人工或 AI 复核；只能按完整节拍合章 / 拆章。
6. **粗胚可重切** —— 写好的章节可合 / 拆，按节拍调整。

## 派生作品的特殊约束

- **spinoff 并行外传**：每个原作锚点至少 1 章覆盖；锚点密集段可拆成"赴约 + 现场 + 复盘"3 章。
- **expand 扩写**：每个原章节扩到 N 个新章节（N = expand ratio）；新章数 ≈ 原章数 × ratio。
- **condense 精简**：相邻同主题章合并；纯支线章砍成一句话或全删。
- **continue 续写**：新章节字数 / 节奏对齐原作末几章的字数 / 节奏，便于读者衔接。

## 元数据剥离

原作转 .txt 后，需剥离这些"非正文"开头：
- 书名《...》/ 简介 / 内容简介 / 一句话简介
- 作品标签 / 看点 / 一句话剧透
- 作者 / 字数 / 平台信息
- 以 `【` / `✅` / `★` / `#` / `—` 开头的元数据行

派生 skill 的 `init_project.py` 应自动剥；本 craft 文件只规定规则。

## 反模式

- **按字数硬切节拍** —— 到 1000 字就切，把高潮戏拦腰断。
- **把预警上限当裁决权** —— 章很长但闭环完整，只因超 max 就切。
- **章数对齐原作章数** —— 派生作品强行 1:1 跟随原作章节，节奏全乱。
- **不留钩子** —— 每章结尾平淡，读者无动力翻下一章。
- **字数过偏** —— 一章 500 字、下一章 12000 字，读者节奏被打散。
- **过早 fixate 章数** —— 章纲写到中段发现节拍不够 / 太多，要敢调整章数。
