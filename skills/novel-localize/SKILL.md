# novel-localize — 写小说出海·本地化

把**已写好的中文小说**翻译 + 文化适配成目标语言版本，供出海。是 novel-* 家族里最下游的输出 skill（在 `novel-promote` 之后），与 `novel-craft` 导出 `n2d` 并列为"成品后的两条交付路"。

> **为什么单列一条 skill**：2026 出海是最大增量——短剧出海 YouTube 收益已超长剧、AI 漫剧出海市场望破 350–500 亿、主流变现链是「网文IP→AI漫剧→YouTube 广告分成」。但翻译不是 `MT 一键译`：长篇出海的真问题是**专名跨章漂移**（同一人/功法/门派在第 3 章和第 80 章译名不一致）+ **文化梗错位**（成语/称谓/计量/honorifics 直译失味）。本 skill 把"术语锁 + 文化适配 + 机检"做成可复跑流程。

## 输入 / 输出 / 读写边界

- **输入**：`写小说/<项目>/章节/*.md`（中文成品）、`设定/角色卡.md`·`世界观.md`·`锚点表.json`（抽专名）、可选 `审稿/` 质检结论（先过审再出海）；选择点 `目标语言`·`翻译后端`·`出海目标平台`。
- **输出**：
  - `写小说/<项目>/出海/<lang>/术语表.json` —— 术语锁（source→target canonical，跨章唯一）。**先产，后翻译。**
  - `写小说/<项目>/出海/<lang>/章节/*.md` —— 逐章本地化产物。
  - `写小说/<项目>/出海/<lang>/localize_report.json` —— 机检报告（未译残留/术语一致/覆盖）。
  - `写小说/<项目>/出海/manifest.json` —— 语言×平台交付矩阵 + 权利/标识留痕。
- **读写边界**：只读源章节与设定（**绝不改中文源**——源是真值）；只写 `出海/` 子树。翻译质量由后端/人判，本 skill 负责锁、编排、机检。
- **契约关系**：选择点经 `novel-craft/references/选择点与偏好.md` 适配；权利/AI 披露复用 `novel/_lib/disclosure.py` + `合规/`；progress 列经 `novel-craft` 进度契约。

## 工作流

1. **定位 + 前置闸门**：项目根 = `写小说/<项目>/`，须有 `章节/*.md`。先确认①已过 `novel-review`（崩的稿不值得翻）②**合规三连**（见下，硬闸门，每次确认）③选择点 `目标语言`（可多语）+ `出海目标平台` + `翻译后端`。
2. **建术语锁（最关键一步，先于翻译）**：从 `设定/角色卡.md`·`世界观.md`·`锚点表.json` + 全书高频专名抽 source 专名清单（人名/地名/门派/功法/法宝/称谓/独有设定词），逐条定 target canonical 译名（音译/意译/混合按目标市场习惯），写 `出海/<lang>/术语表.json`。**这是本地化的"定妆库"——锁住它，跨章才不漂。** 多语各一份。
3. **逐章本地化**：按 `章节/` 顺序，给每章生成本地化任务（喂术语表 + 文化适配规则 + 本章中文），交 `翻译后端`（LLM 代理/专业MT/人工）产出 `出海/<lang>/章节/第NN章.md`。文化适配不是直译：成语→目标语等效表达、称谓/honorifics→目标习惯、计量/文化梗→本地化或加注。术语严格按术语表，不得即兴另译。
4. **机检（确定性，必跑）**：
   `python3 skills/novel-localize/scripts/localize_check.py <项目根> --lang <lang>`
   逐章查：**未译 CJK 残留**（拉丁/非 CJK 目标语里残留中文=漏译）、**术语未本地化**（术语表 source 仍出现在译文=专名漏锁）、**章节覆盖 + 长度比**（缺章/截断）。落 `出海/<lang>/localize_report.json`，block/warn 候选交人判。
5. **人判 + 回流**：机检盖不住的——是否地道、语气/文风是否贴目标读者、文化梗是否到位、有无机翻味——LLM/人判。专名译名一旦改，回术语表改一处、受影响章重跑（同"锁→重跑"铁律），不在单章即兴改。
6. **回写 manifest + 进度**：`出海/manifest.json` 记语言×平台交付矩阵 + 权利/AI 标识留痕；`_进度.md` 标本地化列。

## 选择点（经适配层，不写死）

按 `novel-craft/references/选择点与偏好.md` 解析（`_设置.md` → 全局默认 → 问一次后持久化）：

- **`目标语言`**：en \| id（印尼）\| th（泰）\| es \| pt \| ja \| 自定义　（可多选；无默认，立项定）
- **`翻译后端`**：LLM代理 \| 专业MT \| 人工 \| 混合　（默认 **LLM代理**：术语表 + 文化规则注入后逐章生成；专业MT 走外部引擎；混合=MT 初翻 + LLM/人工润色）
- **`出海目标平台`**：YouTube \| TikTok \| 海外阅读平台 \| 通用　（影响文化适配口径与交付规格；漫剧/短剧改编源额外标 `n2d-ready`）

## 合规（硬闸门 · 每次确认，绝不沉默假定）

翻译 = **演绎/衍生作品**，出海放大 IP 风险（参 2026「AI 内容侵权速度远超维权」业界讨论）。下列每次出海前都要确认，即便 `_设置.md` 记过（合规点复用「每次重新确认」铁律）：

1. **源书权利**（`权利来源`）：有权对源书做翻译演绎？公版/自有/已授权才放行；`未声明` 一律先确认，不得默认公版。
2. **目标辖区发行权**（`权利辖区` / `发行地区`）：译本在目标市场的发行权——公版在 A 区不等于在 B 区公版（版权期不同）；授权范围是否覆盖目标语言与地区。
3. **目标市场 AI 内容标识**（`AI使用披露`）：AI 生成/辅助译本按目标法域加标识——中国 GB 45438-2025《AI 生成合成内容标识办法》（2025-09 起强制：显式标识 + 元数据隐式标识 + 日志留存≥6月）、EU AI Act 透明度义务等；按 `出海目标平台` 所在法域核当次最新规则，写入 `合规/` + manifest。

> 与 novel 线既有合规一致：源书合法性走 `权利来源`（同 novel-fetch），AI 披露走 `disclosure.py` 写 `合规/`。本 skill 只是把它们在"出海"场景再确认一遍 + 补"目标辖区/目标市场标识"两层。

## 不做什么

- 不改中文源章节 / 设定（源是真值；本地化只在 `出海/` 子树产出）。
- 不在单章即兴定专名译名——专名统一进术语表，锁了再翻。
- 不替用户判断源书能不能翻、能不能在目标市场发——只把合规三连摆出来确认，不沉默假定。
- 不做配音/出图/视频（那是 n2d / 下游的事；本 skill 只产本地化文本 + n2d-ready 标记）。
- 不碰 song / mv / ad / n2d 四条线。

## 常见错误

| 错误 | 纠正 |
|---|---|
| 先翻译再想术语 | 先建术语锁再逐章翻——否则同一专名跨章必漂，回工成本最高 |
| 把 MT 直译当本地化 | 文化梗/称谓/计量要适配；机翻味、成语直译交人判，机检只兜未译残留 |
| 单章即兴改译名 | 改术语表一处 + 受影响章重跑（同"锁→重跑"铁律） |
| 跳过合规直接出海 | 源书权利 / 目标辖区发行权 / 目标市场 AI 标识 三连每次确认 |
| 译完不跑机检 | 未译 CJK 残留 / 术语漏锁 / 缺章截断是确定性秒查，漏跑等于白翻 |
| 改了中文源去对齐译文 | 源是真值，永远改译文不改源 |
