# N2D 工业化量产可行性审查（2026）

> 状态：当前实现快照；复核日期：2026-08-22。
> 边界：这是工程可行性审查，不是市场规模、盈利能力或“完全无人值守”的承诺。运行期真值以 `skills/n2d/` 的合同、runner、gate 与 schema 为准。

## 1. 结论

N2D 已具备**受监督的工业化生产**基础：同一作品可以从源文本连续推进到剧本、配音、分镜、图片、视频、合成和验收；确定性前置、普通可逆选择、已授权预算包内的生成任务和可恢复步骤可以自动串联；失败可以定位到集、阶段、镜头或资产后局部返工。

它仍不是无条件无人值守系统。下面四类边界必须保留人工责任：

- 权利、真人肖像/声音和其它合规授权；
- 每张图片对当前像素的具名验收；
- 最终母版与不可逆发布/覆盖；
- 阶段预算包创建、扩大、过期、合同变化，以及未知成本或 provider 状态不明。

因此当前更准确的产品定位是：**一键推进到下一个真实责任边界，并把全部阻断一次性汇总**。

## 2. 状态与完成口径

N2D 不以 `_meta.json` 作为生产状态。`_meta.json` 只服务作品卡片的标题、封面和简介展示。生产控制采用以下收敛口径：

1. **一个业务前沿**：`_进度.md` 记录当前阶段，`run.py next --json` 只从本线阶段合同推导下一动作。
2. **一个当前内容身份**：每个被验收对象以当前 canonical SHA-256 绑定输入、产物、QC 和收据；字节变化使旧证据失效。
3. **一个完成定义**：`release_verdict.py` 聚合当前合同与收据，明确区分 `clip_delivery_complete`、`master_delivery_complete` 和各发布 profile；旁路 dashboard、telemetry 或 UI 不能自行宣布完成。

## 3. 工业化能力审查

| 维度 | 当前能力 | 仍需关注 |
|---|---|---|
| 可恢复性 | 队列具备幂等键、租约、重试、dead-letter；重启后从当前前沿与落盘证据恢复 | provider 返回不明时必须先查询/结算，不能换 attempt id 盲重放 |
| 一致性 | 身份/资产 registry、真实参考输入、逐图前后 B14 闸门、跨镜合同继承和局部返工 | 高运动、多人同框、极端表情仍依赖当前像素人审和针对性重做 |
| 成本治理 | 阶段预算包绑定项目、阶段、输入 SHA、scope、模型、渠道、调用/重抽次数、费用与期限；runner 原子消费 | 未知价格、超额、过期或授权绑定变化必须停，不能用“自动化”掩盖责任 |
| 自动推进 | 普通可逆选择自动采用有证据优势的推荐值并写回；supervisor 串联确定性前置和 specialist | 代理创作不是 subprocess，需要结构化任务包、回写验证与失败闭环 |
| 交付可信度 | clip、master、production、CN/海外/商业发布就绪分开报告 | 技术完成不等于公开/商业发布获准，最终成品仍需具名验收 |
| 可观测性 | episode graph、blocking bundle、flow telemetry、dashboard 和 release verdict 可互相追溯 | 派生面板不能成为第二状态机；指标必须回指 canonical hash 与合同 |

## 4. 下一阶段优化重点

1. **继续减少软停顿**：把可恢复错误、普通选择、确定性 repair 和已有预算包内的调用留在同一 run 内完成。
2. **不削弱硬边界**：逐图当前像素、最终母版、合规和预算扩权保持 fail closed；用更好的批量审阅界面降低摩擦，而不是伪造验收。
3. **缩短返工半径**：所有状态变化都映射到最小受影响资产/Clip/集，并保持输入 SHA → 输出 SHA → receipt 的可追溯链。
4. **用真实数据校准**：一次通过率、重抽率、每分钟成本、人工审阅时长和发布表现必须来自可归因记录；样本不足时只报告观察，不作盈利或质量保证。
